## 第一阶段：项目初始化与基础 Pipeline（05-18 ~ 05-19）

项目目标：把教材（PDF/DOCX）全自动转成带动画 + 配音的教学视频。

**05-18 — 项目脚手架**

项目从零搭建。一天内完成了大量探索性工作：
- 项目初始化（pyproject.toml、.gitignore、.env 机制）
- LLM 客户端对接华东师大网关（ECNU API）
- 动画基础模板（CSS + JS）
- 早期 Demo：lesson 4 动画、标题页、神经网络组件原型
- 项目规划文档（项目计划、协作路线图、PoC 日志、可行性分析）

**05-19 — 完整 Pipeline 骨架**

echo 建立了端到端 pipeline 的所有模块：
- CLI 入口（`t2v` 命令）+ 全局配置
- LLM 客户端 + prompt 模板
- 六大 pipeline 模块：parser、scriptwriter、storyboard、narrator、recorder、composer
- 测试框架 + 动画模板
- 研究文档、动画 Demo、脚本
- 合并 `github/publish` 分支，项目正式进入远程协作阶段

此时的 pipeline 走通了"教材 → 讲稿 → storyboard → HTML → MP4"的全链路，但生成质量粗糙，动画生成高度依赖 LLM。

## 第三阶段：多格式输入与管道鲁棒性（06-02 ~ 06-03）

**06-02 — DOCX 解析 + AI 配图 + CSS 热修复**

三个重要模块在同一天落地：
- **DOCX 解析器**：支持多格式输入（PDF + DOCX），按 Heading 样式解析
- **AI 配图**：对 storyboard 中的 image 元素自动生成配图，inline placeholder 注入
- **CSS 热修复引擎**：零 token 的布局修复，通过 Playwright 直接操作 DOM 后写回

图片提取也由 echo 集成进 pipeline 和 storyboard 生成。

其他改进：
- 主题 CSS 变量覆盖修复
- 防御性高度规则
- 动画 pipeline 鲁棒性提升
- 单 slide LLM repair（减少 token 浪费）

**06-03 — JSON-to-HTML 管道根治**

这是项目的一个重要转折点，标记为 F1~F5 五项关键修复：

| 编号 | 问题 | 修复 |
|------|------|------|
| F1 | slide 提取失败 | 浏览器 DOM 回退（零开销栈匹配 + msedge 兜底） |
| F2 | storyboard 强制复杂导致深嵌套 | 放松复杂度约束 |
| F3 | 提取回退 + repair 预算不足 | 提高修复轮次上限 |
| **F5** | **LLM 生成质量不可控** | **确定性模板渲染器 `template_renderer.py`** |
| A | css_hotfix 固化运行时状态 | 序列化前复位 slide 状态 |
| B | LLM 超时不精确 | 禁用底层重试，`num_retries=0` |
| C | 教材原图链接断裂 | storyboard src → base64 注入 |

**F5 是架构级决策**：从"完全依赖 LLM 写 HTML"转向"模板渲染优先 + LLM 兜底"。这个决策后来成为整个渲染管线的核心。

同时：
- 卡片背景改用 `var(--card-bg)`，深色主题可读性修复
- 添加 `CLAUDE.md` 项目上下文文档

## 第四阶段：深蓝学术主题 + 端到端命令（06-03 ~ 06-04）

**06-03 ~ 06-04 — 深蓝学术主题精致化**

**06-04 — 流水线命令补全 + 音画合成**

完整的 CLI 命令体系在这一天成型：
- `t2v produce` — 端到端一步式命令（教材 → 有声 MP4）

- `t2v narrate` — 独立 TTS 重生成命令
- `t2v script` / `t2v storyboard` — 拆分中间步命令
- `t2v validate` / `t2v doctor` / `t2v batch` — 运维三件套

storyboard 也做了 richer content 对齐（渲染友好的内容结构），image 元素增加 SVG vector placeholder。

音画合成模块 `compose.py` 解决了"最终 MP4 无声"的关键断点。

**06-04 — Pipeline 加固**

`fix/pipeline-hardening` 分支修复了 6 个生产级问题：
- #1（高危）：单段 TTS 失败不再拖垮整批
- #2 / #7：浏览器 channel 回退 + webm 转码失败清理
- #3：段数一致性 + segment id 重复校验
- #5 / #6：教材图路径穿越防护 + 图片 alt 转义
- 删除死代码 `composer.py`（被 `compose.py` 取代）

**06-04 — 文档整理**

- README 重写 + 两份实现文档更新

**06-06 — 自适应版面设计落地**

这是项目在视觉质量上投入最大的一天。

**上午 — 设计文档**（`docs/adaptive-layout-design`）：
- 自适应 slide 版面 v2 设计
- 取代 budget/element-rules 方法论
- 按对抗性自审修正 5 项缺陷

**下午 — 版面自适应落地**（`feat/layout-fill-step1`），12 个提交：

| 步骤 | 改动 |
|------|------|
| 第 1 步 | 内容行少时居中成组，不再被 `space-evenly` 拉散 |
| 第 2 步 | icon_group auto-fit 填宽 + 字号 clamp 流式 |
| 第 3 步 | grow-to-fill — hero 撑满纵向空间治空旷 |
| 第 4 步 | 空间权重 + 单主元素语法 + 互斥校验 |
| B 步 | storyboard 加"单主元素+权重"软引导 |
| 修正 | grow-to-fill 仅用于 comparison/table/image，flow/activity 保持紧凑 |
| 回退 | 退回密度 grow 改动（内容压薄反而难看） |
| 新增 | scale-to-fit — 内容超框时整页等比缩小塞下 |
| 新增 | 连续 stat_card/badge 横排成行 |

**晚上 — 内容结构治理**（`feat/limit-element-types`）：

核心思想：充实靠多放实例，不靠多加类型。
- 限制每页 body 元素"类型种数"
- 功能重叠按组互斥（icon_group 与 flow_step 不同页等）
- 类型重叠在生成 JSON 时确定性拆段（根治，保信息 + 每页干净）
- 拆段瘦半页 LLM 改写填实（混合策略，避免寡淡页）

## 第六阶段：混合渲染与变体库（06-07 ~ 06-08）

**06-07 — 混合渲染模式 + 文档清理**（PR #1 ~ #4）

**PR #1 — 混合渲染模式**（`feat/hybrid-render-mode`）：
- `--free-form` 开关：允许 LLM 自由发挥的页面
- `render_mode` 字段路由：每页独立决定用 template 还是 LLM 渲染
- icon_group 按 seg_id 轮换 3 种版式
- 元素间距分级 + variant C 加大 + 同类轻元素合并
- 全面禁用 stat_card 元素类型
- scale-to-fit 推广到所有 slide
- 防溢出 prompt 强化

**PR #2 — 文档清理**：新增 `improvements.md` 路线图 + 清理过时文档

**PR #3 — 文档同步**：文档与当前实现状态对齐

**PR #4 — 教材原图利用率**：storyboard prompt 强化，鼓励引用教材原图而非 AI 重画

**06-08 — 主题动画 + 变体库扩展**（PR #5 ~ #6）

**PR #5 — 主题动画体系**（`feat/theme-animation-phase1`）：
- Phase 1：theme 携带动画风格（duration_scale + 默认转场）
- Phase 2：per-theme easing 曲线 + 粒子密度 + stagger 步长
- Phase 3：主题统一转场 + 关键帧库 + 卡片视觉强化

**PR #6 — 变体库扩展 v2**（`feat/variant-library-expansion-v2`）：

这是截至目前最后一次合并，将 `template_variants.py` 拆分为独立的 `variants/` 子包：

```
variants/
├── __init__.py          # 注册表 + 路由
├── _shared.py           # 共享工具
├── activity_step.py     # 5 variants
├── badge.py             # 3 variants
├── comparison_panel.py  # 5 variants
├── flow_step.py         # 5 variants
├── groups.py            # 5 variants
├── heading.py           # 5 variants
├── icon_group.py        # 5 variants
├── image.py             # 5 variants
├── layouts.py           # 布局变体
├── quote.py             # 5 variants
├── subheading.py        # 3 variants
├── table.py             # 5 variants
└── text.py              # 3 variants
```

共 27 个 variant 覆盖 12 种元素类型，主题可通过 `preferred_variants` 指定偏好。

布局也做了多项调整：
- subheading 横跨整宽
- 图文构图轻元素密度自动伸展
- 图文版式阈值优化，3 种版式都常态命中
