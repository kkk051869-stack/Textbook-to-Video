# Textbook-to-Video 项目计划

> 本文档为项目主计划，记录目标、技术决策、架构设计和研究结论。
>
> 创建日期：2026-05-18

## 一、项目目标

将中小学**人工智能教育**教材文本输入，全自动化生成带 CSS 动画 + 配音的趣味教学视频。

> **项目聚焦：中小学人工智能教育**（不是全学科通用）
>
> 覆盖主题：什么是 AI、机器学习入门、神经网络、计算机视觉、自然语言处理、决策与搜索、AI 伦理、AI 实践等

### 核心产出

```
教材文本 → 讲稿 → 画面动画大纲 → 生成音频 → 生成动画 → 音频动画合成
```

> **关键决策**：
> - 不需要「教案」环节。教材本身结构化程度高，教案不进入自动化流程。
> - 采用**音频先行**方案（方案 A）：先生成音频获取精确时长，再生成匹配时长的动画。
> - 动画质量是目前的核心瓶颈，需要系统性提升方法。

### 产品形态

- **v1.0 (MVP)**: Python CLI 工具，输入教材文件 → 输出视频
- **v2.0**: Web 应用，支持上传教材、配置参数、预览动画、批量生成

## 三、系统架构

### 3.1 Pipeline（6 步，音频先行）

```
Step 1        Step 2          Step 3         Step 4       Step 5   Step 6
教材内容  →   讲稿生成   →   画面动画大纲  →  生成音频  →  生成动画 → 合成

┌──────┐   ┌──────────┐   ┌───────────┐  ┌────────┐  ┌──────┐  ┌──────┐
│ PDF  │   │ 逐段旁白  │   │ 每段讲稿对 │  │ edge-tts│  │ HTML │  │ MP4  │
│ 提取 │   │ 文本      │   │ 应的画面描 │  │ 生成    │  │ CSS  │  │ 视频 │
│      │   │          │   │ 述+动画类型│  │ MP3    │  │ JS   │  │      │
└──────┘   └──────────┘   └───────────┘  └───┬────┘  └──┬───┘  └──────┘
                                               │           │
                                          拿到精确时长    按时长生成
                                          分配给每段      匹配的动画
                                               │           │
                                               └─────┬─────┘
                                                     ▼
                                              ffmpeg 合并
                                              音频+视频

输出: MP4 教学视频 (1080p, 30fps, H.264 + AAC)
```

### 为什么是音频先行（方案 A）

| 对比 | 方案 A：音频先行 ✅ | 方案 B：并行 |
|------|-------------------|-------------|
| 顺序 | 讲稿 → TTS → 拿到时长 → 生成动画 | 同时生成音频+动画 → 合成时对齐 |
| 优点 | 动画时长精确匹配音频，不会错位 | 更快 |
| 缺点 | 串行，稍慢 | 时长可能不匹配，需要反复调整 |
| 选择理由 | PoC 证实：均匀分配时间会导致讲稿和画面错位 | — |

### 各步骤详细说明

**Step 1: 教材内容 → 讲稿**
- 输入：PDF 提取的课程文本
- 输出：按「页/段」拆分的旁白文本列表
- 粒度：1 页动画 = 1 段讲稿（最直接的对应关系）
- 风格：老师讲课风格（自然口语化，适合中小学生）
- 关键约束：每段讲稿控制在 5-25 秒（TTS 后），总时长合理

**Step 2: 讲稿 → 画面动画大纲**
- 输入：每段讲稿文本
- 输出：结构化 JSON，描述每段对应的画面
- 这是**最关键的衔接环节**，需要定义中间格式：

```json
{
  "segments": [
    {
      "id": 1,
      "narration": "同学们好！今天我们来学习人工智能的技术基础...",
      "visual_type": "title",
      "elements": [
        {"type": "heading", "text": "人工智能的技术基础"},
        {"type": "icon_group", "items": ["数据", "算力", "算法"]}
      ],
      "animations": [
        {"target": "heading", "effect": "bounceIn"},
        {"target": "icons", "effect": "fadeInUp", "stagger": true}
      ]
    }
  ]
}
```

**Step 3: 生成音频**
- 输入：每段讲稿文本
- 输出：每段 MP3 文件 + 精确时长
- 工具：edge-tts（MVP）→ Fish Audio（后期）
- **关键输出**：每段音频的精确秒数，传递给下一步

**Step 4: 生成动画**
- 输入：画面动画大纲 JSON + 每段音频时长
- 输出：完整 HTML（自写 SlideController，每页停留时间匹配对应音频时长）
- 生成方式：LLM 生成完整 HTML/CSS/JS（单文件零依赖）

**Step 5: 音频动画合成**
- 输入：动画 HTML + 音频 MP3
- 输出：最终 MP4 视频
- 流程：拼接音频 → 录制匹配时长的视频 → ffmpeg 合并

### 3.2 技术栈

```
Python 3.11+
├── Pipeline: asyncio, pydantic, click (CLI)
├── LLM: litellm（Claude/GPT/GLM/Qwen 可切换）
├── TTS: edge-tts → Fish Audio / CosyVoice
├── 录制: Playwright (Python)
└── 合成: ffmpeg

动画技术栈（零外部依赖）
├── 自写 SlideController (~50 行 JS)
├── .anim + .d1~.d12 CSS 延迟触发系统
├── Canvas API 粒子系统
├── SVG 噪点纹理叠加
└── 多层 radial-gradient 背景
```

## 四、核心难点

### 难点 1：音画同步

#### 当前问题

```
讲稿段落时长：s1=11s, s2=19s, s3=23s, s4=16s, s5=16s, s6=20s（总计 ~105s）
录制时均匀分配：每页 105/6 = 17.5s

→ 第3页讲稿 23s 但只分配 17.5s → 讲稿没播完就翻页了
→ 第1页讲稿 11s 但分配 17.5s → 讲稿播完后画面静止 6.5s
```

#### 方案：音频时长驱动 slide 时间

```
Step 1: 生成音频 → 拿到每段精确时长 [11.0, 19.2, 23.0, 15.6, 16.4, 20.2]
Step 2: 生成动画时，把时长信息注入 HTML
        SlideController 配置：slideTimes = [11000, 19200, 23000, 15600, 16400, 20200]
Step 3: 录制时 SlideController 按配置时长自动翻页
```

需要做的事：
1. `narrator.py` 输出每段音频时长
2. 动画 HTML 支持 `slideTimes` 配置
3. `recorder.py` 不再用均匀间隔，改为从 HTML 读取 `slideTimes`

#### 音画同步的深层问题

上面是粗粒度的方案（每页停留时长匹配音频）。实际落地还有三个更细粒度的问题：

**1. slide 内部动画节奏也要对齐**

一页 slide 里有多个 `.anim` 元素依次出现（`.d1~.d12`，间隔 0.2s，总计 2.4s）。
如果这页讲稿时长 23 秒，动画 2.4 秒就全出现了，剩下 20 秒画面静止。
需要根据该页的讲稿时长，动态调整 `.anim` 的延迟间隔，让动画"铺满"整段讲稿。

**2. 讲稿和 slide 不是 1:1 对应**

一段讲稿可能跨两页 slide，或者两段讲稿对应一页。
需要讲稿生成时就定义好"这段讲稿对应第几页"，而不是简单地按顺序一一对应。

**3. 录制是实时的**

Playwright 录制走的是真实时间流逝，不是虚拟时钟。动画时间轴必须精确到毫秒级才能对齐。
任何 JS 执行延迟、页面渲染卡顿都会导致同步偏移累积。

### 难点 2：Prompt 工程的稳定性（最难量化）

当前方案是 LLM 直接生成完整 HTML（800-1500 行）。核心问题：

- **一次生成质量不够** — AI_Animation 项目的参考动画是多轮迭代出来的（先出页面→加动画→改→优化→美化），单次 Prompt 很难直接出高质量结果
- **不同模型输出差异大** — Claude 偏保守规整，GPT 偏花哨，GLM 可能缺动画，同一个 Prompt 出来的东西完全不同
- **"好看"没有客观标准** — 人工评审成本高，自动化评审（VLM 截图打分）还没做

可能的解决方向：
- 多轮迭代自动化：生成→审查→修复循环
- Prompt 模板持续迭代，把视觉技巧固化到模板中
- 建立动画质量评分标准（量化"好看"）

### 难点 3：LLM 代码生成的可靠性

LLM 生成的 HTML/CSS/JS 不是每次都能直接运行。已知问题类型：

| 问题 | PoC 中已遇到 | 检测方式 |
|------|-------------|---------|
| Canvas/Chart 尺寸爆炸 | ✅ Chart.js canvas 膨胀到 30148px | 检查 DOM 元素尺寸 |
| Slide 高度溢出 1080px | ⚠️ 可能发生 | Playwright 截图检查 |
| CSS 变量/z-index 冲突 | ⚠️ 可能发生 | 视觉检查 |
| 动画时序错误 | ⚠️ 可能发生 | `.anim` 元素出现时间检查 |
| JS 运行时报错 | ⚠️ 可能发生 | console.error 监听 |

需要的自动化验证：
1. 生成 HTML 后 Playwright 打开
2. 截图每页 slide
3. 检查高度是否溢出、元素是否渲染、是否有 JS 报错
4. 不通过则自动修复或重新生成

### 难点 4：内容准确性

LLM 对中小学 AI 教育内容的理解大部分正确，但：

- **概念简化过度** — 为了让中小学生听懂，LLM 可能把技术概念讲错（比如把"梯度下降"说成"不断尝试"）
- **数据/数字编造** — "准确率提升 95%" 这种数字，LLM 可能随口编，不是教材原话
- **跨页逻辑连贯性** — 6 页 slide 是一节课，前面讲的后面要呼应，LLM 多次调用之间容易遗忘上下文

可能的解决方向：
- 讲稿生成时严格引用教材原文
- 加入事实核查步骤（对比教材原文）
- 画面大纲整体生成，再拆分到各页，保证连贯性

### 难点 5：长视频的工程挑战

当前 PoC 只做了 1 课 6 页 ~105 秒。扩展到完整课程（30 分钟，30+ 页）：

- **内存** — Playwright 录制 30 分钟视频，内存占用持续增长
- **容错** — 30 个 slide 中间 1 个出错，要不要全重来？需要分段录制再拼接
- **风格一致性** — 30 个 slide 分多次 LLM 调用生成，每次的配色/字体/间距可能有微妙差异
- **LLM 上下文窗口** — 30 页的内容不可能一次 Prompt 生成，需要分批生成但保持风格统一

可能的解决方向：
- 分段录制（每 5-10 页一段）→ ffmpeg 拼接
- 第一轮生成整体画面大纲，第二轮逐页生成动画（保证风格一致）
- CSS 变量 + 模板强制约束配色/字体

## 五、动画质量研究（Q7 结论）

> 2026-05-18 完成，分析 `references/AI_Animation-master/` 50+ 动画 + `examples/transformer-attention.html`

### 核心发现 1：全部零依赖、自写 slide 控制器

质量最高的参考动画**不用 Reveal.js、不用 Animate.css**，全部手写：

```javascript
.slide { opacity: 0; visibility: hidden; position: absolute; }
.slide.active { opacity: 1; visibility: visible; }

function go(n) {
    slides[cur].classList.remove('active');
    slides[cur].querySelectorAll('.anim').forEach(e => e.classList.remove('show'));
    cur = n;
    slides[cur].classList.add('active');
    slides[cur].querySelectorAll('.anim').forEach((e, i) => {
        setTimeout(() => e.classList.add('show'), 200 + i * 280);
    });
}
```

### 核心发现 2：5 个立竿见影的视觉提升技巧

**技巧 1 — SVG 噪点纹理叠加**（所有高质量动画都有）

```css
body::before {
    content: "";
    position: fixed; inset: 0;
    background-image: url("data:image/svg+xml,...feTurbulence...");
    opacity: 0.03;
    mix-blend-mode: overlay;
    pointer-events: none;
}
```

**技巧 2 — 多层 radial-gradient 背景**（非纯色/单色渐变）

**技巧 3 — Canvas 粒子**（非 DOM 粒子，性能好 + 效果精致）

**技巧 4 — `.anim` + `.d1~.d12` 延迟触发系统**（替代 Animate.css，每个元素方向/时间独立控制）

**技巧 5 — JS 动态 SVG 连线**（动态计算 DOM 元素位置画 SVG 连线）

### 核心发现 3：Prompt 是多轮迭代的

AI_Animation 项目的 Prompt 模式是**渐进式**，不是一步到位：

1. 先出页面 → 2. 加动画 → 3. 改 PPT → 4. 优化细节 → 5. 美化 → 6. 参考 UI

**启示**：单次 Prompt 难以生成高质量结果，需要迭代流程或更好的模板。

### PoC vs 参考动画差距

| 维度 | PoC v1 | 新方案（已实现） |
|------|--------|-----------------|
| 框架 | Reveal.js (50KB) | 自写 ~50 行 JS ✅ |
| 粒子 | DOM `<div>` 粒子 | Canvas 粒子系统 ✅ |
| 背景纹理 | 无 | SVG 噪点叠加 ✅ |
| 背景 | 单色渐变 | 多层 radial-gradient ✅ |
| 动画系统 | Animate.css + fragment | `.anim` + `.d1~.d12` ✅ |
| 主题 | 暗色 | 亮色 ✅ |

以上 5 项已全部实现并写入 Prompt 模板（`src/textbook2video/llm/prompts/animation_direct.md`）。

## 八、PoC 踩坑记录

> PoC 过程中发现的系统性问题。部分已随方案变更不再适用（Reveal.js 相关），但教训仍值得记录。

### 问题 1：Chart.js canvas 无限撑高

> **注意**：新方案（自写 SlideController + 零外部依赖）已不再使用 Chart.js。但 Canvas 元素高度约束的教训仍然适用。

**现象**：canvas 被渲染为 928×30148px，页面完全无法显示。

**根因**：Chart.js 配置 `responsive: true` + `maintainAspectRatio: false`，容器没有显式高度约束。

**解决方案**（写入 Prompt 模板）：
```css
.chart-box { height: 250px; overflow: hidden; }
.chart-box canvas { max-height: 200px; }
```
```javascript
new Chart(ctx, { options: { responsive: true, maintainAspectRatio: true, aspectRatio: 2 } });
```

### 问题 2：Playwright video.save_as 时序

**现象**：context 关闭后 video 对象失效。

**解决方案**：context 关闭前用 `page.video.path()` 获取临时路径，关闭后 `shutil.move`。

### 通用教训

1. **所有 slide 内容必须控制在 1920×1080 可视区域内** — 录制只录可视区域
2. **每个 slide 的内容高度不应超过 900px** — 减去标题、padding 后约 900px 可用
3. **使用 `vh` 单位而非 `px`** — 在缩放环境中更可靠
