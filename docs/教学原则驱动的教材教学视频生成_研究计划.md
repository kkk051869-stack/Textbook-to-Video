# 面向教材教学视频生成的教学原则操作化与事件级诊断：研究计划

> 论文研究计划（生成侧补全与研究重点再平衡版）  
> 修订日期：2026-10-04  
> 当前工作重心：**教学原则驱动的视觉支持决策与命题—视觉语义时序对齐**。旧标题暂时保留，避免在 pilot 前反复改名；事件级诊断不再是最高层方法，而是生成方法的验证、定位与反馈机制。

## 1. Scope Decision

第一篇论文不研究“教材视频生成系统的所有模块”，也不再以“做一个 event-level checker”为最高层目标。论文研究以下连续问题：

> **如何用 Coherence 与 Multimedia 判断一个知识命题是否需要额外视觉、是否应触发外部视觉检索；又如何把获得的视觉与讲述命题正确绑定，并依据 Temporal Contiguity 与 Signaling 在正确时刻动态呈现。**

研究链为：

```text
Textbook / Knowledge Source
        ↓
Knowledge Proposition Analysis
        ↓
Visual Support Need Detection
        ↓
Visual Acquisition Decision
   ├─ no additional visual
   ├─ reuse textbook visual
   ├─ retrieve external visual
   └─ generate visual（P1 optional）
        ↓
Semantic Proposition–Visual Binding
        ↓
Dynamic Event Planning
   ├─ temporal scheduling
   └─ signaling target/time/duration
        ↓
Layout / Rendering
        ↓
Post-render Event-level Evaluation
        ↓
Bounded Repair（P1）
```

第一篇论文 P0 最多保留两个核心研究问题：

1. **Visual Support Decision**：Visual Necessity 与 Retrieval Triggering；
2. **Semantic-Temporal Dynamic Alignment**：proposition→visual binding、动态出现与 signaling。

**Event-level evaluation** 是贯穿两个问题的测量与反馈机制，不单独包装成论文最高层创新。AI visual generation、layout optimization 和 repair convergence 放入 P1；学习者实验与广义原则放入 P2。

## 2. 理论边界与代码事实

### 2.1 原则在决策链中的角色

| 原则 | 生成问题 | 本文角色 |
|---|---|---|
| Coherence | 是否有必要增加该视觉；是否引入无关、冗余内容 | Visual Necessity 的抑制约束 |
| Multimedia | 哪些命题能从解释性视觉获益 | Visual Support Need 的正向依据 |
| Temporal Contiguity | 正确对象何时 show/reveal/highlight/remove | Dynamic Event Planning 的时间约束 |
| Signaling | 是否需要 cue、指向谁、何时出现、持续多久 | Dynamic Event Planning 的注意引导约束 |
| Personalization | 对话式、口语化但准确的讲解 | generation constraint / control，不是主 Gap |
| Image | 讲者/代理是否出现 | 当前无 presenter，conditional / N/A |

### 2.2 必须继续保留的审计事实

- 当前没有 proposition-level representation；subtitle sentence/chunk 只是计时单元。
- source provenance 不完整；`source_refs` 在 lesson plan 后不能稳定贯穿。
- 当前有 segment narration、element ID、animation/timeline、planned time 和部分 runtime trace，但没有 final MP4 对象真实 visibility interval。
- legacy timing 与 semantic timing 只达到 sentence→visual event 的部分对齐，不等于 proposition→visual object 的教学语义对齐。
- technical QA 不等于 pedagogical quality。
- signaling mechanics 已存在，但 applicability、semantic target、overload 与 duration 没有原则级保证。
- repair 已有 candidate、accept/rollback、`max_rounds` 等相邻基础，但没有 objective vector、重复状态/振荡检测和原则特异的收敛控制。

### 2.3 Research Platform 定位

Textbook-to-Video 是 **Research Platform / Experimental Testbed / ours**，不是需要击败的 “Baseline A”。研究允许在 feature flag 与版本化 schema 下修改 parser、lesson plan、scriptwriter、storyboard、timing、renderer、recorder 和 evaluation。旧版本只用于：

- before/after analysis；
- component ablation；
- reproducibility；
- regression detection。

必须保存 Git commit/tag、配置与 Prompt hash、schema 版本、输入/输出 hash 和冻结产物。修改后的系统不得再伪装成另一个外部 baseline。

PresentAgent 是实际运行后才能使用的外部系统参照；Doc2Present paired video 是 human-authored reference ceiling，不是 PresentAgent 自动输出。

## 3. Research Questions

### RQ1：原则如何驱动视觉支持与检索决策？

> **How can Coherence and Multimedia be operationalized into proposition-level visual-support and retrieval-triggering decisions for automatically generated instructional videos?**

RQ1 将每个 knowledge/narration proposition 分类为：

1. `NO_ADDITIONAL_VISUAL`：纯讲解或现有布局已足够；
2. `REUSE_SOURCE_VISUAL`：教材已有足够且适配的视觉；
3. `RETRIEVE_EXTERNAL_VISUAL`：需要额外视觉且外部检索适合；
4. `GENERATE_VISUAL`：仅作为 P1/optional branch；教材与检索均不合适，且命题适合生成式表达。

Visual Necessity 不等价于“有没有图片”；Retrieval Triggering 也不等价于“把整段教材送进普通 RAG”。

### RQ2：命题感知的语义时序对齐能否改善动态呈现？

> **Can proposition-aware semantic visual binding and dynamic event planning improve visual timing and attention guidance over current sentence-level, lexical, and rule-based methods?**

RQ2 的依赖顺序是：

```text
Narration Proposition
        ↓
Semantic Visual Binding
        ↓
Visual Event
        ↓
Temporal Scheduling
        ↓
Signaling Target / Time / Duration
```

必须先判断 proposition 对应哪个 visual object，再安排 show/reveal/highlight/focus/transition/remove/dim。文本相似度只能作为 baseline，不能直接等同于教学语义对齐。

### RQ3：事件级成片证据能否可靠验证上述生成决策？

> **To what extent can event-level post-render evidence validate visual-support, semantic-binding, temporal, and signaling decisions beyond aggregate scores and direct VLM judging?**

RQ3 是评价问题：区分 plan、runtime 与 rendered-video evidence；定位错误发生在 visual need、acquisition、binding、timing、signaling 还是 rendering。它不把 checker 重新提升为论文的最高层方法。

## 4. 研究重点优先级

`HIGH / MEDIUM / LOW` 是相对判断；“当前代码基础”越高表示复用越多，“工作量”越高表示成本越大。

| Candidate Problem | 教学意义 | Novelty | 当前代码基础 | 实验可验证性 | 工作量 | 是否 P0 | 原因 |
|---|---|---|---|---|---|---|---|
| Visual Necessity | HIGH | MEDIUM | LOW | HIGH | MEDIUM | **YES** | 连接 Coherence/Multimedia 与视觉选择；当前只有 Prompt 建议，无命题级决定 |
| Retrieval Triggering | HIGH | MEDIUM-HIGH | LOW | HIGH | MEDIUM | **YES** | 研究“何时检索”而非普通 RAG；可与 always/never/direct-LLM 对照 |
| Visual Acquisition Policy | HIGH | MEDIUM | MEDIUM | MEDIUM | HIGH | **P0 limited** | P0 只研究 reuse/retrieve/no-visual 决策，不承诺完整资产系统 |
| AI Visual Generation | MEDIUM | LOW | LOW | MEDIUM | HIGH | **NO** | 图像生成模型本身不是创新；只作 P1 optional completion |
| Semantic Alignment | HIGH | MEDIUM-HIGH | MEDIUM | HIGH | MEDIUM | **YES** | 当前只有词面/规则匹配；命题→对象正确性是 timing 前提 |
| Temporal Alignment | HIGH | MEDIUM | MEDIUM-HIGH | HIGH | MEDIUM | **YES，合并** | 已有 timing 基础；与 Semantic Alignment 合为一个连续问题 |
| Signaling | HIGH | MEDIUM | MEDIUM-HIGH | MEDIUM-HIGH | MEDIUM | **YES，合并** | mechanics 可复用；作为 dynamic presentation 子任务，不独立扩张 |
| Event-level Diagnosis | HIGH | MEDIUM-HIGH | MEDIUM | HIGH | MEDIUM | **YES，评价层** | 保留 human gold、定位与反馈价值，但不再作为最高层中心 |
| Layout Optimization | MEDIUM | LOW | HIGH | HIGH | MEDIUM | **NO** | 通用布局修复已拥挤；只作技术安全门 |
| Bounded Repair | MEDIUM-HIGH | MEDIUM | MEDIUM | MEDIUM | HIGH | **NO，P1** | 闭环本身不新；价值在收敛、安全和 error migration，依赖 P0 |

### 最终 P0

- 核心 1：**Visual Necessity + Retrieval Triggering**；
- 核心 2：**Semantic-Temporal Dynamic Alignment**，Signaling 合并其中；
- 统一评价：**event-level post-render evaluation**。

## 5. 删减原则

若两人团队无法在 16 周内完成全部 P0，按以下顺序删减：

1. 删除 AI Visual Generation 作为独立创新；
2. 删除 Layout Optimization / Repair Loop 主实验；
3. 将 Signaling 合并为 dynamic presentation 的 cue-target 子指标；
4. 将 Visual Acquisition 限定为“决策与已提供候选池选择”，不建设通用搜索/资产平台；
5. 若仍过宽，保留 Visual Necessity/Retrieval Triggering 与 Semantic Alignment，把自动 temporal planning 降为受控实验。

不允许通过减少 baseline、取消人工 gold 或把 Prompt requirement 当 execution guarantee 来“节省范围”。

## 6. 数据表示与决策契约

拟议 `research_generation_v2` 最小关系（不新增独立的 `proposition_visual_plan.json`）：

```text
source_unit(id, page/paragraph/span, text, image_refs)
  → lesson_plan.knowledge_points[].propositions[]
      (knowledge_proposition_id, proposition_text, source_refs,
       visual_need, rationale, confidence, acquisition)
  → script_v2.narration_propositions[]
      (narration_proposition_id, knowledge_proposition_ids,
       narration_text, narration_span)
  → storyboard.visual_element(id, semantic_role, proposition_ids, source_refs)
  → visual_event(id, action, target, proposition_ids)
  → timed_storyboard.schedule(trigger_at_sec / at_sec, cue_target)
  → compiled_runtime_timeline(start_ms, duration_ms)
  → animation-trace-v0.1(actual_ms, target_resolution, status)
  → render-evidence-v0.1(observed_visible_start/end, confidence)
```

字段存在不等于能力实现。每个自动字段必须记录 `producer`、`version`、`confidence` 与 `abstain_reason`；人工 gold 与模型预测分开保存。

工程落地采用“复用现有文件、只补缺失字段”的原则：知识命题、`source_refs`、`visual_need`、`acquisition` 放入现有 `lesson_plan.json`；旁白生成后再把旁白命题、`knowledge_proposition_ids` 与 `narration_span` 写入新增的结构化 `script_v2.json`，同时保留旧 `script.txt`；`visual_element` 继续使用 `storyboard.json` 的 `elements[]`；`visual_event` 继续使用 `animations[]` / `timeline[]`。时间证据分四层保存：`timed_storyboard.json` 只承担 planned `trigger_at_sec` / `at_sec`，HTML 编译后的 runtime timeline 承担 `start_ms` / `duration_ms`，Browser raw trace 与 `animation-trace-v0.1` 承担 runtime `actual_ms`、target resolution 与 status，独立的 `render-evidence-v0.1` sidecar 承担 final-video 中人工或工具观测的可见区间。它是成片证据，不是第二套 runtime trace。当前不创建独立的 `proposition_visual_plan.json`，只有在需要多套候选方案、独立版本管理或跨 Renderer 共享视觉规划时才重新评估是否拆分。

### Visual Acquisition 决策树

Knowledge Proposition
        ↓
Need Visual Support?
   ┌────┴────┐
   NO       YES
   │          ↓
讲解/文本   Existing Source Visual Sufficient?

## 7. 最小人工 Gold

正式 pilot 不标完整系统所有字段。每个 proposition 只标：

1. `proposition_span` 与 `source_evidence_ids`；
2. `visual_support_need`：none / source-sufficient / extra-support-needed / uncertain；
3. `retrieval_need`：no / retrieve / generation-candidate / uncertain；
4. 候选视觉的 `appropriateness` 与 `visual_function`：explain / organize / signal / example / decorative；
5. `proposition_to_visual_binding`：correct / partial / wrong / missing；
6. `acceptable_visual_window` 或可判定的 onset/interval；
7. `signaling_need`、`target` 与 `acceptable_window`；
8. rendered outcome：correct / missing / premature / delayed / mismatch / wrong-target / overload / unobservable。

正式 pilot 不标：图像生成审美、多轮 layout repair history、所有 Coherence 子类、学习结果。

门槛：

- proposition boundary agreement ≥ 0.80；
- visual need、retrieval need、binding、event label 的 κ/α 预注册目标 ≥ 0.67；
- 不确定/不适用必须允许 abstain；
- 若 retrieval need 一致性低，RQ1 收缩为 Visual Necessity；
- 若 rendered interval 不可靠，RQ2 只报告人工 onset window 与 runtime event，不声称完整 visibility interval。

## 10. 最重要的三个实验

### Experiment 1：Visual Support / Retrieval Decision

在人工 gold proposition 上比较 always、never、heuristic、Direct LLM、no-source 与 proposed。主要指标：macro-F1、per-class recall、calibration、abstention、retrieval cost，以及最终候选视觉 appropriateness。关键消融：去 source、去教学目标、去 proposition context。

### Experiment 2：Semantic-Temporal Dynamic Alignment

固定同一视觉候选集，比较 lexical、embedding、Direct VLM、current semantic timing 与 proposed。指标：binding accuracy、target accuracy、onset error、window overlap、wrong-target/early/late/missing rate。关键消融：无显式 binding、sentence 替代 proposition、无 signaling policy。

### Experiment 3：End-to-end Decision Chain

在同一 T2V platform 上比较：

1. frozen v1；
2. `+ Visual Support/Triggering`；
3. `+ Semantic Binding`；
4. `+ Dynamic Planning`。

使用盲化 human event gold 评价原则违规、source fidelity 与 technical quality；若 PresentAgent 成功冻结，再测试 evaluator 与标注协议能否迁移到外部生成器，而不是把 T2V v1 伪装成 competing system。

### 实验范围审计：避免重复设计

三项实验共享同一套 knowledge/narration proposition、lesson plan、结构化 script、storyboard、timed storyboard 和证据 sidecar，不建设三套独立系统：

1. 实验 1 复用 `lesson_plan.json` 中的 knowledge proposition、`source_refs`、`visual_need` 和 `acquisition`，研究是否需要视觉以及是否触发检索；
2. 实验 2 复用 `script_v2.json` 中由 knowledge proposition 派生的 narration proposition/span 与同一批 storyboard 元素，研究 narration proposition→visual binding 和 timing；
3. 实验 3 只是前两项能力的受控端到端消融，不新增另一套 visual planner、timing、runtime trace 或成片证据格式。

明确不重复实现：

- 不新增独立 `proposition_visual_plan.json`；
- 不新增第二套 `visual_element`、`visual_event` 或 `schedule` schema；
- 不新增第二套 runtime trace，继续使用 `animation-trace-v0.1`；
- final-video 可见区间写入 `render-evidence-v0.1`；它与 runtime trace 分工不同，不重复记录浏览器事件；
- PresentAgent 对照、Video-QA 和学习者实验不并入 P0 主实验；
- AI visual generation、通用 RAG、自动 repair 和 layout optimization 保持 P1/P2。

因此，P0 的最小实验组合是：

```text
Experiment 0a：5–10 proposition 非正式标签与接口 sanity check
Engineering dry run：3–5 份文档跑通结构化产物与证据链
Experiment 0b：20–30 proposition 正式双人 pilot
Experiment 1：Visual Support / Retrieval Decision
Experiment 2：Semantic Binding + Temporal Alignment
Experiment 3：端到端消融（时间允许时执行）
```

如果 pilot 证明某一层无法稳定标注，或正式实验没有增益，就删除该层的论文主张，而不是继续增加模块。

## 11. Contribution Gates

| 候选贡献 | 保留条件 | 失败处理 |
|---|---|---|
| Pedagogically grounded visual-support decision formulation | visual need/retrieval gold 可稳定标注，且策略优于 always/never/direct LLM | 降为数据分析或只保留 Visual Necessity |
| Proposition-aware visual acquisition and semantic binding | binding 与 acquisition decision 在人工 gold 上有显著增益 | acquisition 降为固定候选池；不声称新策略 |
| Semantic-temporal dynamic presentation | 相对 current semantic timing 改善对象、时间与 signaling 指标 | 只保留 semantic binding，不声称 timing 贡献 |
| Event-level post-render validation | 相比 aggregate/VLM 在定位、归因或校准上有稳定优势 | 降为人工评价协议，不列方法贡献 |
| Source-conditioned claim | no-source 消融稳定变差，且不是 token/metadata leakage | 删除 source-conditioned 修饰 |

## 12. 两人并行执行与合并

只保留一次接口契约冻结、一次 Gold/标注协议冻结和一次结果合并，不安排周期性“反复对齐”。

| 主线 | 独占责任 | 可独立推进的产物 |
|---|---|---|
| **成员 A：Visual Decision Track** | Phase 1 source/proposition schema；Phase 2 Visual Necessity、Retrieval Triggering、候选池；T2V v2 生成 | schema、visual-decision predictions、候选视觉包、方法/消融结果 |

| **A/B 独立标注** | 各自填写盲化标签，首轮不看对方结果 | annotator_A、annotator_B、agreement、adjudicated gold |

## 13. P1：AI Visual Completion 与 Bounded Iterative Repair

### 13.1 AI Visual Generation

只有同时满足以下条件才触发：

1. proposition 需要视觉；
2. 教材没有合适视觉；
3. 检索候选均低于适配阈值；
4. proposition 适合生成式视觉表达；
5. 生成结果通过 source/semantic safety check。

P1 可只支持少量结构化类型，或只评价 retrieve vs generate decision。图像生成模型本身不列论文创新。

### 13.2 Bounded Iterative Repair / Repair Convergence Control

```text
Diagnose
  → Local Repair Candidate
  → Re-render
  → Multi-objective Re-evaluation
  → Accept / Rollback / Alternative
  → Stop
```

必须新增：

- `max_iterations`；
- repair history 与 state hash；
- objective vector：principle violations、source fidelity、layout/readability、technical quality、edit cost；
- regression detection；
- accept / rollback；
- repeated-state 与 A↔B oscillation detection；
- no-improvement/patience stop。

复用 `src/textbook2video/repair/orchestrator.py::RepairOrchestrator` 的 candidate、accept/rollback、lineage 与 `max_rounds`；新增研究模块：

- `src/textbook2video/research/repair_convergence.py`；
- `src/textbook2video/research/repair_objectives.py`；
- `tests/test_repair_convergence.py`；
- `tests/test_repair_oscillation.py`。

Layout repair 只是一类 action。若 overlap 修复导致语义关系恶化、缩小导致不可读、删除后 richness heuristic 又加回元素，必须 rollback 或停止；不能把“多跑几轮”当优化成功。

## 15. 版本、Baseline 与污染控制

| 改动 | 是否允许进入正式代码 | 隔离要求 |
|---|---:|---|
| proposition/source schema | 是 | v2 schema + migration + flag |
| visual need/acquisition fields | 是 | 默认关闭；保存 v1/v2 双产物 |
| semantic binding | 是 | 可单独关闭，支持 gold/predicted 两种输入 |
| proposition-aware timing | 是 | 保留 legacy/semantic modes；固定 mode 名称与配置 |
| runtime trace persistence | 是 | flag 控制；不得假装是 rendered visibility |
| event evaluator | 是 | 独立 evaluator；不改变生成默认结果 |

## 16. 数据与统计

- Doc2Present 30 份 source 作为正式外部数据；document-level split 暂定 dev 10 / validation 5 / locked test 15，在 G0 一次性冻结。
- 现有 5 案 Pilot 只做操作定义和标注校准，不并入正式 test。
- proposition/event 是 document 内嵌套观察，统计使用 document-level bootstrap 或 mixed-effects model。
- retrieval 评价必须同时报告准确性、cost/coverage 与 abstention，避免 Always Retrieve 通过堆资源获胜。
- generation 评价必须控制 source、narration、候选池和时长，避免把更多内容/更贵模型混成方法增益。
- 无真实学习者实验时，只声称 visual decision、alignment 或 principle compliance 改善，不声称学习效果提升。

## 17. 下一步第一件事

G0 字段、ID、目录和 mock 已按 `research-generation-v2-v0.1` 冻结。下一步先用 **5–10 个 proposition 做非正式标签与接口 sanity check**，只用于发现定义和数据阶段冲突；随后立即实现 `research_generation_v2` 的最小结构化产物与导出链，并在 3–5 份文档上 dry run。若需不兼容调整则发布 v0.2 migration；之后冻结标注协议，再开展 **20–30 个 proposition 的正式双人 Visual Support / Retrieval Triggering pilot**。
