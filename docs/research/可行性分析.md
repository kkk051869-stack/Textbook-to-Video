## 1. 项目概述

### 1.1 目标

构建一套 **全自动化流水线**，将中小学教材文本输入后，自动完成以下流程：

```
教材文本 → 内容拆解 → 分镜脚本 → CSS 动画页面 + 演讲稿 → TTS 配音 → 音视频合成 → 教学视频
```

最终输出教学视频，面向中小学生，要求简单易懂、生动有趣。

---

## 2. 系统 Pipeline 架构

> 此架构设计仍然有效，已调整为 6 步流程 + 音频先行。

```
Phase 1: 教材解析      → 结构化知识点 JSON
Phase 2: 讲稿生成      → 讲稿文本 + 画面动画大纲 JSON
Phase 3: 动画生成      → HTML 动画页面（LLM 直接生成）
Phase 4: TTS 配音      → 音频文件 + 每段时长
Phase 5: 录制合成      → MP4 视频（Playwright 录制 + ffmpeg 合并）
Phase 6: 后处理        → 最终视频（字幕、片头片尾等）
```

### Phase 1: 教材内容解析

- **输入**: 教材 PDF / 纯文本
- **处理**:
  - 文本提取与清洗
  - 章节自动分段（LLM 识别标题层级和逻辑边界）
  - 知识点提取（概念、定义、示例、图解说明）
- **输出**: 结构化 JSON — 章节 → 小节 → 知识点列表

### Phase 2: 分镜脚本生成

- **输入**: Phase 1 的结构化知识点
- **处理**:
  - 将知识点转化为教学场景
  - 生成演讲稿（教师口吻，生动有趣）
  - 标注动画需求
- **输出**: 讲稿文本 + 画面动画大纲 JSON

### Phase 3: 动画页面生成

- **输入**: 画面动画大纲
- **处理**: LLM 为每个场景生成独立的 HTML/CSS/JS 动画页面
- **输出**: 一组 HTML 文件
- **关键挑战**: 保证跨场景的视觉风格一致性

### Phase 4: TTS 配音

- **输入**: 讲稿文本
- **处理**: 调用 TTS 生成各场景音频，获取每段精确时长
- **输出**: MP3 音频文件 + 精确时长列表

### Phase 5: 音视频同步录制

- **输入**: HTML 动画页面 + 音频文件 + 时长列表
- **处理**: Playwright 打开 HTML 页面，按音频时长驱动 slide 翻页，录制为视频
- **输出**: MP4 视频

### Phase 6: 后处理

- **输入**: 各场景视频片段
- **处理**: FFmpeg 拼接 + 可选字幕 + 可选片头片尾
- **输出**: 最终 MP4 教学视频

## 3. 学术前沿参考

> 本节内容仍然有效，学术成果的启发已融入项目设计。

### 3.1 LASEV — LLM 多智能体教学视频生成系统

- **来源**: 2026 年论文，https://robitsg.github.io/LASEV/
- **架构**: 编排 Agent 协调三个专业 Agent：
  - **Solution Agent**: 解题推理
  - **Illustration Agent**: 生成可执行可视化代码
  - **Narration Agent**: 生成教学演讲稿
- **关键特性**:
  - 不直接合成像素，而是生成**结构化可执行视频脚本**
  - 完全自动化，无需人工编辑
- **成果**: 日产量超 100 万条视频，成本降低 95%
- **启发**: 多 Agent 分工协作 + 可执行代码是正确的技术路线

### 3.2 Code2Video — 代码驱动的教学视频框架

- **来源**: 2025 年论文
- **架构**: 三 Agent 协作：Planner + Coder + Critic
- **关键特性**:
  - 范围引导的自动修复（ScopeRefine）
  - 视觉锚点提示（Visual Anchor Prompt）
- **启发**: Critic Agent 用 VLM 审查动画画面质量的机制值得借鉴

### 3.3 TeachMaster — 生成式教学框架

- **来源**: 2025 年论文
- **架构**: 三阶段流水线：内容规划 → 演示生成 → 质量验证
- **成果**: 制作成本仅为传统在线课程的 0.3%
- **启发**: 视觉与音频分离开发生成、最后同步的架构已被验证可行

### 3.4 Learn Your Way — Google AI 增强教材

- **来源**: Google 2025，基于 Gemini 2.5 Pro
- **成果**: 随机对照试验证实 AI 增强教材显著优于传统数字教材
- **启发**: 教材内容的多模态变换（文本→幻灯片→视频）是可行且有教育价值的

### 3.5 启发汇总

| 启发 | 来源 | 应用 |
|------|------|------|
| 多 Agent 分工协作 | LASEV | 内容解析 + 动画生成 + 配音 + 审校 |
| 生成可执行代码而非像素 | LASEV/Code2Video/TeachMaster | 生成 HTML/CSS/JS 代码，浏览器渲染为动画 |
| VLM 审查画面质量 | Code2Video | 用视觉模型截图审查动画是否正确 |
| 视觉与音频分离生成 | TeachMaster | 动画页面和 TTS 音频独立生成，最后同步 |
| 模板系统保证一致性 | LASEV | 统一的 CSS 变量 + 基础模板 |

## 4. 成本分析

以生成 **1 个教学视频** 为例：

| 项目 | 估算成本 | 说明 |
|------|---------|------|
| LLM API 调用 | ¥15-40 | 约 70K tokens |
| TTS 合成 | ¥0-20 | Edge TTS 免费；Fish Audio 约 ¥0.6 |
| 计算资源 | ¥5-15 | Playwright + FFmpeg |
| **单视频总成本** | **¥20-75** | 取决于 LLM 和 TTS 选型 |

对比传统人工制作 ¥3,000-10,000，AI 生成仅为 **0.3%-2.5%**。

## 5. 技术选型（已确认的决策）

### TTS

| 服务 | 用途 |
|------|------|
| **Edge TTS** | MVP 阶段，零成本 |
| **Fish Audio S2 Pro / CosyVoice 3.0** | 生产阶段，音质最佳 |

### 录制

- **Playwright** (Python) — 浏览器录制
- **ffmpeg** — 音视频合并

### LLM

- **litellm** 统一调用层 — Claude/GPT/GLM/Qwen 可切换
- 具体模型待 benchmark

### 动画技术栈（已确认）

| 技术 | 说明 |
|------|------|
| 自写 SlideController | ~50 行 JS，替代 Reveal.js |
| `.anim` + `.d1~d12` 延迟系统 | 替代 Animate.css |
| Canvas 粒子系统 | 替代 tsParticles |
| SVG 噪点纹理 | 所有高质量动画必备 |
| 多层 radial-gradient | 背景质感 |

## 6. 主要风险与挑战

| 风险 | 级别 | 缓解措施 |
|------|------|---------|
| LLM 生成动画一致性 | 🔴 高 | 统一 CSS 变量 + 基础模板 + Prompt 约束 |
| 教育内容准确性 | 🔴 高 | 审校 Agent（参考 LASEV quality gate） |
| 音画同步 | 🔴 高 | 音频先行方案 + JS 驱动时间轴 |
| 跨场景风格统一 | 🟡 中 | 亮色主题 + 配色方案参数化 |
| LLM 代码生成 bug | 🟡 中 | Playwright 自动验证 |
