状态：阶段 1 已交付；阶段 2 已获批准并交付离线工程实现，状态 `TESTED_MOCK`，最终视觉相关代码 `494 passed`。全量仅一次，三项环境失败详见下文。无真实模型调用，未启动 r71 或整课试跑，独立语义验收尚未执行。本文保留审核修订方案及实际验收记录。

## 一、根因与边界

r70 的五个模型响应都失败于编译/截图审阅之前：一条图面板容量限制、三条固定关系角色表拦截、一条模型响应协议包装失败。这里的“角色表拦截”不能直接归类成误拒：有的边可能合法，有的可能错了对象或漏了中间过程，需分开验证。特别校正轮次：`revision-03` 是从 0 开始编号的第四个响应/尝试（总共五次，目录为 `revision-00` 至 `revision-04`），不是第三次；它返回了裸候选但没有 `tool` 包装。

用户指出的 r66 `ACCEPT` 仍有语义错误，说明当前 `visual_fact_audit` 审核模型只能当筛查器，不能作为语义正确性的充分证明。因果错误、对象错误和缺失中间过程的责任分层如下：

| 检查层 | 可负责的事 | 不能据此声称 |
|---|---|---|
| 确定性结构/来源校验 | schema、ID/端点、容量/拓扑、来源 ID 存在、引用对应当前原文、旁白分配完整且不重不漏 | 引用存在不等于边的动作、方向、因果或教学关系正确 |
| `visual_fact_audit` 编译审核模型 | 对每条边和每个旁白事实给出来源/截图对齐的风险提示 | 单个模型返回 `ACCEPT` 不等于语义通过；r66 已构成反例 |
| 独立语义签核 | 人工对照完整教材原文、完整旁白和最终页面，逐边核对主语—动作—宾语/方向/因果，并查找缺失中间过程及遗漏事实 | 截图可读、覆盖分数高，不能替代以上核查 |

在有独立、经人类标注验证的语义校验器之前，模型 `ACCEPT` 不得单独升级为语义通过；未经独立签核的产物最多标记为“工程结构通过/语义未确认”。第一阶段不改固定角色表。第二阶段若要移除角色配对，必须作为单独决策，在对抗性语义样例及 r66 类漏检评估完成后再批准；在此之前保留现状。即使后续移除，也必须保留来源核验和上述独立语义签核，不以“strict”标签本身证明正确。

## 二、分阶段实施

### 阶段 1：只收敛包装、一个候选契约和结构错误定位

只改 `visual_tools.py`、`visual_model_interface.py`、必要时 `visual_grammar.py`；覆盖 `tests/test_visual_tools.py`、`tests/test_visual_model_interface.py`、`tests/test_visual_grammar.py`，并用既有缓存/旧产物测试确认兼容。**不改** `visual_semantic_graph.py` 的角色规则，不实现 DraftGraph Patch，不接 proposition graph，不改 `pipeline/course_visuals.py` 或课程主链。

模型仍使用供应商现有 `response_format={"type":"json_object"}`，只返回一个 JSON 对象 `VisualPlanV1`；模型不再输出 `tool`/`name`/`arguments`、操作类型、父路径、操作原因或程序元数据。现有视觉字段不重造；`visuals`、`content_map`、`composition`、适用时的 `page_plan` 以及已有 `updates` 字段沿用现有含义。`visuals` 与 `updates` 按现有语义互斥。程序根据运行状态选择 create/revise，再把规范化内容包装成现有内部调用对象，现有执行器、渲染器和修订门禁继续使用。

契约示例（字段值仅示意）：

```json
{
  "plan_version": "visual-plan-v1",
  "visuals": [{
    "id": "hash_flow",
    "kind": "flow",
    "title": "哈希与区块引用",
    "teaching_goal": "说明区块如何保存前一区块哈希",
    "narration_refs": ["narration-001", "narration-002"],
    "nodes": [
      {"id": "prev_hash", "label": "前一区块哈希", "role": "data",
       "source_ref": ["source-014"], "stored_by": "current_block",
       "refers_to": "prev_block"},
      {"id": "current_block", "label": "当前区块", "role": "entity",
       "source_ref": ["source-014"]},
      {"id": "prev_block", "label": "前一区块", "role": "entity",
       "source_ref": ["source-014"]}
    ],
    "edges": [
      {"source": "current_block", "target": "prev_hash", "relation": "stores",
       "source_ref": ["source-014"]},
      {"source": "prev_hash", "target": "prev_block", "relation": "references",
       "source_ref": ["source-014"]}
    ]
  }],
  "content_map": {
    "element-1": {"decision": "represented", "source_ref": ["source-014"],
      "visual_refs": ["hash_flow:prev_hash"], "reason": "区块保留前一区块哈希"}
  }
}
```

契约细则：

- `visuals[].id` 和节点 `id` 沿用现有局部 ID；边的 `source`/`target` 必须指向**同一 visual 内**的节点 ID。ID 唯一性、安全格式和端点存在由程序确定性校验。阶段 1 不重写传给 renderer 的 ID。
- `source_ref` 在模型契约中规范为非空 `source-###` ID 数组；适配层仍接受现有手工接口/旧记录中的单字符串或显式逗号枚举，并规范化到同一内部形式。随后仍由现有 `materialize_source_refs` 从当前 source 物化精确原文；无效/过期引用拒绝，不猜测、不改写引用含义。
- `narration_refs` 保持现有 `narration-###` ID 数组及顺序。程序从不可变完整旁白生成 unit、物化 `narration_span` 并验证连续、无重复、无遗漏；不接受模型改写旁白来凑覆盖。
- `stored_by` / `refers_to` 在阶段 1 **继续保留**，仍按既有校验/物化处理；不能把它们静默删除或仅靠自由文本边替代。
- 解析先保存原始响应及 hash，再用现有 `_json` 行为解析单个 JSON 对象（允许当前已支持的 fenced JSON/控制字符兼容；不补缺失括号、不猜字段、不修语义）。校验 `plan_version`、字段 allowlist、类型和互斥关系；错误携带 JSON 路径、visual/node/edge ID 与违反的确定性规则。
- 执行器将 `VisualPlanV1` 映射成既有内部 `{tool, arguments}`；create/revise 由有无父版本及当前 run 状态决定，compose/排版沿用现有 composition 渲染路径，不由模型返回工具名。最大修订次数不变，不因格式错误额外重试。

例如 10 节点图继续因 2–8 节点 renderer 限制而失败，但错误改为报告 `visuals[0].nodes`、当前/允许数量及超限节点 ID，并说明需要结构替换/分面；阶段 1 不自动删节点、不缩字、不假称已修复。

### 阶段 2：先持久化 DraftGraph，再做局部语义修订或结构替换

用户已批准本阶段的离线工程实施。候选在**语义物化之前**进入单轮 revision 目录：原始响应先落盘；解析和最小 ID/引用结构检查后，保存不可变 `draft-graph.json`。因此 `materialize_semantic_graphs` 的角色/关系校验失败时，DraftGraph 仍可供定位与修订。若 JSON 或唯一 ID 本身无效，则保留原始响应并记录结构错误，不伪造稳定 ID。

DraftGraph 最少绑定：候选及 schema 版本、raw response 路径/hash、父 revision/hash、source 原文 hash 与被选 `source_ref`/物化摘录、旁白 hash、由不可变旁白导出的**完整预期 narration unit 列表**、每个 panel 的原始 `narration_refs`、结构化错误位置及 ID 映射。旁白未覆盖/重复也写入失败 DraftGraph，不能因失败而丢失覆盖责任。

稳定 ID 规则：模型现有 `visuals[].id`/`nodes[].id` 作为候选内局部 key，边以有序端点对为局部 key（现有 grammar 禁止重复端点对）。程序在 DraftGraph sidecar 生成并持久化 run 内 stable ID：根候选按明确分隔编码的 `(run_id, object_kind, visual_key, local_key)` 计算 SHA-256 并加类型前缀；后继候选对映射表中确认未变的 key 沿用父 stable ID，新对象从父候选 hash 与局部 key 派生新 ID；碰撞显式报错，不按 label 相似度自动认亲。DraftGraph 用 stable ID 定位对象；VisualPlan、`content_map.visual_refs`、edge endpoints 和 renderer 继续使用原局部 ID。revision selector 通过 sidecar 在两套 ID 间映射，不改变旧 renderer/手工接口 ID。

修订分两类，禁止混用：

| 类别 | 适用 | 行为 |
|---|---|---|
| 局部修订 | 错误能唯一定位在既有 node/edge，且不改变 panel 分组、图类型、拓扑边界及完整旁白分配 | 只允许目标 stable ID 的 allowlist patch；语义字段仅限该对象的 label/detail/action/已存在来源绑定。错误端点以“删除被定位边+新增有来源支持的边”表达，不原地篡改端点；若需新增中间节点/边，只能作为目标关系的局部子图 patch，并绑定现有 source refs；不相关合法对象 hash 必须保持不变。 |
| 结构替换 | 10 节点超限需拆面；kind、面板数、节点归属/拓扑、跨面关系或旁白分区改变；或错误无法局部定位 | 基于 DraftGraph 创建完整子候选，明确旧→新 ID 映射和删除/新增集合；沿用原 source/narration hash，重验完整事实覆盖。旧 DraftGraph/父版本不可变，合法节点/边可按明确 ID 复用，但不得自动复制未经确认的关系。 |

每个 patch 校验 parent hash、目标 ID、允许字段、来源绑定与结构；越权字段或父版本漂移即拒绝。每轮保存原始响应、patch、父子 hash、诊断与结果。达到原有迭代上限即停止。

### 字段与历史资产兼容策略（阶段 2 才允许转换）

不直接删除 `stored_by`/`refers_to`。若要将其投影为显式边，方向和语义必须一一确定：`stored_by=owner` 等价于 `owner --stores--> value`；`refers_to=target` 等价于 `value --references--> target`。转换时保留原始字段、source refs 和 node IDs；仅当 round-trip 测试证明 owner/referent、方向、可见标签、来源绑定均无损后，才讨论新候选的规范化。无法无损映射的记录继续走旧字段路径。

- 历史运行资产只读且按旧 schema 读取/验签，不批量迁移、不重写 hash。
- 先验证现有代码 hash/cache binding 会让旧候选缓存失配；历史运行资产仍可只读查看。只有测试证明现有 binding 不足时，才补一个契约版本项；不重建缓存系统。
- 手工 `tool + arguments` 接口保持兼容，由边界 adapter 转为同一个内部对象；不强迫人工调用者改 schema。
- 已有 revision selectors 使用的 renderer local IDs 保持不变；DraftGraph stable ID 只存在 sidecar，并经映射进入现有修订接口。角色/owner/reference 语义字段的 patch 在兼容验收前仍走完整替换。

此阶段**不接入 proposition graph、不改课程主链、不新建事实抽取系统或并行协议**。

### 实际接线与契约

`visual_draft_graph.py` 是一个存储与受控修订模块，不是另一套模型输出协议。dispatch 在语义物化前以独占创建方式写入 `draft-graph.json`；后续另写 `draft-result.json`，不改写原候选。重复/缺失 ID 的候选保留诊断和原始输入，不分配伪 stable ID。fingerprint 的预处理跳过语义物化，避免在 DraftGraph 保存之前触发角色失败。

DraftGraph 包含候选、原始响应路径/字节 hash、raw tool request hash、父 draft/父 revision 记录 hash、完整原文单元与精确引用快照、完整旁白与所有预期 units、逐面板旁白 refs/spans、对象 stable ID→原选择器映射、父子映射及新增/删除 ID、诊断和 `semantic_status=UNCONFIRMED`。容量/角色/旁白/引用失败仍保留该证据；revision/failure 校验同时绑定 draft/result。旧版没有 sidecar 的 revision 仍按旧入口验证，后继只绑定其旧 revision 记录，不迁移旧资产。

模型继续只返回 VisualPlanV1。程序给出 `draft_updates` 模式时，复用 `updates` 字段，最多一个程序定位的目标：

```json
{
  "plan_version": "visual-plan-v1",
  "updates": [{"target_id": "edge-<程序提供的稳定ID>", "set": {"relation": "stores"}}]
}
```

允许字段和目标来自既有确定性校验器的真实错误位置；scope 会重新校验，不信任模型自报目标或可改写的错误文案。局部不能改 ID、已存在 role、owner/referent、面板、旁白或未授权来源。局部中间子图仍使用同一个 `updates[].set` 的 `nodes`/`edges`，只删除被定位边并插入连通的新子图，保留所有旧节点及其它边；新增对象只能用目标关系现有来源，未知字段被拒。原始补丁在 raw tool request/模型原响应中留存，父子增删和 hash 在 sidecar 留存。

无法局部定位、角色/归属需要整体变化、拆面或 ID 失效时，程序选择既有 `structural_replacement`。对象映射只依靠明确 ID 和精确内容相等，不用 label 相似度认亲。普通完整替换可从同一不可变原文重选引用，引用增删明确写入 `source_reference_delta`，新引用仍逐项精确核验；不强迫保留已选错的旧引用。容量拆面保护原节点/边及其来源，同时允许修正确定性校验器明确定位的错误边；若原结构/来源错误无法定位，则记录完整增删并要求整体重验，不能把旧引用或角色表当语义真值。逐面板旁白必须重新覆盖全部原旁白，漏受保护节点/边或改旁白会拒绝。失败的 append_missing_panel 尝试作为独立失败分支保留，后续从已审核面板重新派生，不把失败新增的节点当成必须保留的教材事实。

`stored_by`/`refers_to` 继续保存原字段及原物化路径，未实施边字段迁移，因此无需同时维护第二份 ownership 事实。验证了原始 owner/referent 保留和可见物化，未删除旧字段。缓存 binding 已覆盖整个 package 的代码 hash；无需新增缓存协议。跨运行恢复会复制不可变 draft 证据、保存恢复来源，重新绑定恢复结果；旧否定审核依然保留。
