# 研究方案代码审计报告

> 审计日期：2026-10-04  
> 审计对象：当前 Textbook-to-Video 仓库、相关测试、tracked pilot3 artifacts 与 `.local/data` 中已有评测/视频产物。  
> 限定：本报告描述的是代码和产物事实，不代表拟议论文功能已经实现。

# 1. 审计结论

**存在重大误判。**

误判不在理论方向本身，而在工程起点：原研究设计把“教材 source evidence → knowledge point → narration proposition → visual element → visual event → rendered interval”近似视为当前项目已有链路。真实代码只较稳定地提供 KP ID、segment narration、element ID、planned event，以及评测侧可选的 runtime event start；source_refs 在 lesson plan 后断裂，proposition 不存在，final-video rendered visibility interval 不存在，principle-aware compliance 也不存在。

另一个重大差异是：default edge TTS 使用 legacy timing。`src/textbook2video/pipeline/timing.py::apply_timing` 在 legacy 模式重写 `animations[]`，但不更新已有 `timeline[]`；`src/textbook2video/animation_gen.py::build_slide_timelines` 在 timeline 非空时优先执行 timeline。因此“storyboard 中已有 trigger_at_sec”不能证明该时间进入最终 HTML/MP4。

# 2. 原研究报告中正确的判断

以下判断有代码或真实产物支持，可以保留，但需加边界：

1. 项目有从 PDF/DOCX 到有声 MP4 的完整流水线。证据：`src/textbook2video/pipeline/orchestrator.py::produce`、`recorder.py::record_html_to_video`、`compose.py::compose_video`。
2. 动态教学视频需要补充 Temporal Contiguity 与 Signaling；当前系统确有 planned timing 和 signaling mechanics，适合成为研究切入点。证据：`animations[].trigger_at_sec`、`timeline[].at_sec/action/target`、`animation_gen.py::_compile_timeline_items`、`templates/slide-controller.js::applyEvent`。
3. 技术正确不等于教学原则合规。`quality.py::build_quality_report` 主要检查结构、音频、字幕、布局、ID coverage 和 quiz 等 proxy；它不读取 final MP4 的教学语义。
4. 事件级诊断比只给整段/整视频总分更适合当前架构，因为 element ID、target、timeline event 和 runtime trace 已提供定位基础。
5. source-conditioned 是有潜力的差异化方向。pilot3 的 `source.json` 与 `private/annotation.json` 已有人工作成的 paragraph/concept evidence，可用于研究 pilot；但这不是生产 provenance。
6. repair 应基于诊断并通过 candidate 隔离。`src/textbook2video/repair/orchestrator.py::RepairOrchestrator` 已有 candidate、targeted evaluation、accept/rollback 和 lineage 机制。
7. Personalization 已有较强 Prompt-level requirement。`src/textbook2video/llm/prompts/script.md` 明确要求“大家/我们”、口语化转述、非低幼/非网络化；不适合作为主要 Gap。
8. Image principle 在当前产品形态下应条件性处理。代码、测试和抽样产物中未发现 presenter/digital-human/avatar/talking-head 生成路径。

# 4. 当前真实能力矩阵

判定口径：YES=生产或明确评测路径能稳定提供该能力；PARTIAL=有字段/Prompt/proxy/可选评测路径，但缺关键保证；NO=没有对应表示或观测。

| 能力 | 判定 | 当前表示/证据 | 关键缺口 |
|---|---|---|---|
| source | PARTIAL | PDF `extract_lesson_info` 有 page range/text；DOCX 有 section text/images；lesson plan 有 `source_refs`；pilot3 有人工 paragraph IDs | 无统一 source unit/span，未贯穿生成链 |
| KP | PARTIAL | `knowledge_points[].id`；segment `knowledge_point_ids`；quality ID coverage | source 绑定弱；script 无结构化 KP；element/event 无 KP |
| narration | YES | `segments[].narration`，一段对应一页；TTS/SRT 使用它 | 只有 segment/page 粒度 |
| proposition | NO | 无 proposition ID/schema；subtitle sentence/chunk 只是计时单元 | 需拟议 research sidecar |
| visual element | YES | `elements[].id/type/...`；`normalize_element_ids`；模板 `data-anim-id` | 最终 DOM 可缺失；无 source/KP/proposition 关系 |
| visual event | YES | animations 与 timeline；compiled runtime events | 两套事件源；语义正确性未验证 |
| planned time | YES | `trigger_at_sec`、`at_sec`、compiled `start_ms` | legacy trigger 可能被 timeline 覆盖 |
| rendered time | NO | runtime trace 有实际启动时刻，但不是 final MP4 visibility interval | 无 visible start/end、无逐帧对象观测 |
| signaling | PARTIAL | highlight/dim/focus/pulse 等 action、target、trigger | 无 applicability、语义 target、过量/遗漏检查 |
| quality | PARTIAL | technical QA 完整；KP/image/pedagogy/VLM 有 proxy 或独立 evaluator | 没有 principle-aware event compliance |
| repair | PARTIAL | generic storyboard/layout repair；candidate isolation/rollback | 没有 TC/Signaling action semantics；高成本操作未支持 |

## 4.4 Technical QA 与 Pedagogical Compliance

Technical QA 已覆盖：render bundle 时长一致、音频数量、SRT coverage、layout/overflow、元素/图片基本结构、quiz 结构、runtime target resolution、事件启动延迟。证据：`artifact_integrity.py::verify_render_bundle`、`quality.py::build_quality_report`、`animation_gen.py::run_layout_qa`、`eval/evaluators/animation_runtime.py::evaluate_animation_runtime`。

Pedagogical adjacent proxy 已有：KP ID coverage、image usage、`eval/evaluators/pedagogy.py::evaluate_pedagogy`、`content.py::evaluate_source_fidelity`、`visual_vlm.py`、`av_semantic_alignment.py::AVSemanticAlignmentAdapter`。

但这些 proxy 尚不能证明 Mayer principles：尤其 AV semantic alignment 的 desired time 来自当前 generated sentence binding 与 lead，只检验内部一致性，不验证绑定是否教学正确；Visual VLM 以截图为主，不是事件级时序判断。

# 5. 真实数据流

## 5.1 链路

```text
PDF + lesson_number
  └─ parser.extract_lesson_info → page range + flattened text

DOCX + chapter/section
  └─ parser.extract_section_from_docx → flattened section text + extracted images

text/images
  └─ LLM lesson_plan.generate_lesson_plan
       → lesson_plan.json: objectives, KPs, source_refs, suggested_visual...
       → lesson_plan_prompt_section（不含 source_refs/required_images）
          └─ LLM scriptwriter.generate_script
               → script.txt: plain narration segments
               └─ LLM storyboard.generate_storyboard + deterministic cleanup/enrichment
                    → storyboard.json: segment narration/KP IDs/elements/animations/timeline
                    └─ TTS narrator.generate_audio / generate_sentence_audio
                         → sN audio + measured audio_duration_sec
                         → optional sentence_cues.json
                         └─ timing.apply_timing
                              → 覆盖 storyboard.json + 写 timed_storyboard.json
                              └─ animation_gen.generate
                                   → template or LLM slide HTML
                                   → compiled slideDurations/slideTimelines
                                   → layout reports + render manifest
                                   └─ recorder.record_html_to_video
                                        → silent MP4（默认完成后删除）
                                        └─ subtitles.generate_srt
                                        └─ compose.compose_video
                                             → final MP4
                                             └─ quality.write_quality_report
```

独立评测路径可对 HTML 调用 `window.exportAnimationTrace()` 并保存/adapt `animation_trace.json`，再运行 animation/runtime/semantic/VLM/source evaluators；它不是 `produce` 默认链路。

## 5.3 真实产物抽样

- `datasets/pilot3/artifacts/` 有 8 个案例的 HTML、storyboard、timed storyboard、quality、SRT 和 layout；没有 tracked MP4/animation trace。
- 8 个 tracked `lesson_plan.json` 抽样状态为 disabled，不能支撑真实 KP/source provenance 结论。

# 6. 当前最值得研究的 Gap

最多保留三个：

1. **Source-conditioned event-level diagnosis**：以最小 sidecar 建立 source/KP/proposition/element/event 证据链，输出可核查的违规理由，而不是整页相似度或总分。
2. **Plan/runtime/video 三层时间证据**：识别 planned trigger、浏览器实际事件启动与 MP4 对象可见区间的差异，避免把 internal timing consistency 当 Temporal Contiguity。
3. **Signaling applicability、target correctness 与 overuse**：复用现有 action/target mechanics，新增“何时应提示、提示谁、是否过量”的原则级诊断和 abstention。

不把端到端生成、真实 TTS duration、元素 ID、runtime trace、通用 source fidelity、Personalization Prompt 或 generic repair orchestration写成论文创新。

# 7. 当前最危险的研究假设

以下假设必须先做 3–5 案例 pilot：

1. **Proposition 可稳定标注。** 当前 segment 较粗，subtitle chunk 又只是形式切分；若 proposition 边界与 element binding 的人际一致性低，整个事件级定义不成立。
2. **Final-video visibility 可可靠观测。** runtime `actual_ms` 不是 MP4 visibility；对象的渐显、遮挡、持续显示、focus/highlight 时长需要单独验证。若 observer 误差过大，只能把主结论降为 runtime event onset。
3. **Source conditioning 有增益。** 生产 source_refs 很弱，只能先用 pilot3 的人工 paragraphs/concept evidence。必须证明 source 相比 narration-only baseline 改善诊断，而不是增加输入却无效果。
4. **当前 baseline 有足够自然违规。** Prompt 的丰富度与 fallback 提示有风险，但需统计真实 early/late/wrong-target/overuse 分布，不能仅依靠人工 fault injection。
5. **Direct VLM 不是已经足够。** 必须与统一输入/输出协议的 VLM judge 对比，证明结构化方法在定位、校准或可解释性上真正更好。
6. **runtime event 与教学对象一一对应。** grouped targets、renderer compaction、LLM HTML 与 overlay 可能破坏该假设，应先量化 unmatched/ambiguous cases。

Pilot 的停止条件：标注一致性未达阈值、自然违规过少、source 增益不明显或 visibility 不可复现时，缩小 claim 或转向 runtime target reliability benchmark，不继续扩张 repair。

# 8. 是否建议继续当前论文方向

**调整后继续。**

理由：现有项目拥有难得的真实生成链、元素/事件 ID、页面级真实音频时长、HTML runtime、最终 MP4 与评测/repair 基础，足以支撑一个扎实的事件级研究载体；文献边界也支持把创新收窄到 source-conditioned、principle-aware diagnosis。需要调整的是研究顺序和声明强度：先承认 provenance、proposition 与 rendered interval 都未实现，用 sidecar pilot 验证定义与可观测性，再做诊断；repair 仅在诊断可靠后进入 P1。
