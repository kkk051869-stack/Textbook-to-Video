## 关键失败：引文真实仍不保证对象符合目标角色

flows-s1的context原回复选择`flow-data-ri`，同一条证据写明：actor=`Subsequent invertible layers fθj>i`、action=`operate only on`、patient=`ri`、candidate label=`ri`，解释也明确称它为patient。全部引用连续且真实，程序锚点校验通过。

但是本轮Prompt要求SUPPORTED对象实际执行叙述动作。选择patient不符合这个执行者导向的要求，说明当前语义支持判断/门禁仍有角色缺口。4个代理裁判均支持ri，只能证明代理接受这种视觉关注目标，不能消除与已有请求规则的冲突。若未来允许绑定被处理的数据、结果或多个不同角色，应在运行前明确，并使用现有对象/绑定结构表达；不得事后修改本轮成功定义。

这里不宣称“数据对象永远不能被教学画面指示”。问题是生成要求、实际输出与评价口径没有在本轮一致执行。该条应保留为规则冲突，不写成通过语义验收；不新增一套图、协议或修订框架来救分。
