# 通用增强与成片验收交接

## 目标与策略（负责人要求记录；下述新机制尚未实现）

目标是可跨教材使用、效率高且真正改善教学表达的增强链路，不是针对某一课补丁，也不是仅恢复旧页面出片。
开发验收采用严格增强；生产容错采用透明、局部且明确标识的降级。两种目标不能混为一谈。

- 每页都需分析教学内容、决定表达和编排，但不等于每页强行加图。
- 必须图解的教学内容要真实生成、插入、检查；失败则本次增强任务未完成，不能悄悄用旧页面充当增强成功。
- 标题/过渡等不需要图解的页面明确记录无需增强；可选装饰失败可省略，不影响教学信息。
- 增强成功数为零时，不能发布为“增强功能已完成”的成果。保留诊断产物不等于通过验收。
- 音画不同步、内容错误、来源/文件完整性错误必须阻止最终交付。当前缺少自动实际视频时序门禁，不能声称代码已实现该要求。

## 通用方案与下一步顺序

1. **审核服务最小健康检查与故障隔离。** 先用最小图片审核请求确认调用链可用，保存脱敏错误诊断；不可用则停止增强批次，不让每页重复撞同一个错误。区分传输失败、生成错误、审核否决；传输失败不应触发重新画图。
2. **减少模型的机械负担。** AI负责教学关系、表达选型和语义修改；程序负责来源ID物化摘录、布局计算、字号与溢出约束，避免要求AI同时维护重复的长摘录与ID。不是删除事实/来源校验，也不是专为区块链手填图型。
3. **真正的逐页缓存与局部恢复。** 保存并验证输入/代码/策略/资产绑定；成功页可安全复用，失败页从对应阶段恢复。内容问题改内容、布局问题改布局、接口问题重试接口，不能整课全部重来。该项尚未实现。
4. **独立修复录制时钟和最终验收。** 查清页面时钟—录制媒体时间—音频时间关系，增加实际MP4切页及元素出现时刻检查，不能靠 `-shortest` 掩盖尾页缺失或不经验证整体拉伸视频。可只读复用r36 HTML/音频/字幕，在新目录重新录制，不重跑增强。
5. **公共问题收口后再整课。** 先验证最小通用链路与跨内容回归，再以严格增强目标跑整课；不把0增强、纯旧页、测试数量或文件存在当成功。录制修复可独立推进，不必等增强全部成功。

禁止改冻结输入/gold、旧运行、master/A归档；不启动baseline/P0成对、服务器或批量实验。密钥与大产物不入Git。
