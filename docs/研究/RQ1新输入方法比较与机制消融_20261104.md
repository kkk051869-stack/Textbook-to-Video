日期：2026-11-04
范围：RQ1 开发性小规模比较；不属于 pilot、validation、locked test 或正式论文实验。

## 结论摘要

本轮以三个可追溯的 NOAA 教学材料为新输入，固定 4 条开发命题和 12 条跨文档比较命题；实际运行 Never Retrieve、Always Retrieve、Keyword Heuristic、Direct LLM、Proposed 和四项机制消融，并完成匿名双顺序 Judge 与少量真实候选图检查。方法预测、消融和 Judge 均有真实模型传输记录，结果包可在离线条件下验证并重新统计。

本轮**没有证明 Proposed 优于其他方法**。12 条比较命题上，Proposed 与四个消融的动作只在少数命题不同；Judge 的首选对模型与选项顺序高度敏感，48 次计划评价有 46 次可用。Proposed 在 46 次有效评价中被列为首选 5 次、列入可接受集合 44 次；不同方法的可接受集合重叠很大，不能把这些数字解释为准确率。实际素材检查仅覆盖 4 张有落地文件的候选，均未达到正式 ACCEPT。

Judge 结果是模型代理评价，不是人工真值、事实蕴含标注或学生学习效果。本轮未进行人工标注、人工 Gold、人工复核或 Kappa 计算，也不以这些作为当前研发前置条件。

## 2. 方法实现和比较条件

核心逻辑复用现有 proposition、source evidence、visual decision 与 acquisition 结构。`research_condition` 是显式研究入口；未传该参数的普通 `decide_visual_support()` 仍走原逻辑。本轮没有改变普通 produce 默认行为、素材来源门禁或图像生成开关。

| 条件 | 实际行为 |
|---|---|
| Never Retrieve | 禁止外部检索；若教材已有图片，可作 `reuse`，所以并不等于永远 `none`。 |
| Always Retrieve | 每条命题都提出 retrieve；实际候选仍须通过相同的本地检索分数门槛。 |
| Keyword Heuristic | 使用本轮冻结的英文关键词词表；原有默认中文词表保持不变。 |
| Direct LLM | 在同一允许输入上直接选择动作，不读取 Proposed 输出/理由，也不执行 Proposed 的分阶段判断步骤。 |
| Proposed | 使用来源条件输入，并显式要求视觉必要性、原来源充分性、检索适用性和不确定性处理。 |
| no-source | 移除模型可见的来源文本、引用、图注及来源图像条件；共享检索候选池仍保留。此项测试来源信息整体作用，不能单独归因于来源充分性模块。 |
| without-source-sufficiency | 保留来源输入，移除 `source_sufficiency` 输出字段/判断。 |
| without-retrieval-suitability | 保留来源输入，移除 `retrieval_suitability` 输出字段/判断。 |
| without-uncertainty-handling | 移除研究决策层的不确定/abstain 输出要求；来源、许可、Hash、候选校验仍照常执行。 |

Direct LLM、Proposed 与四个消融在比较集共 6×12=72 次真实请求；确定性 Baseline 不消耗模型调用。开发集额外运行 Direct LLM 和 Proposed 各 4 条。`generate` 只作为决策动作返回；`generation_enabled=false`，没有调用图片生成器。

本轮涉及的工程文件为 `src/textbook2video/research/visual_decision.py`（显式研究条件，普通默认路径不变）、`visual_decision_baselines.py`（可选冻结英文词表，中文默认不变）、`rq1_preference_judge.py`（匿名排序与严格结构校验）、`rq1_controlled_evaluation.py`（离线统计）及 `scripts/run_rq1_new_corpus.py`（冻结输入、调用账本、断点恢复、verify/analyze-only）；配置和定向测试分别在 `configs/research/rq1_new_corpus_dev_v1.json` 与 `tests/test_rq1_new_corpus_runner.py`、`test_rq1_controlled_evaluation.py`、`test_visual_decision_baselines.py`。工作树还包含既有 Phase 1/RQ1 未提交变更；运行包保存了相关快照和差异，不能把整个脏工作树都归因于本轮。旧 router 本轮未运行，旧四条开发样本也没有放入新统计。

## 4. 匿名 Judge 代理评价

每个比较命题将 9 个匿名动作提议交给 `ecnu-plus` 与 `ecnu-max`，正序/反序各评价一次。Prompt 不包含方法名、方法理由、旧 Judge 结果或 Gold；模型只看到匿名选项 ID。Judge 独立评 6 个 1–5 维度：视觉必要性、来源充分性、动作合理性、来源忠实度、冗余/装饰风险、不确定性处理。

**评价表述细节未充分标准化，是本轮 Judge 比较的协议限制。** 提议外层字段相同，但 `retrieval_query`、`acceptance_criteria`、`generation_request` 保留了各方法原始输出；同一命题中有的 retrieve 提议只有查询词，有的包含多条验收标准，Always Retrieve 也可能没有标准。这会让提议详略差异影响 Judge。相关原始输入可在 `run-01/prompts/` 中核对。由于比较输入已冻结，本轮没有根据输出修改 Judge Prompt 或重复请求；因此 Judge 结果仅作探索性代理证据，不能称为完全控制了提议详略的公平偏好实验。后续若继续使用 Judge，必须在新样本上预先冻结统一表述模板与每种动作可见字段。
