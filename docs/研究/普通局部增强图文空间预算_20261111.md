## 默认行为

普通局部增强页面有正文或其他教学组件时，默认使用现有 classic 左图右文布局；视觉栏约占扣除间距后可用宽度的53.5%。不再因为正文较短就默认给解释图整页宽度，也不在容量失败后自动切成整页图。

多张视觉在同一视觉栏内纵向组合；组宽和每张图片均检查预算。放不下时明确返回 `adjust_or_split_required`，不截断文字、删除组件、无限缩小字体或改变事件目标。明确指定 `local_visual_layout=full_stack` 的海报/整图页仍可使用旧布局，图片独占页及非局部增强旧模式保留。

预算不是固定684×401：通过真实浏览器测量标题以下内容区和响应式间距，计算两视口的视觉栏宽高；生成前采用较保守的共同预算。CSS 小视口原有14px间距与默认46px现在通过 CSS 变量实际读取，避免预算与布局不一致造成误拒。

## 实际调用关系

`course_visuals._measure_generation_capacity()` → `measure_generation_capacity()` → 现有 `page_capacity.visual_slot` 随请求传入 `run_visual_agent()`。预算包含显示宽高与最小10px文字要求，提示规划应适合与正文共同呈现，不能只适合整页预览。没有增加响应字段；放不下由页面预检报告，不要求模型编造拆页协议。

生成后仍走 `compose_local_visual()` → `select_local_page_layout()` → Template Renderer → 双视口浏览器检查。检查视觉栏总宽、单图宽高、实际显示的 SVG 字号、内容和溢出。源图中的22px文字缩到页面后若不足10px，继续拒绝。失败的布局诊断保留到既有输出位置，原页面修改仍原子提交。

## 修改文件

- `pipeline/visual_page_render.py`：生成前视觉栏预算、候选预算检查、限制混排失败回退；增加 SVG 实际显示尺寸与视觉组测量。
- `template_renderer.py`：局部增强有正文时自动选择 classic，保留显式布局选择。
- `variants/layouts.py`：共享预算比例与间距；显式 classic 将多图放在视觉栏内。
- `templates/base.css`：响应式图文间距通过共享 CSS 变量暴露给测量。
- `pipeline/course_visuals.py`：容量失败时保留顶层布局诊断，不改变来源、审批或页面提交门禁。
- 定向测试：`test_local_visual_composition.py`、`test_visual_tools.py`，覆盖多图标注和事件、失败回滚、实际字号、保留显式整图模式、预算到规划请求及缓存绑定。

## 尚未证明的部分

本轮证明预算、默认混排和拒绝机制已接通，**没有进行新的真实模型生成**，不能保证模型一定能按预算规划出合格小图。也未实现自动将任意现有SVG中的节点说明迁移到正文，或自动重写密集拓扑为紧凑图。此前手工紧凑S2示例仍是手工呈现调整。

遇到复杂图仍可能需要新的合理规划、明确调整或拆页。本轮不修改语义绑定、G0、来源/角色门禁、TTS与媒体链，不升级S2语义或视频验收状态。修改保留在工作树，未提交、未推送，其他已有修改保留。
