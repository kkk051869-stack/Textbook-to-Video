## 如何使用缓存和恢复

在仓库根目录使用 `.venv/Scripts/python.exe`。普通 `produce` CLI默认使用 `.local/visual-cache`；Python预览和PowerShell启动器也使用本地共享缓存。程序API调用方需要显式传 `cache_dir` / `visual_cache_dir`，正式P0/研究入口不自动读取开发缓存。

- `produce --visual-cache-dir <目录>`：指定缓存；`--no-visual-cache`禁用。
- Python预览同样支持 `--visual-cache-dir` / `--no-visual-cache`。
- PowerShell启动器使用 `-VisualCacheDir <目录>` / `-NoVisualCache`。
- `produce --visual-review-model ecnu-max --visual-review-policy strict`：开发增强验收的明确审核配置；不默默切换模型，也不使用旧页降级冒充增强。

缓存绑定教材原文、目标、完整旁白、页面上下文和源图、规划/审核模型、实际生效endpoint、主题、生成许可、审核策略、代码/主题/模板和运行库版本。密钥不进入绑定或索引。不同代码/策略/输入产生MISS，不能为了复用放宽绑定。代码hash是保守的整个包指纹，纯文档修改不影响缓存。

命中前重新检查完整run、revision、审核结果、截图、资产及恢复父链；draft只可在development同策略复用，不能升级为strict。失败结果可以作为恢复起点，但不登记为可用增强资产。缓存索引使用原子发布的新记录，不覆盖旧运行。

| 失败阶段 | 下次同配置的新运行如何处理 |
| --- | --- |
| 请求尚未得到规划响应 | 重试规划请求；先前成功页仍直接命中 |
| 来源/结构/组合/布局校验 | 把原候选和明确错误交给局部编辑；不原样重试无效组合 |
| 某张图片API失败 | 复用同spec/model且hash正确的已生成图，仅重试失败图；不重新规划 |
| 浏览器渲染失败 | 复用已编译资产，仅重渲染；失败再次发生也保存可继续恢复的检查点 |
| 审核传输或协议失败 | 复用已验证截图，在新目录重试审核；同像素既有否决/负面检查/有效低分不能被后续协议响应抹掉 |
| 审核要求内容修改 | 进入带反馈的局部编辑；不靠对同图反复审核刷出ACCEPT |
| 绑定漂移、资产/截图/父链损坏 | 不复用、不能静默降级绕过；保留错误供修复 |

缓存索引引用保留的原运行和资产，当前只承诺同机跨运行，不承诺跨机器搬迁。不要删除被引用的旧运行。整个原run不存在时记录MISS；部分证据损坏则硬停止。Git推送不含缓存、图片、音频或视频；交给同学时需要另行共享实际运行包。
