# 通用教学视觉生成系统

## 目标与边界

该系统把教学视觉的规划与绘制解耦。规划器（包括 AI）只提交可审计的 `VisualSpec`；编译器按视觉意图选择确定性 SVG 或 `ecnu-image`，并输出带输入、来源、哈希和状态的 manifest。它不是 `lesson_002` 专用功能；课例只用于端到端验证。

确定性图形覆盖：流程、层级/树、网络、时间线、循环、比较、因果、部分—整体、比例/柱状图、表格、公式与代码。场景、物体、人物、历史、照片和纹理才走 `ecnu-image`。外部素材检索与素材库尚未接入。

## AI 如何调用与修改

AI 调用下面的 JSON 命令接口，而不是直接手写 SVG：

```powershell
.\.venv\Scripts\python.exe -m textbook2video.research.visual_synthesis `
  --specs .local\visual-specs.json `
  --output-dir .local\visual-revisions\r001
```

`visual-specs.json` 可以是数组，或包含 `visuals` 数组的对象：

```json
{
  "visuals": [
    {
      "id": "consensus-flow",
      "kind": "flow",
      "title": "共识步骤",
      "items": ["提议", "验证", "确认"]
    },
    {
      "id": "lab-scene",
      "kind": "scene",
      "description": "明亮的教学实验室，留出右侧字幕安全区"
    }
  ]
}
```

命令向标准输出返回机器可读 JSON，并写入 `visual_assets.json`。结构图会得到 `DETERMINISTIC_SVG`；图像生成物先标记为 `GENERATED_PENDING_REVIEW`，未经审核不得自动进入 P0 成片。

若图的关系、文案、布局或风格不正确，AI 应提交修改后的 spec 到新的输出目录，并携带原 manifest：

```powershell
.\.venv\Scripts\python.exe -m textbook2video.research.visual_synthesis `
  --specs .local\visual-specs-r002.json `
  --output-dir .local\visual-revisions\r002 `
  --revision-of .local\visual-revisions\r001\visual_assets.json
```

已有 `visual_assets.json` 的目录会拒绝写入，因此旧 SVG、图像和哈希不会被覆盖；新 manifest 通过 `revision_of` 保留谱系。

## 正式 P0 接入

`produce --p0-research` 已接入此编译器。正式运行同时提供视觉 spec、绑定和明确的 P0 事件计划：

```powershell
t2v produce <教材或占位输入> --from-storyboard <baseline_storyboard.json> --output .local\p0-run `
  --p0-research --p0-plan <p0_plan.json> `
  --p0-visual-specs <visual_specs.json> `
  --p0-visual-bindings <visual_bindings.json>
```

bindings 是数组或 `{ "bindings": [...] }`，每项至少包含 `asset_id`、`proposition_id`、`segment_id` 和新的 `element_id`。显式 P0 plan 必须把对应命题绑定到该 `element_id`；这样不会由系统猜测新图应服务哪条命题。编译产物、绑定和哈希会写进 P0 sidecar。生成图像仍必须先审核；未审核的 `ecnu-image` 产物会 fail closed。

默认的自动路径不需要手写上述三份 JSON：

```powershell
t2v produce <教材或占位输入> --from-storyboard <baseline_storyboard.json> --output .local\p0-run --p0-research --p0-auto-visuals
```

它会在已有命题图与视觉决策之后，让教学视觉规划 AI 输出 VisualSpec，并由确定性代码自动生成 bindings 与 P0 事件计划；三份中间产物都会落盘供复核。自动路径与手写 `--p0-plan/--p0-visual-*` 互斥，避免混用两个版本的计划。结构图可以继续到候选 storyboard；自动生成的场景图仍必须经过图像审核，不能静默进入视频。

## 与 storyboard/P0 的关系

`prepare_p0_candidate` 可接收编译产物 manifest 与 element 绑定，把已验证的 SVG（或已审核的 `ecnu-image` 资产）复制到候选 storyboard 的 images 目录，并记录 `asset_id`、哈希和命题 ID。AI 的职责是提出并修订事实结构，编译器的职责是稳定执行，P0 验证和人工视频复核仍负责决定是否可用于最终视频。

生成图像默认启用 `ecnu-image`，但“生成成功”不等于“内容正确”；涉及事实、标注、版权或画面质量的问题必须审核后才可绑定。教材图复用仍受“每张最多一次”的既有约束。

## SVG 布局契约

确定性 SVG 与生产模板共同遵守以下通用契约，不能为某一课硬编码坐标补丁：

1. SVG `viewBox` 按实际图形边界加安全留白生成，不再固定使用 `1280×720` 空画布；长流程仍按节点数扩展横向边界，不能裁掉末节点。
2. `VisualSpec.title` 只写入 SVG 的无障碍 `<title>`，不再绘制成图内可见标题。页面标题由 storyboard 的 heading 唯一负责，避免重复标题和垂直空间浪费。
3. 含图片的内容页标记 `t2v-has-visual`，图片高度按可用视口自适应；图片与 comparison/table/flow/activity 等宽元素同页时，额外标记 `t2v-visual-with-wide`。
4. `t2v-visual-with-wide` 在 1920×1080 和 1366×768 分别使用不同的视觉高度、间距和内边距预算；窄屏允许对完整内容组做有限上移，但不能让图形与标题相撞。
5. 单页 `--only` 结果不能证明整片通过。修改布局后必须对完整 storyboard 运行双视口 layout QA，并从完整 MP4 抽取各页代表帧和关键动画事件前后帧进行人工可见性检查。
