## 代码与验证

执行器从最新截图审核意见及已验证的父候选解析单个 node/edge 的真实选择器。模型只能返回一条 `updates`，且只含该对象的 `label`；程序核对父候选 hash、选择器和字段后才应用。多项更新、结构字段、`changes`、全量替换、删除或错误选择器均拒绝，失败时保留原候选、审核 revision/hash 和明确的错误位置。审核提到标签但对象不唯一时，停止为 `STOPPED_REPAIR_TARGET_UNRESOLVED`，不猜目标。未受局部标签审核约束的结构任务仍可走原有独立接口；agent 的局部许可不会升级成广泛编辑权限。

独立只读复核发现：直接调底层 `dispatch("revise")` 曾能不传许可而绕过已审核的标签范围。已补从已验证父版本与失败父链自动恢复最近截图审核，底层执行器也据此拒绝越界修改；相应反例覆盖普通父版本、失败父版本、`changes` 和整份替换。独立复核再次确认该旁路已关闭。复核最初提出“单图不填 `narration_span` 可能丢旁白”，经课程接线核对撤回：单图直接沿用原 `segment["narration"]`，多图必须逐段拼回全文；没有把该提醒写成真实内容丢失。

截图审核明确存在 `factual_error`、`missing_content`、`irrelevant_content` 或事实/相关/完整性检查失败时，修订请求改为明确的完整候选替换。此通道拒绝把 `visuals` 与 `updates`/`changes` 混用；替换后照常重新过原文引用、完整旁白、节点/边、页面覆盖、浏览器几何和图片审核。它不自动修正模型的事实或替模型挑图型。

新增通用反例覆盖普通图/relationship 的单标签权限、附带图型或来源修改、错误目标、混合补丁、父候选不变、失败后审核反馈延续、语义问题走结构替换，以及目标不明确时停机。最终全量回归 **974 passed**，触碰文件 Ruff 与 `git diff --check` 通过；这仍只证明工程测试，不证明整课效果。

当前机器 FFmpeg 9.0.2 已移除 `-vsync`；最终帧提取改用 `-fps_mode passthrough`，取证相关 15 项测试通过。首次全量测试因进程 PATH 没有 `ffprobe` 出现 3 个环境失败，补齐 PATH 后同版全量为 `973 passed`；后续结构替换代码另需最终全量复验，不能沿用该数字冒充新版结果。
