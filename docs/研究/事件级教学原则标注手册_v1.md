# 事件级教学原则标注手册 v1

## 1. 目的与基本规则

本手册用于 Pilot v1 的双人独立人工标注。标注者判断的是教材教学视频中的教学原则问题，不是视频是否“好看”，也不是 JSON 是否技术正确。

必须遵守：

1. `machine_observations.json`、candidate boundary、candidate KP/source link 都只是机器候选，不是答案；
2. 不因 element、event 或 target 存在就判定教学正确；
3. 不因 `target_missing` 就自动判定教学违规；
4. Temporal 判断最终以学习者在 MP4 中看到的呈现为准；
5. 不确定时使用 `UNCERTAIN` 或 `UNOBSERVABLE`，不得猜测；
6. A、B 在首轮完成前不得查看对方文件；
7. 不使用 LLM/VLM 代替人工填写 label。

## 2. 固定标注顺序

必须按以下顺序标注：

1. 阅读教材 source 与 knowledge point 候选；
2. 划分 narration proposition；
3. 判断 proposition 的 Visual Necessity；
4. 判断当前 visual 的 Visual Correctness；
5. 只有视觉语义正确或“缺少应有视觉”时，判断 Temporal Contiguity；
6. 判断 Signaling 是否适用；
7. 若适用，判断 cue target、时机与 overload；
8. 填写 confidence、notes 和 uncertainty reason。

该顺序避免把本身错误的视觉再次标成“时间正确”。

## 3. Narration Proposition

### 3.1 定义

Proposition 是旁白中能够独立判断真伪、教学功能或视觉需求的最小完整语义命题。它可以是定义、因果关系、比较、过程步骤、事实陈述、例子与概念的关系，或明确的教学指令。

### 3.2 不是什么

- 不是机械按标点切开的所有句子；
- 不是任意长度相等的字幕块；
- 不是只含连接词、语气词或无独立语义的从句；
- 不是整页 narration 的默认同义词；
- 不是 visual element 的文本复写。

### 3.3 划分原则

- 一个句子表达两个可独立判断的关系时可 `SPLIT`；
- 相邻短句共同构成一个不可分割的定义/因果关系时可 `MERGED`；
- candidate 与最终命题一致时用 `ACCEPT_CANDIDATE`；
- 只修改边界或文本范围时用 `EDITED`；
- proposition text 必须来自 narration，不添加旁白没有说出的结论。

### 3.4 边界状态

| 标签 | 定义 | 判断条件 | 边界情况 | 易混淆项 |
|---|---|---|---|---|
| ACCEPT_CANDIDATE | 接受机器候选边界 | 候选已是完整、单一命题 | 标点不同但范围相同仍可接受 | 不等于接受候选 KP/source binding |
| EDITED | 调整候选起止或文本 | 候选基本正确但含多余/缺失片段 | 小幅去除语气词也可 EDITED | 与 SPLIT/MERGED 区分：命题数量未变 |
| MERGED | 合并两个或更多候选 | 单独候选不构成完整教学含义 | 并列事实若可独立判断，不合并 | 不要因视觉共用而强行合并 |
| SPLIT | 一个候选拆成多个命题 | 含多个可独立判断的关系 | 同一主语的多个独立结论可拆 | 不要按字数机械拆分 |

### 3.5 时间边界

`narration_start/end` 是命题在本 segment 内的时间窗口。candidate time 可作起点，但最终由人工根据旁白和字幕校正。无法精确到词时，可保留到 0.1–0.5 秒精度，并在 notes 说明。

## 4. Visual Necessity

### REQUIRED

- 定义：缺少视觉会使关系、结构、过程、空间对象、数量模式或比较难以有效表达；
- 条件：旁白本身不足以清楚建立关键心理模型，视觉是完成教学功能的必要支持；
- 边界：不是因为视频媒介“应该有画面”就 REQUIRED；
- 易混淆：与 HELPFUL 的区别在于缺少视觉是否显著损害理解，而不只是降低吸引力。

### HELPFUL

- 定义：纯旁白仍可理解，但解释性视觉能明显降低理解成本或增强结构化；
- 条件：视觉提供组织、例示、对比或记忆线索；
- 边界：仅增加装饰感不算 HELPFUL；
- 易混淆：视觉存在不自动意味着 HELPFUL。

### NOT_NEEDED

- 定义：命题可由简短语言充分表达，不需要额外解释性视觉；
- 条件：视觉不会增加关键教学信息或结构；
- 边界：标题、过渡语、礼貌性开场常可能属于该类，但要逐项判断；
- 易混淆：NOT_NEEDED 不等于当前视觉必然 irrelevant，需要在 Visual Correctness 中另判。

### UNCERTAIN

- 定义：source、命题边界或教学功能不足以稳定判断；
- 条件：多种合理教学设计均成立，标注者无法确定；
- 边界：不得用 UNCERTAIN 代替没有认真查看材料；
- 必填：`uncertainty_reason`。

## 5. Visual Correctness

对 REQUIRED/HELPFUL proposition，以及实际存在视觉的 proposition，判断 visual 与命题的关系。主题相关不等于正确解释。

### CORRECT_EXPLANATORY

- 定义：视觉直接表达命题中的结构、关系、过程、比较或对象；
- 条件：学习者可从视觉获得旁白关键关系的可视化解释；
- 边界：文字原样搬到卡片通常不足以成为 explanatory；
- 易混淆：与 CORRECT_SUPPORTIVE 的区别是视觉是否承担核心解释。

### CORRECT_SUPPORTIVE

- 定义：视觉不独立解释全部命题，但提供正确例子、情境、组织或记忆支持；
- 条件：与 source 和当前命题一致，且具有教学辅助价值；
- 边界：泛主题图片若不帮助当前命题，可能是 DECORATIVE；
- 易混淆：supportive 不是“只要相关就正确”。

### DECORATIVE

- 定义：视觉主要用于美化、填充或营造主题气氛，不承担当前命题的解释；
- 条件：移除后教学含义基本不变；
- 边界：装饰不必然构成 violation，需结合 Coherence 和注意竞争判断；
- 易混淆：不要把简洁但有效的示意图误判为装饰。

### IRRELEVANT

- 定义：视觉与当前命题或教学目标没有实质关系；
- 条件：不能由 source/KP 解释其教学用途；
- 边界：同一 lesson 主题相关但与当前 proposition 无关，仍可 irrelevant；
- 易混淆：DECORATIVE 可主题相关，IRRELEVANT 连当前教学支持也缺失。

### SEMANTIC_MISMATCH

- 定义：视觉看似相关，但表达了与命题不同、错误或相冲突的语义；
- 条件：对象、关系、方向、阶段、类别或数值与 source-supported proposition 不一致；
- 边界：视觉过于抽象而无法确认时可 UNCERTAIN，不强判 mismatch；
- 易混淆：IRRELEVANT 是无实质关系，MISMATCH 是存在错误对应关系。

### MISSING

- 定义：proposition 被标为 REQUIRED/HELPFUL，但没有可承担该功能的视觉；
- 条件：实际画面不存在相应 element，或技术缺失导致学习者看不到；
- 边界：HELPFUL 缺失是否构成 violation需在 severity/notes 说明；
- 易混淆：若视觉存在但错误，应标 SEMANTIC_MISMATCH 而非 MISSING。

### UNCERTAIN

- 定义：无法从 source、画面或命题确定 visual relation；
- 必填：原因，例如 multiple acceptable visuals、source insufficient 或 renderer artifact。

## 6. Temporal Contiguity

### 前置条件

只有以下情况才进行 Temporal 判断：

- 当前 visual 为 CORRECT_EXPLANATORY/CORRECT_SUPPORTIVE；或
- proposition 需要视觉但视觉实际 MISSING；或
- 视觉语义疑似不匹配，需要用 `SEMANTIC_MISMATCH` 终止 timing 判断。

标注者必须同时查看 proposition 时间、plan、runtime（若有）和 final MP4。最终标签以 MP4 呈现为准；JSON 只作证据。

### CORRECT

- 定义：正确视觉在命题讲解的合理窗口内出现，并保持到足以理解；
- 条件：不会明显提前泄露或延迟到讲解之后；
- 边界：允许短暂 lead，只要不造成语义脱节；
- 易混淆：plan 正确而 MP4 不正确时仍不能标 CORRECT。

### EARLY

- 定义：正确视觉在相关 proposition 的可接受窗口之前过早出现；
- 条件：提前呈现造成注意转移、答案泄露或与当时旁白不对应；
- 边界：为建立页面上下文而合理预显不一定 EARLY；
- 易混淆：仅“比旁白早 0.5 秒”不自动 EARLY，需结合可接受窗口。

### LATE

- 定义：正确视觉在相关解释开始后过晚出现，或在命题结束后才出现；
- 条件：学习者在关键讲解阶段无法看到必要对象；
- 边界：动画渐显需要的自然过渡时间不必判 LATE；
- 易混淆：视觉从未出现应标 MISSING_VISUAL。

### MISSING_VISUAL

- 定义：需要视觉的 proposition 在学习者可见视频中没有有效视觉；
- 条件：Visual Necessity 为 REQUIRED/HELPFUL，且 relation 为 MISSING；
- 边界：技术 `target_missing` 只有实际造成所需视觉不可见时才支持该标签；
- 易混淆：存在但错误的视觉是 SEMANTIC_MISMATCH。

### SEMANTIC_MISMATCH

- 定义：无法评价正确视觉的时间，因为当前视觉语义本身错误；
- 条件：Visual Correctness 已判 SEMANTIC_MISMATCH；
- 边界：该标签用于保持错误归因，不表示 timing 本身已判断；
- 易混淆：不要同时再给 EARLY/LATE。

### NOT_APPLICABLE

- 定义：该 proposition 不需要视觉，或没有可评价的视觉时间关系；
- 条件：Visual Necessity 为 NOT_NEEDED，且不存在需要时序评价的 cue；
- 边界：有视觉不代表 temporal 自动适用；
- 易混淆：证据不足用 UNCERTAIN，不用 NOT_APPLICABLE。

### UNCERTAIN / UNOBSERVABLE

- `UNCERTAIN`：教学上无法稳定确定 early/late/correct；
- `visibility_status=UNOBSERVABLE`：MP4 中无法可靠判断出现/消失时刻，例如渐变、遮挡、对象始终存在或 frame evidence 不足；
- 必填：`uncertainty_reason`。

### 时间字段

- `acceptable_start_min/max`：人工认为不构成 early/late 的本 segment 局部时间范围；
- `observed_visible_start/end`：从最终 MP4 人工观察所得；
- 若 end 无法确定，可只填 start，并把 status 标为 UNOBSERVABLE/partial note；
- 不得把 `trigger_at_sec` 直接复制为 observed visible start。

## 7. Signaling

Signaling 包括 highlight、pulse、focus、dim、arrow、颜色变化或其他明确引导注意的 cue。普通 `show` 入场不自动视为 signaling；如果其教学功能确实是突出对象，可在 notes 说明。

### signal_applicability

#### REQUIRED

- 多对象并存、关系复杂或当前目标容易混淆，不提示将显著妨碍定位；
- 不是因为系统支持高亮就判 REQUIRED。

#### HELPFUL

- 无 cue 仍可理解，但提示能明显降低搜索成本；
- 不把纯美化动画算作有帮助的 signal。

#### NOT_NEEDED

- 当前对象唯一、已足够突出或命题不需要注意引导；
- 不因没有 signaling action 就自动判该类。

#### UNCERTAIN

- 对象/命题/画面不足以稳定判断，必须记录原因。

### signal_label

#### CORRECT

- cue 在相关时间指向当前正确对象，强度与频率适当；
- cue target 技术存在不等于教学 target 正确。

#### MISSING_SIGNAL

- applicability 为 REQUIRED/HELPFUL，但没有有效 cue；
- HELPFUL 的缺失是否构成严重违规需在 reason/severity 中谨慎说明。

#### WRONG_TARGET

- cue 存在但指向非当前 proposition 的对象，或 target 对象语义错误；
- 技术 target missing 可作为证据，但必须确认学习者实际未获得正确提示。

#### SIGNAL_OVERLOAD

- cue 过多、过密、同时竞争，或对不需要强调的对象反复提示；
- 不能只按数量阈值自动判断，需观察注意竞争和教学必要性；
- 多个 cue 服务同一复杂关系可能仍合理。

#### NOT_APPLICABLE

- signal_applicability 为 NOT_NEEDED；
- 不要用它代替“没看清”。

#### UNCERTAIN

- 无法确认 cue 类型、target 或必要性；必须填写原因。

## 8. Uncertainty / Abstention

可用 `uncertainty_reason`：

- `source insufficient`；
- `ambiguous proposition`；
- `multiple acceptable visuals`；
- `target ambiguous`；
- `visibility unobservable`；
- `principle not applicable`；
- `renderer artifact`；
- `other`，并在 notes 解释。

UNCERTAIN 是有效研究结果，不是标注失败。不得为了后续计算 F1 强制给出确定标签。

## 9. 技术错误与教学违规的区分

| 观察 | 可以自动确认 | 仍需人工判断 |
|---|---|---|
| target missing | runtime 没找到 DOM target | 该对象是否教学必要、是否导致 MISSING_VISUAL/WRONG_TARGET |
| runtime delay | actual start 与 planned start 的差 | 是否超出教学可接受窗口 |
| element 多/动画多 | 数量和密度 | 是否 irrelevant、redundant 或 overload |
| source image 未使用 | 资产使用事实 | 是否本命题真正需要该图 |
| trigger 很早 | planned time | 学习者看到时是否构成 EARLY |

## 10. 待标例子使用方式

Pilot package 中的真实 narration、visual、trace、帧与 MP4 都是“待标例子”。手册不提供这些案例的正确答案。讨论例子时必须在双人首轮完成后进行，避免形成共享答案。

## 11. 完成检查

每个最终 proposition 至少检查：

- proposition ID/text/time/boundary status；
- KP/source binding 是否人工确认或明确 uncertain；
- Visual Necessity；
- Visual Correctness 与 element IDs；
- Temporal label、窗口和 visibility status；
- signal applicability/label/target；
- confidence、notes、uncertainty reason。

完成单个 case 后，将 `annotation_status` 从 `NOT_STARTED` 改为 `COMPLETED`。不要编辑另一位标注者的文件。
