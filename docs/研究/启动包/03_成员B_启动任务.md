# 成员 B：Dynamic Alignment & Evaluation Track 启动任务

## 目标

回答三个问题：

1. narration proposition 应绑定哪个 visual element；
2. 对该对象执行什么 visual event，并在何时执行；
3. plan、runtime 和 final video 是否一致。

## 输入

- `script_v2.json` 的 narration proposition、span 和 knowledge proposition links；
- `storyboard.json` 的固定 mock elements；
- `storyboard_timed.json`、compiled timeline 与现有 `animation-trace-v0.1`；
- A 后续输出的 visual decision/candidate bundle。

## 写入字段

- `script_v2.segments[].narration_propositions[]`；
- `storyboard.segments[].events[]`；
- `storyboard_timed.segments[].scheduled_events[]`；
- `compiled_timeline.segments[].events[]`；
- `render_evidence.observations[]`；
- binding、timing、signaling 和 evaluator 结果。

不得把 `trigger_at_sec`、`start_ms` 或 runtime `actual.start_ms` 写成 final-video visibility。

## 第一批本地任务

1. 读取 G0 mock 并校验所有跨文件引用；
2. 实现 lexical/Jaccard binding baseline；
3. 建立 narration proposition→element→event 的结果格式；
4. 复用现有 timing/compiled trace，分别计算 planned/runtime 差异；
5. 读取 `render_evidence.json`，计算 onset error、window overlap、missing/wrong-target；
6. 在 3–5 文档 dry run 中记录不可观测字段和 renderer ID 断链。

## 什么时候需要大模型

本地即可完成：lexical baseline、规则 timing、事件执行、Playwright trace、人工/帧采样证据、指标和统计。  
可能使用本地 embedding：embedding binding baseline。  
需要 LLM/VLM：Direct LLM/VLM binding、proposed semantic binding（若采用模型）、Direct VLM judge。  

模型尚未接入前，使用 mock elements 和固定 prediction 开发，不等待 A。

## 完成标准

- 每个 event target 都能解析到真实 element；
- 每个 binding 都引用 narration proposition；
- planned、compiled、runtime、rendered 四层指标分开；
- mock 和本地 baseline 不调用外部模型；
- 不依赖 A 的真实实现；
- 能直接消费 A 的标准 result bundle。
