# 成员 A：Visual Decision Track 启动任务

## 目标

回答两个问题：

1. 一个 knowledge proposition 是否需要视觉支持；
2. 需要视觉时，应 `reuse / retrieve / generation-candidate` 中的哪一种。

P0 不建设通用 RAG，不把图像生成模型本身作为创新。

## 输入

- `source_units.json`；
- `lesson_plan.json` 中的 knowledge point、knowledge proposition、source refs；
- 教材图片及受控外部候选池；
- G0 mock 中 B 提供的固定下游结构。

## 写入字段

- `lesson_plan.knowledge_points[].propositions[].visual_support`；
- `storyboard.segments[].elements[]` 的 source、acquisition、semantic role 和 proposition 引用；
- 独立实验结果中的 prediction、confidence、abstention 和 cost。

不得修改已冻结的 case/source/KP/proposition/segment/element/event ID。

## 第一批本地任务

1. 读取 `mock_v0.1/package_manifest.json`；
2. 正确识别 mock 中 `reuse` 与 `retrieve` 两个分支；
3. 建立 Never Retrieve、Always Retrieve 和 keyword heuristic；
4. 输出与 schema 一致的 visual-support decision；
5. 对 5–10 proposition 做非正式试填，记录难例，不计算正式 agreement；
6. 为 3–5 文档 dry run 生成版本化预测和候选视觉包。

## 什么时候需要大模型

本地即可完成：读取/校验、规则 baseline、候选池、成本统计、结果导出。  
需要 LLM：Direct LLM baseline 和 proposed visual-need/retrieval decision。  
可能需要 embedding/VLM：候选视觉语义排序。  
P1 才需要图像生成模型。

模型尚未接入前，不要阻塞代码：使用 mock prediction 或固定 fixture。

## 最小交付

```text
result_bundle/
├─ run_manifest.json
├─ visual_decision_predictions.json
├─ candidate_pool_manifest.json
├─ metrics.json
├─ failures.json
└─ README.md
```

每个 prediction 至少包含：case ID、knowledge proposition ID、label、acquisition、producer/model version、confidence、abstain reason、input hash。

## 完成标准

- mock 全部通过 schema；
- baseline 输出可重复；
- 不依赖 B 的真实实现；
- 不把 source-sufficient 与 retrieve 混为一类；
- 未调用模型时不伪装成模型结果；
- 结果包可以由 B 只读消费。
