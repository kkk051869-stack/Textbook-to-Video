# 共同环境与工作规则

## 1. 包内结构

```text
Textbook-to-Video-Research-G0-Starter-20261005/
├─ START_HERE.md
├─ PACKAGE_MANIFEST.json
├─ CHECKSUMS.sha256
├─ repository/Textbook-to-Video/       # 可直接工作的 Git 仓库
└─ original-history.bundle             # 原仓库历史的额外离线备份
```

项目仓库内：

```text
contracts/                              # JSON Schema
datasets/pilot3/                        # 已有冻结/候选教材与生成产物
datasets/research_event_alignment/      # Pilot v1 标注与时间证据包
datasets/research_generation_v2/        # G0 mock、后续 dry run 与实验目录
docs/研究/                               # 研究报告、协议和启动说明
src/textbook2video/research/             # 已有研究导出/一致性工具
tests/                                  # 本地确定性测试
```

## 2. 安全规则

- 包内不含 `.env`；每个人从自己的安全渠道获得 API key。
- 不在聊天、日志、截图、commit 或实验 bundle 中写入密钥。
- `.env.cloud.example` 只包含非秘密配置示例。
- 不把 `.local/`、模型权重、虚拟环境、缓存或临时输出提交进仓库。

## 3. Git 分工

启动仓库默认位于 `codex/g0-starter`。建议两个人各自创建分支：

```powershell
git switch -c research/visual-decision-a
# 另一份克隆中：git switch -c research/alignment-eval-b
```

不要两个人共用同一个工作目录。每个人从启动包复制或克隆出自己的工作副本。

禁止直接覆盖 frozen 数据。所有 dry run 写到：

```text
datasets/research_generation_v2/dry_run/<run_id>/cases/<case_id>/
```

`run_id` 使用 `<YYYYMMDD>-<short_commit>-<config_slug>`。

## 4. 模型调用规则

本地阶段全部使用 mock 或确定性 baseline。需要 LLM/VLM 时：

1. 先在 1 个 case 上验证输入输出；
2. 固定 provider、model、Prompt version、temperature、seed（如支持）；
3. 保存原始响应和解析后结果；
4. 对相同 input hash 使用缓存，不重复付费调用；
5. 模型失败必须留下显式状态，不能悄悄回退后仍标记成功。

TTS 和 LLM 是不同依赖。`edge-tts` 可能需要网络，但不属于大模型调用。

## 5. 共同验收命令

```powershell
python -m pytest tests/test_research_generation_contract.py tests/test_research_pilot.py -q
python -m pytest tests/test_lesson_plan.py tests/test_scriptwriter.py tests/test_storyboard.py tests/test_timing.py -q
```

生成/渲染相关工作再运行：

```powershell
t2v doctor
python -m pytest tests/test_template_renderer.py tests/test_record_timing.py -q
```

## 6. 唯一合并规则

- G0：字段、ID、目录和 mock 已冻结；
- G1：只冻结 dry run 后的正式标注协议和 gold；
- G2：合并标准 result bundles；
- 接口不兼容时发布新 schema 版本和 migration，不原地改 v0.1；
- 每条分支提交自己的输出，不等待对方实现；通过 manifest 和 mock 交接。
