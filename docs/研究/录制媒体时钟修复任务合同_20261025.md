# 录制媒体时钟修复任务合同

目标：排除页面加载及浏览器关闭时间对成片时间轴的污染；以统一起点驱动第一页动画和绝对截止时间翻页。禁止整体拉伸视频或盲截尾部伪装同步。

输入：43fc648；仓库 Python3.12 虚拟环境；旧三页探针请求6秒、输出8.2秒，第二/三页约2.7/4.7秒出现。

允许修改：recorder、独立录制时钟辅助模块、slide-controller、相关测试、诊断脚本与交接文档。禁止修改冻结输入、gold、旧r36等运行、研究指标或结论。

方案：现代模板先延迟播放，待资源就绪后用像素校准片头/片尾标记包围真实播放；从实际视频检测两端标记，验证媒体区间长度后仅删除校准段。翻页按累计绝对时刻调度。不存在标记、区间时长异常或控制器不支持时不得冒充已校准。保留原始录制供排错。

验收：无LLM的真实浏览器三页短片，解码MP4核对页色及元素出现时刻；增加加载延迟与运行中短暂停顿反例；开发预检、定向/全量回归、独立只读复核。工程通过不等于r36或真实整课通过。

停止条件：实际视频证据不能支撑校准、旧HTML缺少统一启动接口或运行资源缺失时，保留失败结果并明确状态，不猜测时间缩放比例。不跑完整增强或服务器实验。

## 实现结果与边界

- 原生带时长的 SlideController 路径延迟第一页动画，等待字体/图片就绪，统一起点；按累计绝对时刻切页。录制专用 `recordingGo` 在音频页边界直接切页，不使用会吞掉页尾500ms的交互退场；页内动画保留，普通浏览交互 `go` 保持原行为。
- 起止四色校准片实际进入 WebM。解码像素识别两端后，只移除校准段，不做整体时间拉伸。媒体采样至少30fps，与输出fps分离；区间误差上限120ms。浏览器页进入、动画执行及结束时间偏差上限100ms。这些是本次开发工程检查阈值，不是预注册研究指标或完整课程验收标准。
- 结束标记出现时快照动画trace；取消、缺失、未执行或明显迟到的事件阻止输出。trace仍是浏览器证据，不升级成实际视频元素可见性证据。
- 保留 `.raw.webm` 与 `.clock.json`；转码先写 `.partial.mp4`，成功后才移动到正式文件名。已有输出/证据拒绝覆盖。加载与播放失败均尝试关闭资源并保存原始录制；清理/写报告失败不掩盖已有主异常。
- 旧 HTML 有时长但没有新录制接口会明确失败，需用当前模板另存重新生成 HTML；不能声称旧r36 HTML可直接使用。无时长控制器/Reveal.js旧兼容路径未获得本轮校准证明。
