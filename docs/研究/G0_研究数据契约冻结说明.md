# G0 研究数据契约冻结说明

状态：**G0_FROZEN**  
版本：`research-generation-v2-v0.1`  
适用范围：Visual Decision Track 与 Dynamic Alignment & Evaluation Track 的并行开发和 3–5 文档 dry run。  
不适用范围：正式人工 gold、最终实验阈值、模型实现和论文结论。

## 1. 冻结目标

本次冻结只解决四件事：

1. 两个人使用相同的实体和字段名；
2. ID 可以跨 lesson plan、script、storyboard、timing、trace 和最终视频证据稳定引用；
3. 两条主线可以用 mock 独立开发，不等待对方真实输出；
4. planned、compiled、runtime 与 final-video evidence 不再混写。

本契约是研究增量层，不替代现有生产文件。关闭后续 `research_generation_v2` feature flag 时，旧 `lesson_plan.json`、`script.txt`、`storyboard.json`、`storyboard_timed.json` 和 renderer 行为必须保持不变。

## 2. 唯一数据链

```text
source_units.json
  → lesson_plan.json / knowledge proposition
  → script_v2.json / narration proposition + narration span
  → storyboard.json / visual element + visual event
  → storyboard_timed.json / planned trigger
  → compiled_timeline.json / compiled start_ms + duration_ms
  → animation_trace.json / runtime actual_ms + target resolution
  → render_evidence.json / final-video visible interval
```

禁止新增第二套 `proposition_visual_plan.json`、visual element、visual event、schedule 或 runtime trace。后续确需新字段时，先增加可选字段；只有发生不兼容语义变化才升 schema 版本。

## 3. ID 规则

### 3.1 格式

所有新稳定 ID：

- 只使用小写字母、数字和连字符；
- 以 case slug 开头；
- 类型标记固定；
- 数字至少三位补零；
- 一经持久化不得因排序变化而重编号；删除后不得复用。

| 实体 | 格式 | 示例 |
|---|---|---|
| case | 兼容现有 `<name>_<nnn>` | `mock_lesson_001` |
| source unit | `<case-slug>-src-p<nnnn>` | `mock-lesson-001-src-p0001` |
| source image | `<case-slug>-img-<nnn>` | `mock-lesson-001-img-001` |
| knowledge point | `<case-slug>-kp-<nnn>` | `mock-lesson-001-kp-001` |
| knowledge proposition | `<case-slug>-kprop-<nnn>` | `mock-lesson-001-kprop-001` |
| segment | `<case-slug>-seg-<nnn>` | `mock-lesson-001-seg-001` |
| narration proposition | `<case-slug>-nprop-<nnn>` | `mock-lesson-001-nprop-001` |
| visual element | `<segment-id>-el-<nnn>` | `mock-lesson-001-seg-001-el-001` |
| visual event | `<segment-id>-evt-<nnn>` | `mock-lesson-001-seg-001-evt-001` |
| render observation | `<case-slug>-obs-<nnn>` | `mock-lesson-001-obs-001` |

### 3.2 兼容旧 ID

- `segment.id=1`、`element.id=e1` 等旧局部 ID 不直接作为跨文件主键；
- v2 使用稳定 ID，并通过 `legacy_segment_id`、`legacy_id` 保存旧映射；
- renderer 尚未支持 v2 ID 时，执行层可以使用 legacy ID，但研究结果必须回写稳定 ID；
- 不允许通过文本内容、数组下标或当前排序临时重建 ID。

## 4. 冻结字段

完整机器校验规则见 `contracts/research_generation_v2.schema.json`。以下是不能随意改名或改变语义的核心字段。

### 4.1 Source

| 对象 | 必需字段 | 说明 |
|---|---|---|
| source artifact | `schema_version`、`artifact_type`、`case_id`、`document`、`source_units`、`source_images` | 原教材证据入口 |
| source unit | `id`、`kind`、`text`、`source_locator`、`image_refs` | page/paragraph/span/caption 之一 |
| source image | `id`、`path`、`caption`、`source_refs` | 只记录教材图片，不表示已被采用 |

### 4.2 Knowledge Proposition 与 Visual Decision

| 对象 | 必需字段 | 说明 |
|---|---|---|
| knowledge point | `id`、`name`、`source_refs`、`propositions` | 容纳一个或多个知识命题 |
| knowledge proposition | `id`、`text`、`source_refs`、`visual_support` | 在 lesson-plan 阶段产生 |
| visual support | `label`、`acquisition`、`rationale`、`metadata` | A 主线负责 |
| metadata | `producer`、`version`、`confidence`、`abstain_reason` | 自动字段和 mock 都必须声明来源 |

`visual_support.label`：`none / source-sufficient / extra-support-needed / uncertain`。  
`acquisition`：`none / reuse / retrieve / generation-candidate / uncertain`。

### 4.3 Narration Proposition

| 对象 | 必需字段 | 说明 |
|---|---|---|
| script segment | `id`、`legacy_segment_id`、`narration_text`、`narration_propositions` | `script_v2.json`；旧 `script.txt` 继续保留 |
| narration proposition | `id`、`knowledge_proposition_ids`、`text`、`span`、`metadata` | script 生成后产生，不得提前塞入 lesson plan |
| span | `start`、`end`、`unit`、`end_exclusive` | 相对本 segment 的 `narration_text`；Unicode code point；`[start,end)` |

### 4.4 Visual Element 与 Visual Event

| 对象 | 必需字段 | 说明 |
|---|---|---|
| visual element | `id`、`legacy_id`、`type`、`semantic_role`、`source_refs`、`knowledge_proposition_ids`、`narration_proposition_ids`、`acquisition`、`payload` | “画面里有什么” |
| visual event | `id`、`action`、`target_element_id`、`narration_proposition_ids`、`semantic_role` | “对哪个对象做什么” |

`semantic_role` 不是正确性结论；字段存在只表示系统声明了绑定。`target_element_id` 必须引用同一 case 中真实存在的 element。

### 4.5 四层时间证据

| 层 | 文件 | 冻结字段 | 不能声称什么 |
|---|---|---|---|
| planned | `storyboard_timed.json` | `trigger_at_sec`、`planned_duration_sec`、`timing_source` | 不能声称浏览器已经执行 |
| compiled | `compiled_timeline.json` | `start_ms`、`duration_ms`、`easing` | 不能声称实际准时执行 |
| runtime | `animation_trace.json` | 复用 `animation-trace-v0.1` 的 `planned`、`actual`、`target_resolved`、`status` | 不能声称对象在 MP4 中实际可见 |
| rendered | `render_evidence.json` | `observed_visible_start_sec`、`observed_visible_end_sec`、`method`、`confidence`、`status` | 不能把 mock 或不可观测项当真实测量 |

## 5. 目录冻结

```text
datasets/research_generation_v2/
├─ mock_v0.1/                         # 冻结接口样例
│  ├─ package_manifest.json
│  └─ cases/<case_id>/                # 八个 canonical artifact
├─ dry_run/<run_id>/cases/<case_id>/  # 3–5 文档真实 dry run
└─ experiments/<experiment_id>/<run_id>/
```

`<run_id>` 建议使用 `<YYYYMMDD>-<short_commit>-<config_slug>`。每个 run 只追加，不覆盖；需要修订时创建新 run 并在 README/manifest 中说明 supersedes 关系。

## 6. 两人所有权与并行方式

### 成员 A：Visual Decision Track

写入：

- `lesson_plan.knowledge_points[].propositions[].visual_support`；
- `storyboard.segments[].elements[]` 中的视觉候选、source 和 acquisition 信息；
- Visual Necessity、Retrieval Triggering 与候选池实验结果。

读取但不改：B 冻结的 narration proposition/event mock。

### 成员 B：Dynamic Alignment & Evaluation Track

写入：

- `script_v2.segments[].narration_propositions[]`；
- `storyboard.segments[].events[]`；
- `storyboard_timed`、`compiled_timeline`、`render_evidence`；
- binding、timing、signaling 与 evaluator 结果。

读取但不改：A 冻结的 knowledge proposition/visual-decision mock。

### 共同只读

G0 后两人不得各自改 case/source/KP/proposition/segment/element/event 的已分配 ID。接口变更只通过：

1. 提交变更理由；
2. 增加 schema 版本；
3. 提供旧→新 migration；
4. 更新 mock 与契约测试。

不通过聊天口头改字段。

## 7. Mock 使用方法

入口：`datasets/research_generation_v2/mock_v0.1/package_manifest.json`。

- A 可以直接读取 `source_units.json`、`lesson_plan.json` 和 `storyboard.json` 的固定下游结构开发 visual decision；
- B 可以直接读取 `script_v2.json` 与 mock element 开发 binding、timing 和 evaluator；
- mock 中同时包含 `reuse` 与 `retrieve` 两条 acquisition 分支；
- mock runtime/render evidence 明确标注为接口样例，不得计入正式指标。

## 8. G0 变更边界

冻结后仍可在不升版本的情况下：

- 增加新的 mock case，但必须通过同一 schema；
- 填充当前允许为 `null` 的 checksum、confidence 或观测值；
- 在 `payload` 中增加 renderer-specific 内容。

以下变化必须升版本：

- 字段改名、删除或改变含义；
- ID 格式或稳定性规则变化；
- enum 收缩；
- narration span 单位或边界规则变化；
- 把 planned/runtime/rendered evidence 合并；
- 新建与现有实体含义重复的第二套 schema。
