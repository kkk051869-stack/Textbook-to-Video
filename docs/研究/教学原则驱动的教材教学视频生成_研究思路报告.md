# 面向教材教学视频生成的教学原则操作化与事件级诊断

> 论文研究思路报告（生成决策与动态呈现再平衡版）  
> 修订日期：2026-10-04  
> 本报告保留原理论框架、novelty audit 与代码审计事实，但把技术中心从“事后事件诊断”前移到“视觉支持决策与语义时序动态呈现”。旧标题暂时保留，标题候选见第 18 节。

## 1. 最高层研究定位

本研究关注：

> **教学原则如何进入教材教学视频的视觉生成决策，使系统知道哪些知识命题需要视觉、何时应检索外部视觉，以及获得的视觉应该对应哪个讲述命题并在何时动态出现。**

完整逻辑是：

```text
教学视频应该遵循什么原则
        ↓
原则对应什么视觉支持与呈现决策
        ↓
系统如何获得、绑定并动态呈现视觉
        ↓
最终成片是否执行了这些决策
        ↓
如何在有界条件下优化或修复
        ↓
如何评价
```

Event-level diagnosis 仍然重要，但重新定位为：

- 生成方法的验证机制；
- 失败发生位置的定位机制；
- P1 repair 的反馈信号。

它不再是整篇论文唯一或最高层的方法中心。

## 2. 为什么生成侧必须补全

仅在成片后检测 `EARLY / LATE / WRONG_TARGET`，无法回答更早的因果问题：

- 这个知识命题本来是否需要视觉；
- 教材已有视觉是否足够；
- 何时才应触发外部检索；
- 检索结果与当前命题是否真正匹配；
- 正确对象应该何时 show、reveal、highlight、dim 或 remove；
- 错误来自视觉选择、语义绑定、时间安排，还是渲染执行。

因此研究对象必须从“错误标签”扩展为“生成决策链”，但范围仍然只聚焦两个连续问题：视觉支持/检索决策与语义时序动态对齐。

## 3. 理论起点保持不变

老师最初提出的 Coherence、Multimedia、Personalization、Image 继续保留；动态视频补充 Temporal Contiguity 与 Signaling。六项原则不是六个平行算法。

```text
内容与视觉选择
├─ Coherence：不要为了丰富而加入无教学必要的信息
└─ Multimedia：判断哪些命题能从解释性视觉中获益

讲解与讲者
├─ Personalization：对话式、口语化但准确
└─ Image：讲者/代理的条件性呈现；当前无 presenter，N/A

动态呈现
├─ Temporal Contiguity：正确视觉在相关讲解附近出现
└─ Signaling：在适当时刻引导注意到正确对象
```

当前 script Prompt 已较强覆盖 Personalization，因此不把它写成主要研究 Gap。Image Principle 不是“多放图片”；在当前无数字人/讲者形象配置下保持 conditional / N/A。

## 4. 四个原则形成一条因果链

### 4.1 Coherence + Multimedia：Visual Support Need

对每个 knowledge/narration proposition 先判断：

- 不需要额外视觉；
- 教材已有视觉已经足够；
- 需要额外视觉支持；
- 证据不足，应 abstain。

这一步称为 **Visual Necessity / Visual Support Need Detection**。它不是图片存在检测：有图可能仍然是 decoration，没有图也不代表该命题一定需要图。

Coherence 提供抑制条件，避免视觉丰富度、动画数量和 5–8 秒变化频率把无关内容引入页面；Multimedia 提供正向条件，判断解释性、组织性或关系性视觉是否能帮助构建知识表征。

### 4.2 Visual Support Need → Retrieval Triggering

老师提出“如何找到真正需要 RAG 检索的关键部分”。研究问题不是普通 RAG pipeline，而是 **Retrieval Need Prediction**：

```text
Knowledge Proposition
        ↓
Need Visual Support?
   ┌────┴────┐
   NO       YES
   │          ↓
纯讲解     Existing Source Visual Sufficient?
              ┌────┴────┐
             YES        NO
              │          ↓
            Reuse     Retrieval Suitable?
                         ┌────┴────┐
                        YES       NO
                         │         │
                      Retrieve   Generate（optional）
```

论文需要验证选择性触发是否优于 Always Retrieve、Never Retrieve、keyword heuristic、Direct LLM 和 no-source 决策。只有在 source-conditioned 决策产生实际增益时，才保留相应 claim。

### 4.3 Retrieval / Reuse → Semantic Alignment

获得视觉不等于获得正确视觉。必须建立：

```text
Narration Proposition ↔ Visual Object
```

Semantic Alignment 回答“当前讲述命题到底对应哪个视觉对象”。它先于 timing，也先于 signaling。词面重合、embedding 相似或同一页面共现都只能作为 baseline；真正的教学语义对齐还要考虑 source evidence、visual function 和对象表达的关系是否正确。

### 4.4 Semantic Alignment → Dynamic Presentation

只有 binding 正确，Temporal Contiguity 才能决定该对象何时出现，Signaling 才能决定是否提示、指向谁、持续多久。

动态事件不只包括 `trigger_at_sec`，而应显式表示：

- show / reveal；
- highlight / focus；
- transition；
- dim / remove；
- target；
- start / duration；
- proposition dependency。

Temporal Contiguity 因而同时是 generation constraint 与 post-render evaluation principle。Signaling 同时包含 generation decision（是否需要、目标、时机、持续、竞争 cue）与 diagnosis（missing、wrong target、overload、mistimed）。

## 5. AI Visual Generation 的准确位置

AI generation 是 **Visual Completion / Visual Acquisition Action**，不是主要创新。只有同时满足以下条件才触发：

1. proposition 需要视觉；
2. 教材没有合适视觉；
3. 外部检索没有足够合适的候选；
4. proposition 适合生成式表达；
5. 生成视觉能通过 source/semantic safety check。

第一篇论文可以只保留 `generation-candidate` 标签或少量结构化生成类型。若工作量过大，直接把 AI generation 放到 P1，不影响 P0 的研究闭环。

## 6. Source-conditioned 的角色

Source 不是为了 novelty 增加的输入，也不是普通 RAG 的同义词。它支持：

1. 确定 knowledge proposition；
2. 判断 Visual Necessity；
3. 触发或抑制 retrieval；
4. 评价视觉是否正确；
5. 建立 proposition→visual binding；
6. 区分 selection、binding、timing、signaling 与 rendering error。

但代码审计表明，当前 production chain 并不具备完整 provenance：`source_refs` 在 lesson plan 后断裂，script 无 proposition ID，element/event 无 source/KP binding。新方案允许在 versioned feature flag 下修改正式代码补足必要关系；不能继续把这些关系写成当前已有能力。

若 no-source ablation 没有稳定变差，source-conditioned claim 必须删除，source 只能作为 fidelity guard 或控制变量。

## 7. 当前系统事实与研究起点

### 已有或部分已有

- segment/page 级 narration；
- knowledge point ID 与 element ID；
- animations/timeline、target 与 planned time；
- 真实 TTS duration、subtitle sentence cues；
- highlight、focus、dim、pulse 等 signaling mechanics；

- render、layout、audio、subtitle、duration 与 target resolution 等 technical QA；
- candidate、accept/rollback、lineage 与有限 `max_rounds` 的 repair infrastructure。

### 当前缺失

- proposition-level representation；
- source→proposition→visual 的稳定 provenance；
- Visual Necessity 与 Retrieval Triggering；
- proposition→visual 的教学语义 binding；
- final MP4 中对象的实际 visibility interval；
- principle-aware event compliance；
- layout/semantic/temporal 多目标 repair convergence 与 oscillation detection。

### 数据结构落点（最小增量）

本研究不要求新增一套与 storyboard 平行的视觉规划 JSON。当前版本采用：

```text
lesson_plan.json
  └─ knowledge_points[].propositions[]
       ├─ knowledge_proposition_id / proposition_text
       ├─ source_refs
       ├─ visual_need
       └─ acquisition

script_v2.json（同时保留旧 script.txt）
  └─ narration_propositions[]
       ├─ narration_proposition_id
       ├─ knowledge_proposition_ids
       ├─ narration_text
       └─ narration_span

storyboard.json
  └─ elements[]
       ├─ proposition_ids
       ├─ source_refs
       └─ visual_role

timed_storyboard.json
  └─ animations[] / timeline[]
       ├─ trigger_at_sec / at_sec（planned time）
       └─ matched_sentence_id / proposition_ids

compiled HTML / runtime timeline
  └─ start_ms / duration_ms（compiled schedule）

animation-trace-v0.1
  └─ actual_ms / target resolution / status（runtime evidence）

render-evidence-v0.1
  └─ observed_visible_start / observed_visible_end / confidence
     （final-video evidence）
```

已有字段直接复用，新增内容只通过可选字段或证据 sidecar 补充。知识命题先在 lesson-plan 阶段产生；旁白命题和 `narration_span` 必须在 script 生成后产生，不能提前写成 lesson-plan 已知字段。独立的 `proposition_visual_plan.json` 暂不建立；只有在需要多套候选方案、独立版本管理或跨 Renderer 共享视觉规划时才拆分。`render-evidence-v0.1` 不是第二套 runtime trace，而是对最终 MP4 可见区间的独立观测记录。

### Timing 的真实边界

当前系统达到：

- 视频—音频总时长对齐：YES；
- page/segment—旁白对齐：YES；
- sentence—visual event 对齐：PARTIAL；
- proposition—visual object 对齐：NO；
- principle-aware semantic-temporal alignment：NO。

`trigger_at_sec` 是 planned time；runtime trace 是浏览器事件启动证据；两者都不能冒充 final-video visible interval。legacy timing 还可能只改 animations，而 renderer 优先已有 timeline。

## 8. Highest-level Method

拟议方法不是单个 checker，而是一条可消融的生成决策链：

### Stage A：Knowledge Proposition Analysis

先从 source unit 与 knowledge point 得到 knowledge proposition，记录到现有 `lesson_plan.json`，并保留 source evidence 与不确定性；script 生成后再形成 narration proposition，记录到 `script_v2.json`，用稳定 ID 连接对应的 knowledge proposition，并保存 `narration_text` 与 `narration_span`。两类 proposition 不合并成一个跨阶段“天然已存在”的对象。

### Stage B：Visual Support Decision

预测 `none / reuse / retrieve / generation-candidate`。Visual Necessity 与 Retrieval Triggering 共用 Coherence/Multimedia 依据，但分别评价。

### Stage C：Semantic Proposition–Visual Binding

从教材图片或候选视觉中选择能够解释 proposition 的对象，记录 visual function、binding confidence 和 abstention。

### Stage D：Dynamic Event Planning

以 binding 为前提生成视觉事件 schedule；Temporal Contiguity 决定 timing，Signaling 决定 cue applicability、target、time 与 duration。

### Stage E：Post-render Event-level Evaluation

对比 generation decision、plan、runtime 与 rendered-video evidence，输出定位、证据、置信度和错误归因。它验证前四阶段，而不是取代前四阶段。

### Stage F：Optional Bounded Repair

P1 才根据诊断生成 local candidate，经多目标复评后 accept / rollback / alternative / stop。

## 9. Research Questions

### RQ1

> **How can Coherence and Multimedia be operationalized into proposition-level visual-support and retrieval-triggering decisions for automatically generated instructional videos?**

### RQ2

> **Can proposition-aware semantic visual binding and dynamic event planning improve visual timing and attention guidance over current sentence-level, lexical, and rule-based methods?**

### RQ3

> **To what extent can event-level post-render evidence validate visual-support, semantic-binding, temporal, and signaling decisions beyond aggregate scores and direct VLM judging?**

RQ1/RQ2 是生成侧核心；RQ3 是统一评价。若范围必须再缩小，RQ1 保留 Visual Necessity/Triggering，RQ2 只保留 Semantic Alignment + timing，Signaling 作为子指标。

## 10. 论文贡献候选

### Contribution 1：Pedagogically Grounded Visual-Support Decision Formulation

将 Coherence/Multimedia 转成可标注、可拒绝的 visual need 与 acquisition decision，而不是“多图多动画”规则。只有 gold 一致性达标并优于 always/never/direct-LLM 才保留。

### Contribution 2：Proposition-aware Retrieval Triggering and Semantic Visual Binding

判断哪些命题需要外部视觉支持、何时复用教材图、何时检索，并将候选视觉绑定到 source-supported proposition。普通 RAG、候选检索器或 schema 本身不是贡献。

### Contribution 3：Semantic-Temporal Dynamic Presentation

在 semantic binding 后安排 visual event 与 signaling，使“出现什么、何时出现、提示谁”构成连续决策。必须相对 current semantic timing、lexical/embedding 与 Direct VLM baseline 证明增益。

### Enabling Contribution：Event-level Post-render Evaluation

用 proposition/object/event/time gold 验证生成决策，并区分 plan/runtime/rendered evidence。只有相对 aggregate 与 Direct VLM 在定位、归因或校准上有明显优势时，才作为方法贡献；否则只是评价协议。

AI generation、通用 layout optimization 和 checker→repair loop 不列 P0 contribution。

## 12. 人工标注的作用

Gold 不再只为训练 violation checker，而是服务整条决策链：

1. proposition 是否需要视觉；
2. 教材视觉是否足够；
3. 是否应检索；
4. 候选视觉是否适合；
5. proposition→visual binding 是否正确；
6. visual timing 是否可接受；
7. signaling 是否必要、target 是否正确；
8. final rendered outcome 是否执行计划。

正式 pilot 只标最小集合，不标生成图美学或 repair history；此前 5–10 个 proposition 的非正式试填只校准定义，不形成论文数据。若 visual need/retrieval 无法稳定标注，整条生成侧主张必须缩小，而不是直接用 LLM 标签替代 gold。

## 13. Event-level Diagnosis 的新定位

Event-level evaluation 回答：

- Visual Need 决策是否漏掉必要视觉或引入无关视觉；
- acquisition 是否选错来源；
- semantic binding 是否错对象；
- timing 是否 premature/delayed/missing；
- signaling 是否 missing/wrong-target/overload/mistimed；
- plan 是否在 runtime 与 final video 中真正执行。

它输出 location、evidence、confidence、abstention 与 error attribution。技术 QA 继续单列，不能把 render success、layout pass 或 audio duration proxy 写成原则 compliance。

## 14. Bounded Repair 与 Layout Loop

布局优化可能形成：

- 修 overlap → 缩小元素 → 关键信息不可读；
- 移动元素 → proposition–visual relation 变差；
- 删除元素 → 页面变空 → richness heuristic 再加回；
- 调整 signaling → 目标可见但 cue 与 narration 错时。

因此 P1 repair 必须是：

```text
Diagnose
→ Local Candidate
→ Re-render
→ Multi-objective Re-evaluation
→ Accept / Rollback / Alternative
→ Stop
```

必须有 max iterations、repair history、state hash、objective vector、regression detection、rollback、repeated-state/oscillation detection 与 patience stop。当前 repair orchestrator 的 candidate、rollback、lineage 和 max rounds 是相邻基础，但不足以证明收敛。

这一问题不进入 P0，因为通用 repair loop 已被 PIVOT、Code2Video 等近邻覆盖，且它依赖可靠的生成决策和评价信号。

## 15. 最重要的三个实验

### 实验 1：Visual Support / Retrieval Triggering

在最小接口 sanity check、代码/导出链 dry run 和 20–30 proposition 正式 pilot 后扩大到正式数据，比较 always、never、heuristic、Direct LLM、no-source 与 proposed。测 macro-F1、各类 recall、calibration、abstention、候选视觉 appropriateness 和 retrieval cost。

### 实验 2：Semantic-Temporal Dynamic Alignment

在固定候选视觉上比较 lexical、embedding、Direct VLM、current semantic timing 与 proposed。测 binding accuracy、target accuracy、onset error、window overlap 与 early/late/missing/wrong-target。

### 实验 3：端到端消融与跨系统验证

在同一 T2V platform 上依次加入 visual decision、semantic binding、dynamic planning；用盲化 event gold 比较原则违规、source fidelity 与 technical quality。若 PresentAgent 可复现，再验证评价是否可迁移到外部生成器，而不是构造第二个 T2V 名称。

### 实验范围审计：避免重复设计

三项实验不要求三套独立系统：实验 1 复用 `lesson_plan.json` 中的 knowledge proposition、source_refs、visual_need 和 acquisition；实验 2 复用 `script_v2.json` 中由其派生的 narration proposition/span 与同一批 storyboard 元素，只比较 binding 和 timing；实验 3 是前两项能力的受控端到端消融，不再新增另一套 timing、runtime trace、成片证据格式或 visual planner。

以下内容明确不重复实现：

- 不新增独立 `proposition_visual_plan.json`；
- 不新增第二套 `visual_element` 或 `visual_event` schema；
- 不新增第二套 `schedule`，继续使用 `timed_storyboard`；
- 不新增第二套 runtime trace，继续使用 `animation-trace-v0.1`；
- final-video visibility 单独写入 `render-evidence-v0.1`，不把 `actual_ms` 冒充可见区间；
- 不把 PresentAgent 对照、Video-QA 和用户学习实验混入 P0 主实验。

因此，当前实验真正验证的是同一条决策链的三个层次：

```text
是否需要视觉 / 是否检索
→ 视觉是否绑定到正确命题
→ 绑定后的视觉是否在正确时机执行
```

如果 pilot 证明某一层无法稳定标注或没有增益，就删除该层的论文主张，而不是继续增加新的模块。

## 16. Novelty 边界

本文不声称：

- 首次用 Mayer/CTML 指导视频生成；
- 首次做 RAG 教材视频；
- 首次建立 narration–visual alignment；
- 首次在成片上检查原则；
- 首次 checker→repair→rerender；
- 首次建立 typed schema 或 provenance。

候选差异必须落在：**教材证据条件下的选择性视觉支持/检索决策，以及 proposition→visual→event 的人类金标语义时序对齐**。如果公开近邻已覆盖相同粒度，或 pilot 不能证明 source/triggering/binding 的增益，应按 claim gate 收缩。

## 19. 可证伪性

- visual need/retrieval gold 一致性不足：删除 Retrieval Triggering，收缩为 Visual Necessity analysis；
- Always/Never/Direct LLM 与 proposed 无显著差异：不保留视觉决策方法贡献；
- source ablation 无影响：删除 source-conditioned 修饰；
- semantic binding 不优于 lexical/embedding/VLM：不进入 dynamic planning 主张；
- proposition-aware timing 不优于 current semantic timing：只保留 binding，timing 降为工程实现；
- event evaluator 不优于 aggregate/VLM 定位：降为人工评价协议；
- final-video visibility 不可靠：只报告 runtime onset 与人工可判定窗口；
- 无学习者实验：不声称学习效果提高；
- AI generation 或 bounded repair 未完成：不影响 P0 论文成立。

## 20. 下一步

G0 字段、ID、目录和 mock 已按 `research-generation-v2-v0.1` 冻结。下一步先用 **5–10 个 proposition 做非正式标签与接口 sanity check**，随后完成最小结构化产物、证据导出链，并在 3–5 份文档上 dry run；不兼容问题通过新版本和 migration 处理，不原地改冻结契约。dry run 后冻结标注协议，再完成 **20–30 个 proposition 的正式双人 Visual Support / Retrieval Triggering pilot**。这样先完成可复用的内容与代码基础，再投入正式标注；若“无需视觉 / 教材已有足够视觉 / 需要检索”仍不能稳定区分，则删除或收缩对应论文主张，而不是继续实现通用 RAG、图像生成或 repair loop。
