|---|---:|---:|---:|---:|
| Never Retrieve | 3/4 | 2/4 | 2/4 | 1/4 |
| Always Retrieve | 0/4 | 1/4 | 0/4 | 0/4 |
| Keyword Heuristic | 3/4 | 2/4 | 2/4 | 1/4 |
| Current Visual Decision | 3/4 | 4/4 | 3/4 | 2/4 |
| Routed candidate | 3/4 | 3/4 | 4/4 | 3/4 |

两模型在全部顺序下第一名一致的命题为 2/4；加入完整排序与拒绝集合后只有 1/4 一致，3/4 保留 UNRESOLVED。没有模型 abstain，不代表证据充分；不能把模型未主动弃权与可靠性混为一谈。两模型各有 1 条发生第一名顺序变化；完整排序/拒绝集合顺序稳定均为 1/4。

| 命题 ID 尾段 | 内容与观察 | 归因与状态 |
|---|---|---|
| seg-1-nprop-001 | “它不仅支撑了比特币”；max 首选随顺序由 none 变为 generate | 命题残片/指代上下文不足，裁判还指出引用片段偏历史背景；UNRESOLVED |
| seg-1-nprop-002 | “现代数字经济中解决信任问题的关键技术”；plus 首选 none→retrieve，max 两次 generate | 视觉必要性与获取方式存在模型/顺序分歧；UNRESOLVED |
| seg-2-nprop-003 | “区块链，本质上是一种分布式记账方式。”；四次均 generate，排序及拒绝集合一致 | MODEL_CONSISTENT_PROXY；未实际生成素材或证明教学增益 |

router 只改变一条 retrieve→generate。在 plus 原序无变化、反序少匹配一条；max 两序各多一条，故仍不能冻结为已验证有效方法，也没有依据继续对这四条调规则。

发现的优先方法缺口是 Phase 1 的命题完整性和来源支持：引用 ID 完整不等于来源蕴含，语法残片会使裁判自行补全指代并给出不同视觉需求。这里记录裁判理由及来源关联诊断，不手工改冻结命题、不自动补标签。下一批应以完整知识命题、明确旁白上下文和可检查的来源支持作为输入，保留无法判定；先补这一层，再评估获取路由。
