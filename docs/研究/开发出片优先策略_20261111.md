# 开发出片优先策略

2026-11-11，按用户指示实施。普通 development 路径优先完成页面和视频；质量问题保留为未批准草稿及日志，不计为审核通过。strict 和研究入口不采用这项语义放行策略。此前用户指定的图像大小仅提醒策略继续有效。

## 实际行为

- 有效审核记录中的 REVISE、REJECT、低语义/可读性评分和负面内容检查，在 development 下允许作为草稿继续执行。原判词、分数、问题及 strict 拒绝原因均保留；`strict_approved` 仍为 false。
- development 页面预检把裁切、拥挤、小字等布局质量问题写入 warnings。缺失图片像素、丢失元素/正文、替换内容去向缺失仍拒绝该候选。
- 非法结构、生成/服务失败而无可用资产时，普通保全页面路径继续使用原页。`enhancement-failure.json` 和分镜 metadata 记录失败及证据目录；没有把未执行视觉决策标为 none。
- 来源引用、文件、hash、保存记录一致性及事件目标存在性仍校验。候选失败不得通过改写引用或借用别处审核记录恢复。
- Agent、资产消费、局部合成和跨运行缓存均使用同一 development 审核策略。修正缓存包装器与 Agent 对默认资产上限/页面预算的输入绑定差异，避免合法缓存刚生成就被判不一致；原有 hash 验证保留。
