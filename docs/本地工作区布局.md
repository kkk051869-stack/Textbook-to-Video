# 本地工作区布局

源码、运行数据和历史备份在同一个项目总目录下分区存放。Git 只管理源码；本机数据、历史快照和迁移备份统一放入被忽略的 `.local/`，避免再次形成仓库套仓库、重复 worktree 和大体积产物混入版本管理。

## 推荐目录

```text
D:\Code\vibe coding\Textbook-to-Video\
  src\              # Python 包
  tests\            # 自动化测试
  scripts\          # 可复用脚本
  docs\              # 项目文档
  contracts\         # TextbookEval 契约
  datasets\          # 已纳入版本管理的小型冻结数据
  assets\            # 已纳入版本管理的运行资产
  .local\            # 整体被 Git 忽略
    data\
      inputs\        # 教材原件
      runs\          # 生成任务产物
      eval-runs\     # 评测结果
      exports\       # 云端导出和正式视频
      fonts\         # 字体源
      tools\         # ffmpeg 等本地工具
      archives\      # ZIP、RAR、TAR 和历史传输包
      reports\       # 实验报告与项目汇报
    legacy\          # 整理前的旧代码与文档快照
    backups\         # Git bundle 等恢复文件
```

`.local/` 属于项目总目录的一部分，但不得提交到 Git。需要复制或迁移整个项目时，应明确决定是否同时携带 `.local/` 中的大体积数据。

## Git 与 worktree 约定

1. 项目根目录只保留一个 `.git`，`origin` 指向 GitHub。
2. 临时 worktree 放在主仓库同级的 `Textbook-to-Video-worktrees`，不要放进仓库内部。
3. 删除 worktree 必须使用 `git worktree remove`，随后运行 `git worktree prune`。
4. 合并分支后及时移除不再使用的工作树；未合并分支至少保留一个 branch、tag 或 bundle。
5. 提交前运行 `git status --short`，确认没有教材、视频、音频、模型、密钥或运行目录。

## 产物管理

- CLI 默认使用的 `output/` 仅作为临时运行目录，正式结果完成后迁入 `.local/data/runs/` 或 `.local/data/exports/`。
- 每次正式生成或评测使用稳定的 `run-id`，不要用 `copy`、`new`、`final2` 等目录名。
- 字体和 ffmpeg 只维护一份来源；需要自包含归档时再复制到冻结产物中。
- 历史 eval run 保持只读，可按批次压缩归档；探针、smoke 和失败的临时 run 可在确认无复现价值后删除。
- `.env` 只保存在本机且必须被 Git 忽略；迁移时使用私密备份，不进入普通归档包。

## 定期检查

```powershell
git status --short
git worktree list
git count-objects -vH
python -m pytest tests -q
```

若 `git count-objects -vH` 显示大量松散对象或垃圾，先制作并验证 `git bundle create ... --all`，再执行 Git 垃圾回收。
