# 核心近邻工作精读与选题收缩

> 调研日期：2026-10-03  
> 阶段目标：在第一阶段综述基础上，判断最近邻工作已经做到哪里，并把选题收缩为可证伪、可评价的小论文问题。  
> 证据规则：文中将“论文事实”“本文分析”“对本项目的推论”分开书写；没有在原文中披露的实现细节一律标为“未报告”，不据系统名称或流程图推断。

## 0. 结论先行

本轮精读支持四个结论。

1. **不能再把“用 Mayer/教学理论指导 AI 教学视频生成”本身作为主要创新。** PedaCo-Gen 已将 12 条 CTML 原则放入生成与脚本审阅流程，PIVOT 已使用教学化 storyboard 和“生成—验证—代码修复”流程。宽泛定位与它们高度重叠。
2. **现有工作还没有完成“忠实原则定义 → 机器可观测变量 → 类型化违规 → 原则专属局部修复 → 成片复检”的完整链条。** PedaCo-Gen 停留在提示词/审阅量表与教师决策；LASEV 的检查是语义、编译和格式质量门；PIVOT 的检查是布局、事实与认知清晰度；PresentAgent 的评价主要是 VLM 内容/视听质量与问答。它们都没有报告经过验证的 Mayer 原则违规检测器及原则专属修复成功率。
3. **最值得保留为核心的原则是 Coherence、Signaling、Temporal Contiguity；但小论文不应同时把三条都做深。** 最窄、最可验证的方向是以 `Signaling + Temporal Contiguity` 处理“旁白命题—视觉对象/动作—时间区间”的语义时序对齐；Coherence 可作为教材 grounded 的第二候选或边界约束。
4. **论文外包装宜采用 C，科学贡献宜采用 B。** 即题目/系统定位为“教材教学视频中的原则感知生成—检测—修复”，核心方法贡献是“把少量原则转为机器可执行约束”。不宜采用笼统的 A“CTML-guided generation”。

最重要的未解决问题不是“能否生成视频”，而是：**能否把一个教学原则的适用对象和违规条件说清楚，并证明自动检测和定向修复在最终渲染视频上有效，而且不会以教材失真或新错误为代价。**

# 1. 精读口径与比较框架

## 1.1 原则“进入算法”的六个层级

为避免把“引用 Mayer”误写成“操作化 Mayer”，本文使用以下分级：

| 层级 | 判定标准 | 例子 |
|---|---|---|
| A 背景引用 | 只在动机、相关工作或理论背景中提及原则 | “依据多媒体学习理论，视频应清晰” |
| B 提示词要求 | 原则被写进生成 prompt，但没有独立检查对象或输出字段 | “请同步旁白与画面” |
| C 生成/审阅 rubric | 有按原则组织的生成或审阅清单，LLM 可给自然语言意见 | “按 Temporal Contiguity 审阅脚本” |
| D 结构化字段 | IR 显式记录原则所需对象及关系 | `narration_span`、`visual_element_id`、`time_window` |
| E 可判定违规 | 给出可执行或可学习的判定条件，并能输出类型化违规 | `DELAYED_VISUAL(P,E)`、置信度与证据 |
| F 原则专属修复 | 违规类型触发有限、可追踪的定向修改，随后复检 | 延后/提前触发、替换错配视觉、删除无关元素 |

层级高低不等于论文质量高低；它只回答本项目关心的“原则是否已经被算法化”。一个优秀的人机协作系统可以停在 C，一个高吞吐工业系统也可能拥有通用 E/F，但不具备**原则专属** E/F。

## 1.2 评价证据的严格区分

后文不把下列代理指标称为真实学习效果：

- VLM 看视频后回答由研究者编写的问题：是**模型侧信息可恢复性/内容传达代理**；
- LLM/VLM 对“教学有效性”“清晰度”打分：是**模型评审**；
- 教师预测“学生会学得更好”：是**专家感知的教学质量**；
- 学习者自报“容易理解”：是**学习者主观评价**；
- 只有真实学习者的前后测、保持测验、迁移测验或受控组间差异，才是**学习结果证据**。

# 2. 四篇核心近邻工作的定向精读

## 2.1 PedaCo-Gen：CTML 已进入脚本生成和审阅，但没有机器化违规—修复闭环

**来源。** Injun Baek, Yearim Kim, Nojun Kwak, *PedaCo-Gen: Scaffolding Pedagogical Agency in Human-AI Collaborative Video Authoring*, CHI EA 2026，全文见 [arXiv](https://arxiv.org/html/2602.19623) 与 [ACM DOI](https://doi.org/10.1145/3772363.3798741)。以下方法判断主要依据原文 §2.1、Appendix A/B/F，尤其是 Table 9–10。

### 2.1.1 输入、输出与人的角色

**论文事实。** 用户复制粘贴“结构良好的文本知识”，选择预配置的 CTML 约束并可追加自定义要求；Gemini 2.5 Flash 生成按 scene 组织的脚本，每个 scene 仅包含 `Visual Description` 与 `Clear Narration`。Veo 3.1 逐 scene 生成视频再拼接，默认每 scene 8 秒。系统明确是 educational video authoring，但输入不是教材对象模型，没有页码、段落 ID 或证据跨度。教师在约束选择、脚本审阅、接受全部建议或手工编辑中持续参与，是最终的 “pedagogical gatekeeper”。原文位置：[§2.1](https://arxiv.org/html/2602.19623)、Appendix F.1–F.3。

| 问题 | 原文证据所支持的答案 |
|---|---|
| 输入粒度 | 一段学习内容文本 + 原则/约束 + 可选审阅要求 |
| 输出格式 | scene-by-scene 的视觉描述与旁白；随后逐 scene T2V 并合成视频 |
| 是否教材 grounded | 否；未报告页码、段落证据或来源引用 |
| 是否教育专用 | 是 |
| 是否生成动画 | 由 Veo 生成短视频片段，不是对象级可执行动画代码 |
| 音画同步粒度 | scene 级；prompt 要求同步，但 IR 没有对象/事件时间戳 |
| 教师是否参与 | 是，而且选择和应用修改是方法的核心 |

### 2.1.2 实际 IR 字段，而非系统概念图中的抽象说法

| 目标字段 | 是否存在 | 精读结论 |
|---|---:|---|
| learning objective | 否 | 输入有 learning content，但输出 schema 未列目标字段 |
| knowledge point | 否 | 没有知识点 ID/层级 |
| narration | 是 | 每 scene 的 `Clear Narration` |
| visual object/event | 部分 | 自然语言 `Visual Description`，不是对象 ID 或动作记录 |
| timestamp / interval | 否 | 只有默认 scene 时长；没有句/命题到对象的时间区间 |
| source evidence | 否 | reviewer 可比较 learning content，但无证据字段 |
| pedagogical constraint | 外置 | 原则位于设置和 prompt，不随 scene 结构化保存 |
| violation | 弱结构 | 要求指出 scene 编号和问题，但输出是自然语言建议，无固定类型 schema |
| repair action | 否 | 输出一份完整 revised script，不记录原子修改动作 |

因此，论文把“video blueprint”称为 IR 是成立的，但它是**可供教师审阅的脚本 IR**，不是支持对象级自动检查/局部修复的约束 IR。

### 2.1.3 12 条 CTML 原则究竟如何被操作化

PedaCo-Gen 在论文叙述中说“系统化操作 12 条原则”和“structured constraints”。Appendix F 的实际 prompt 则把它们压缩为六组自然语言规则。下表区分了**原则确实出现**与**达到机器可判定条件**。

| CTML 原则 | 生成/审阅 prompt 中的对应规则 | 实际层级 | 关键边界 |
|---|---|---:|---|
| Coherence | 不用背景音乐；保留且只呈现与学习内容直接相关的旁白/画面 | C | relevance 由 LLM 整体判断，无元素级证据或阈值 |
| Signaling | 用箭头、高亮色、粗体引导重要信息 | C | 无 cue、target、时间窗字段 |
| Redundancy | 尽量减少与旁白重复的屏幕文字 | C | 未定义“重复”的可执行条件 |
| Spatial Contiguity | 相关文字与图形放近 | C | 脚本阶段没有可测坐标 |
| Temporal Contiguity | 旁白和视觉在时间上同步、语义上对齐 | C | 没有时间戳，也不检查成片 |
| Segmenting | 单 scene 不放过多信息，分散到多个 scene | C | 没有密度/复杂度阈值；也不是学习者自定步调 |
| Pre-training | 在 Scene 1–2 提前介绍术语和概念 | C | 有位置启发式，但无先备知识模型 |
| Modality | 用图像或旁白替代屏幕文字 | C | 与 Redundancy 合并，未按画面复杂度条件化 |
| Multimedia | Appendix 评价 Q1 要求图/视频与文字结合；生成 prompt 仅间接要求解释性视觉 | B/C | 没有关键命题必须配何种解释图的映射 |
| Personalization | 友好、温和、第一人称、非正式会话风格 | C | 可评审风格，但未结构化 |
| Voice | 使用自然人声而非机器感声音 | B/C | 脚本 reviewer 无法判断最终合成音质 |
| Image | prompt 要求不要持续显示讲者脸，优先解释性视觉 | C | 这一条接近 Mayer 原义；但 Appendix A 又混入“清晰、高质量、相关视觉”，评价 Q12 变成屏幕质量，存在构念漂移 |

**关于 Image Principle 的关键核对。** Mayer 的经典 Image Principle 是“把讲者的静态形象放在屏幕上并不必然带来更好的学习”，不是“多放图片”或“图片要高清”。PedaCo-Gen 的生成规则“避免持续显示 speaker’s face”较接近原义；但 Appendix A 对 Image 的释义加入一般视觉相关性/技术质量，Table 4 的 Q12 又只问屏幕质量是否足够让人聚焦图形。因此，其 Image 评价不能被当作对经典 Image Principle 的纯净测量。经典定义可对照 [Mayer, 2014, Personalization, Voice, Image, and Embodiment Principles](https://doi.org/10.1017/CBO9781139547369.017)。

### 2.1.4 reviewer 的输入、输出、定位能力与检查对象

**论文事实。** Reviewer 输入 `[Learning Content]`、`[Video Generation Script]` 和原则/约束；prompt 要求输出三块：`Detailed Review Results`、`Suggestions for Improvement`、`Revised Script`。建议必须指出具体 scene 编号，并给出修订方案；随后输出整份修订脚本（Appendix F.3, Table 10）。

**能力边界。**

- 能定位到 scene；未报告定位到某个视觉对象、某个旁白命题或某个时间区间。
- 原文说 feedback 是 structured，但公开的输出格式只有三个自然语言标题，没有 `principle_id`、`violation_type`、`evidence_span`、`repair_op` 等机器字段。
- 检查对象是**脚本 IR**。review 发生在 Veo 合成前，因此不能看到最终布局、文字渲染、合成语音、真实对象出现时间或音画错位。
- 它检查内容相关性和 12 原则的脚本可见部分；不能可靠检查编译/渲染、最终认知负荷或真实学习。

### 2.1.5 修复闭环与评价证据

**论文事实。** LLM 给出完整 revised script；教师可以一键应用全部建议，或手工选择性编辑。review 可重复，直到用户满意。论文没有报告自动按违规类型路由、局部 edit script、修后自动复检、最终视频再检查、修复成功率或新错误率。

**评价。** 23 位教育专业人员在三个主题、两种条件下评价约 1 分钟视频；量表是 12 条原则 + overall validity 的 5 点 Likert。平均分从 3.07 升至 3.86，12 项均显著，提升较大的是 Pre-training（+0.86）和 Coherence（+0.84）（§2.2–3.2、Appendix B/D）。这是**教育专家的原则符合度感知和系统体验**，不是独立盲评的学习实验。作者明确把真实学习者的 cognitive load 和 learning outcomes 留作未来工作（§5）。

### 2.1.6 与本项目的重叠和剩余边界

**重叠很高的部分：** Mayer/CTML 指导生成、可编辑中间脚本、LLM reviewer、生成前修订、专家原则量表。若本项目只做“把 7 条 Mayer 原则写入 prompt，再让 LLM 审阅 storyboard”，与 PedaCo-Gen 的差异不足。

**仍然清晰的边界：**

1. PedaCo-Gen 不是教材证据可追溯生成；
2. 原则未进入对象/时间级 schema；
3. 没有原则类型化、可验证的 checker；
4. 没有原则专属局部修复与修后成片复检；
5. 没有检测准确率、repair success/new-error rate 或真实学习结果。

所以可主张的空间不是“比它使用更多 CTML 原则”，而是“把少量原则做得更可执行、更可验证，并作用到最终渲染视频”。

## 2.2 LASEV：最强的结构化时序近邻，但不是 Temporal Contiguity 检测论文

**来源。** Lingyong Yan et al., *Beyond End-to-End Video Models: An LLM-Based Multi-Agent System for Educational Video Generation*, KDD 2026，全文见 [arXiv](https://arxiv.org/html/2602.11790) 与 [ACM DOI](https://doi.org/10.1145/3770855.3818323)。以下判断依据 §3–5，尤其 Eq. (1)–(9)、§4.2–4.4、Table 1–5。

### 2.2.1 输入、输出和 EVS 的真实结构

**论文事实。** 输入是 K–12 教育题目 `Q`，不是长教材；输出是由模板、Manim/Python、TTS 确定性编译的教学视频，不需要教师编辑。核心 IR 是 Executable Video Script：

\[
\mathcal{S}=(\mathcal{P},\mathcal{N},\mathcal{A})
\]

- `P`（Pedagogical Content）：题目前提、逻辑原子步骤、符号和视觉资产；分为 `P^text` 与可选 `P^illus`（Manim 代码/资产）。
- `N`（Narration）：与离散逻辑单元对应、可时间分段的旁白序列 `{n_i}`。
- `A`（Alignment & Orchestration）：旁白—视觉事件时间映射、样式约束和 scene 演化规则，由 Orchestrator 全局生成。

§4.4 进一步明确：每个 narration segment `n_i` 映射到一个 visual event window；显示时长依据 symbolic density；可执行动画以同步 trigger 插入。

| 目标字段 | 是否存在 | 精读结论 |
|---|---:|---|
| learning objective | 隐含 | orchestrator 接收 instructional objective/target audience，但论文未公开稳定字段 schema |
| knowledge point / logical step | 是 | `P^text` 是逻辑原子步骤 |
| narration | 是 | `{n_i}`，可分段 |
| visual object/event | 是 | 视觉资产、Manim 代码、visual event window |
| timestamp / interval | 是（概念级） | `A` 有 step-to-time mapping；论文未披露具体 JSON 字段或区间单位 |
| source evidence | 否 | 输入是题目，不是教材证据链 |
| pedagogical constraint | 部分 | `A` 和 semantic rubric 中有目标/连贯性，未记录 Mayer 原则 ID |
| violation | 是（通用） | semantic/tool/rule 三类 gate 及 structured critique feedback |
| repair action | 模块级 | 反馈返回对应 agent 重新生成；不是原则专属局部操作 |

### 2.2.2 checker 和 repair 到底检查什么

**论文事实。** 每个中间产物必须同时通过：

- `C_sem`：基于预定义 rubric/课程大纲的逻辑正确、教学连贯、学习者友好；
- `C_tool`：Python/Manim 执行与编译；
- `C_rule`：格式、关键词、函数/API 约束。

失败时合并为 `f_i`，返回对应 agent 再生成；每 stage 最多三次，仍失败则发布前过滤。Illustration Agent 明确会处理编译错误与函数约束；Narration Agent 接受语义检查和可分段格式检查（§4.2–4.4、§5.1）。

**未报告。**

- 没有专门的 narration–visual temporal checker 指标、容差或违规类型；`A` 主要是**生成/编排机制**。
- 没有说明 checker 是否从最终 MP4 反推真实对象可见区间并与音频强制对齐。
- 没有报告 premature/delayed/missing/mismatch 的分类准确率。
- 没有以 Mayer Temporal Contiguity 为理论定义建立 checker；Mayer 仅在引言中作为一般教学依据，全文未出现 “Temporal Contiguity”。因此不能把 LASEV 的工程时序同步直接等同为 CTML 原则操作化。
- 修复是失败模块的反馈条件再生成，不是被证明能减少某类原则违规的局部 edit；也没有单列修复成功率和新错误率。

### 2.2.3 评价证据

离线集含 493 道小学语文题和 510 道初中数学题，每题一条视频；三位至少一年教学经验的认证领域专家按 0–3 整体 rubric 评分，85% 视频三人评分完全一致。LASEV 的 Publishable Rate 为语文 92%、数学 96%；消融比较 single agent、无 semantic/tool/rule critique。线上日志超过 2000 万条视频，成功生产 96.42%，其余按政策、脚本/解题、动画/LaTeX、基础设施失败分类（§5.1–5.4、Table 1–5）。

这些是强有力的**可发布性、正确性、可执行性和工业稳定性**证据，但不是原则遵循度、时序对齐误差、认知负荷、保持、迁移或学习增益证据。

### 2.2.4 与当前 timed storyboard 的差异，以及必须超过的层级

当前项目已经有 `segment.narration`、`elements[].id`、`animations[].target`、`trigger_at_sec`、`timeline[].at_sec/action/target` 和 `audio_duration_sec`；但触发时间主要依据旁白句子相对位置分配，尚无“旁白命题 ↔ 视觉语义对象/动作”的显式关系。可对照本地 [storyboard prompt](../../src/textbook2video/llm/prompts/storyboard.md) 和现有 timed storyboard 产物。

LASEV 比当前项目强在：把 `N` 与 `A` 作为一等对象，并宣称 narration segment → visual event window。当前项目强在：输入是教材、已有知识点和来源线索、最终可渲染为确定性 HTML 动画。

若以“语义—时序对齐”为创新，至少必须超过 LASEV 的论文披露层级：

1. 把 narration segment 细化为可复核命题 `P`，并记录 `P → E → action → interval`；
2. 给出 Temporal Contiguity 的类型化违规条件，而不仅是生成 `A`；
3. 在最终渲染视频或等价的运行时轨迹上复核实际出现时间；
4. 用人工标注验证 checker，而不是只让同一模型自评；
5. 报告按违规类型的局部修复成功率、复检结果和新错误率。

如果只增加一个 `trigger_at_sec` 字段或宣称“音画同步”，新颖性不足。

## 2.3 PIVOT：已有“生成—验证—代码修复”，但不是原则感知修复

**来源。** Xinchen Ma et al., *From Content Generation to Learning Support: Pedagogy-Guided Generative Video Tutors for STEM Learning*, arXiv 2026。当前原文页未标示正式发表 venue，故本文不把它写成已录用会议论文。全文见 [arXiv](https://arxiv.org/html/2609.24083)。判断依据 §3–4、Appendix A/B。

### 2.3.1 输入、输出与 storyboard

**论文事实。** 输入是学习者指定的 STEM topic；输出包括教学 Manim 视频、形成性选择题，以及针对模拟错误答案的 remediation video。生成无需教师逐步介入，但作者强调真实部署仍需教师监督。

高层 storyboard 包含：

- learning objectives；
- prerequisite activation；
- stepwise concept explanations；
- visual representation plans（diagram、formula、highlight、animation）；
- worked examples；
- diagnostic assessment probes。

shot-level storyboard 包含：local learning goal、narration、visual description/specification、visual elements、expected duration。它比 PedaCo-Gen 的 scene 脚本结构更丰富，但未包含教材 source span，也未报告视觉动作的精确时间戳。

| 目标字段 | 是否存在 | 精读结论 |
|---|---:|---|
| learning objective | 是 | 高层与 shot 局部目标 |
| knowledge point | 部分 | 概念解释/主题，但无教材知识点 ID |
| narration | 是 | shot-level |
| visual object/event | 是 | formula、diagram、highlight、animation 等 visual elements |
| timestamp / interval | 部分 | expected duration；未报告对象动作时间戳 |
| source evidence | 否 | topic-to-video，不是 textbook-grounded |
| pedagogical constraint | 是（一般教学） | storyboard 字段和 layout prompt；Mayer 只明确支撑 visual plans |
| violation | 未披露 schema | 三类 verifier 能报 failure，但原文未给机器字段 |
| repair action | 代码级 | 低温 prompt 依据 execution trace/rendering feedback 修 Manim code |

### 2.3.2 教学理论进入了哪一层

PIVOT 对教学的操作化主要来自**教学流程字段**：目标、先备知识、支架式解释、例题、诊断题。这达到一般教学意图的 D 层。Mayer (2005) 被明确用于 visual representation plans，属于 A/C；原文没有把 Coherence、Signaling、Temporal Contiguity 等分别编码为字段或违规规则。

因此，“PIVOT 是 pedagogy-guided”是论文事实；“PIVOT 已把 Mayer 原则做成机器可执行 checker”则不成立。

### 2.3.3 verification harness 的输入、输出与修复对象

**论文事实。** Harness 有三项：

| 维度 | 检查内容 | 主要对象 |
|---|---|---|
| Layout Consistency | overlap、spacing、readability、过高信息密度 | 渲染布局/帧 |
| Factual Consistency | 公式、符号变换、算法步骤、教学解释 | storyboard、旁白、代码/渲染内容 |
| Cognitive Clarity | 逻辑一致、教学进程、解释连贯 | storyboard/旁白 |

检测失败后，系统以 execution traces 和 rendering feedback 条件化低温 prompting，优先 GPT-5.2 修 Manim code，持续失败转 Claude Sonnet 4.6 调试。原文称 iterative repair，说明会再次执行/渲染到能获得新反馈，但没有公开固定 violation schema、路由表、停止条件、单次/累计成功率或修复引入新错误率。

**关键时序边界。** TTS 与同步旁白是在 “After verification” 才生成（§3.3）。据公开流程，harness 不可能在该轮验证中观察最终合成音频的真实时长和最终音画关系；论文也没有单列最终视频的 narration–visual alignment/timing checker。这正是与拟议工作可区分之处。

### 2.3.4 评价证据不能被写成“证明学习有效”

- 技术/模型评价：40 个 STEM 知识点；Gemini-2.5-Flash 对中间时间线采样帧评 Layout 和 Richness；GPT-4o 对 narration 评 Accuracy & Depth、Logical Flow。
- 消融：去除 layout verifier 后 Layout 9.10→7.87；去除 factual verifier 后 Accuracy 0.87→0.85；去除 cognitive verifier 后 Logical 0.91→0.89（Table 2–4）。
- 专家评价：32 位 STEM 教师/高校教师对 clarity、engagement、pace、logical flow、error explanation、learning efficiency、teaching effectiveness 作 Likert 判断；96.9% 认为“视频→测验→定向补救”流程比单独视频更有效。
- 不是学习实验：参与者是专家，不是完成前后测的学习者；错误答案是“plausible incorrect answer”模拟出来的。论文所称 perceived learning effects 应翻译为**专家感知的潜在学习效果**，不能写成真实 learning gain、retention 或 transfer。

### 2.3.5 本项目若做 checker + repair，必须如何区分

不能只复现 PIVOT 的“有 verifier、有 repair”。必须将贡献限定为：

- verifier 的维度由某条 Mayer 原则的理论定义推导，而不是泛化的 clarity；
- 输出是 `principle_id + violation_type + location + evidence + confidence`；
- repair 由 violation type 路由到有限局部操作，不是笼统重写/重生整段代码；
- TTS 与渲染后再次检查最终时间轴；
- 报告 repair success、new-error、source-fidelity preservation 和 technical regression。

## 2.4 PresentAgent：文档到有声演示视频的最直接任务近邻，但不是教学原则系统

**来源。** Jingwei Shi et al., *PresentAgent: Multimodal Agent for Presentation Video Generation*, EMNLP 2025 System Demonstrations，见 [ACL Anthology](https://aclanthology.org/2025.emnlp-demos.58/) 与 [arXiv 全文](https://arxiv.org/html/2507.04036)。判断依据 §3–7。

### 2.4.1 输入、输出与 IR

**论文事实。** 输入可为 PDF、Markdown、DOCX 或网页快照等长文档，典型长度 3,000–8,000 词；输出约 1–2 分钟、5–10 张静态 slide 的 narrated MP4。文档先变为 topic–subtopic tree/semantic blocks；每块匹配 slide type 和 HTML layout schema，LLM 生成 `replace_text`、`insert_image`、`add_list` 等编辑操作；每页生成口语旁白和 TTS，页面显示时长等于对应音频时长。

| 目标字段 | 是否存在 | 精读结论 |
|---|---:|---|
| learning objective | 否 | 面向通用 presentation，不限教育 |
| knowledge point | 部分 | topic–subtopic tree/semantic block，不是教学知识点 |
| narration | 是 | slide-specific oral script |
| visual object/event | 部分 | slide element、图片、列表、Alt-Text；最终是静态帧 |
| timestamp / interval | slide 级 | 音频与整张 slide 配对并 timestamp；无对象级动作 |
| source evidence | 弱 | 来源文档被分块，但未报告 slide 元素到原文 span 的证据链 |
| pedagogical constraint | 否 | 无 Mayer/CTML |
| violation / repair action | 未报告固定 schema | 有 VLM self-critique 回馈生成的表述，但没有类型化修复协议 |

它没有教师参与，也不生成动态对象动画。论文在 §7 明确把“当前仅静态 slides、没有 dynamic animations/effects”列为限制。

### 2.4.2 checker、音画同步与评价边界

**论文事实。** 实现部分称 Qwen-VL-2.5-3B-Instruct 会评分 slide layout、chart readability 和 cross-modal consistency，并把 self-critique 回馈生成；但没有披露该反馈的结构、迭代次数、局部修改方式、修复成功率或新错误率。

音画同步是**页面级 duration matching**：静态页面持续显示到该页音频结束。它保证 slide 与 slide narration 同段，不保证旁白内部提到某个概念时对应元素刚好出现，因为页面内没有事件时间线。

PresentEval 包含：

- fixed multiple-choice quiz，由 Qwen-VL-2.5-3B 回答；
- VLM 对 content、visual/audio quality、comprehension clarity 打分；
- 输入主要是整套 slide images + 完整 transcript，或短视频/音频片段。

Doc2Present benchmark 有 30 对人工作品；受商业 API 成本限制，论文详细比较只覆盖 5 篇 academic papers（Table 3、§7）。这些都是模型评审，没有教师/学习者实验。尤其是 VLM quiz accuracy 不是人的 comprehension，更不是 retention/transfer。论文 §6 反而明确承认当前各模态分别评价，未来需要 fusion-aware 的语义与时间一致性评价。

### 2.4.3 对本项目的启示与不能声称的 gap

**已被覆盖：** 长文档 → 结构化内容块 → slide/旁白 → TTS → 按音频时长组装视频；因此“document/textbook to narrated presentation video”不能单独作为创新。

**仍未覆盖：** 教材证据到教学目标/知识点/视觉对象的可追溯关系、页面内部动态事件、原则级时序检查、最终成片的跨模态语义—时间联合评价、类型化修复。

## 2.5 一篇必要的边界文献：AlShaikh et al. (2024)

为判断“CTML + AI + 教学视频”是否已有更早直接先例，本轮补充一篇，而不扩展为新综述：Rana AlShaikh, Norah Al-Malki, Maida Almasre, *The implementation of the cognitive theory of multimedia learning in the design and evaluation of an AI educational video assistant utilizing large language models*, Heliyon 2024（[原文/DOI](https://doi.org/10.1016/j.heliyon.2024.e25361)，开放全文见 [PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC10862517/)）。

该系统对**已有视频**做 Whisper 转写、重点概念高亮、Bard 问答/补充信息和概念图，并把多条 CTML 原则映射到界面模块。它不是教学视频生成器，也没有原则违规检测和自动修复。它进一步说明：**“AI 视频工具采用 CTML”早已有直接先例；真正未饱和的是原则约束的生成与验证机制。**

# 4. 七条原则重新筛选：从理论名称到研究变量

## 4.1 比较矩阵

| 原则 | 对自动教材视频的直接相关性 | 典型生成失败 | IR 可观测性 | 最终视频可验证性 | 自动 checker 可行性 | 定向 repair | 近邻工作覆盖 | 建议角色 |
|---|---|---|---|---|---|---|---|---|

## 4.2 三类结论

### 核心候选

- **Temporal Contiguity**：最贴合视频的时间媒介特性，也最适合当前已有 TTS 时长、动画 target 与 trigger 的工程基础；但与 LASEV 的重叠风险最大，必须以“类型化检测 + 最终成片复检 + 定向修复效果”超过其编排层。
- **Signaling**：与元素 ID、强调样式和 animation target 天然匹配，可形成 cue–target–time 的明确变量，并可与 Temporal Contiguity 共用标注。
- **Coherence**：与教材来源和知识点最相关，可形成 textbook-grounded 的独特贡献；但“相关”和“必要”不完全相同，人工标注成本和判断歧义高于前两者。

### 辅助原则

- **Multimedia**：适合作为 coverage/appropriateness 质量门，不适合作为“检测是否有图片”的主创新。
- **Segmenting**：理论和视频设计证据较成熟，当前项目也已按 segment/page 组织；可以作为生成约束和消融变量。若不实现 learner-controlled pacing，就不应声称完整满足经典 Segmenting Principle。
- **Personalization**：最容易自动改写与检测，但容易退化为代词、语气和句式统计，研究深度偏低。适合作为受控风格变量。

### 当前不适合做核心

- **Image Principle**：当前系统没有讲者画面/数字人。把“图片质量”当 Image Principle 会重复 PedaCo 的构念漂移。只有项目明确引入 presenter presence 且比较其呈现条件时，这条原则才变成直接问题。

# 5. 核心原则的机器化问题定义

以下不是工程设计稿，而是用于判断研究问题是否可测的**概念级操作定义**。所有阈值都应由先导标注和专家一致性校准，不能直接拍定为固定秒数或相似度。

## 5.1 Coherence：来源支持不等于教学必要，二者必须分开

### 理论定义

学习者从排除与教学目标无关材料的多媒体讲解中学得更好。原则对象包括无关文字、图片、声音/音乐及不必要符号；“无关”必须相对于学习目标和解释任务判定（[Mayer, 2009, Coherence Principle](https://doi.org/10.1017/CBO9780511811678.007)）。

### 生成失败模式

- `UNSUPPORTED_CONTENT`：旁白/视觉命题无法由教材证据支持；
- `GOAL_IRRELEVANT`：教材中确有该内容，但与本段目标/知识点无关；
- `DECORATIVE_VISUAL`：视觉存在但不解释、不组织、不提示目标内容；
- `EXTRANEOUS_AUDIO/MOTION`：音效、背景音乐或动作争夺注意而无教学功能；
- `OVERELABORATION`：重复例子/旁白超过理解所需并挤占核心内容。

### 可观测变量

- 教材证据单元 `S_j` 及其页/段 ID；
- 学习目标/知识点 `K_k`；
- 生成单元 `U_i`（旁白命题、文字、图片、视觉对象、动画、声音）；
- `support(U_i,S_j)`、`relevance(U_i,K_k)`；
- 教学功能标签：explain / organize / signal / example / transition / decorative；
- 屏幕占比、持续时间、动作强度等注意资源代理。

### 机器判定条件（待校准）

`U_i` 先被判断是否有来源支持，再判断是否服务于目标。可定义候选违规：

\[
unsupported(U_i) := \max_j support(U_i,S_j) < \theta_s
\]

\[
irrelevant(U_i) := \max_k relevance(U_i,K_k) < \theta_r \land function(U_i) \notin AllowList
\]

其中 `AllowList` 只容纳必要转场、题目提示等经标注认可的功能。不能用“教材里出现过”替代“对当前教学目标有用”。

### 定向修复动作

- 删除纯装饰或无支持单元；
- 将无支持命题改回证据支持的最小表述；
- 用解释性视觉替换装饰图；
- 把有效但错段内容移动到对应知识点；
- 压缩重复例子/旁白，而不整体重生成页面。

### 评价

- checker：元素级/命题级 precision、recall、F1，按违规类型报告；专家一致性；
- repair：违规消除率、教材忠实度变化、新错误率、被修改元素比例；
- 视频质量：技术渲染通过率与内容覆盖率不能下降；
- 学习：若资源允许，用真实学习者做保持/迁移和认知负荷；否则只能报告专家原则符合度，不能声称学习增益。

## 5.2 Signaling：不是“多加高亮”，而是正确对象在正确时刻得到适量提示

### 理论定义

当材料包含帮助学习者识别组织结构和重要内容的线索时，学习通常更好。视觉 cue 可以是箭头、颜色、框、强调或阶段标题，但它必须指向学习任务中的关键关系；过量或错向提示可能失效。证据综述可见 [Schneider et al., 2018](https://doi.org/10.1016/j.edurev.2017.11.001) 与 [Richter, Scheiter & Eitel, 2016](https://doi.org/10.1016/j.edurev.2015.12.003)。

### 生成失败模式

- `MISSING_SIGNAL`：关键命题/步骤出现时没有可见提示；
- `WRONG_TARGET`：箭头/高亮指向无关或错误对象；
- `UNTIMELY_SIGNAL`：提示与对应讲解错时；
- `SIGNAL_OVERLOAD`：同时提示过多对象，失去区分性；
- `INCONSISTENT_SIGNAL`：相同颜色/样式跨 scene 表示不同含义。

### 可观测变量

- 关键命题 `P` 与重要度/教学步骤；
- 视觉目标对象 `E`；
- cue `C` 的类型、target、样式、出现区间；
- 同屏 cue 数量、视觉显著性、全局颜色/符号语义；
- `match(P,E)` 和 `points_to(C,E)`。

### 机器判定条件（待校准）

- 对需要提示的 `P`，不存在满足 `points_to(C,E)` 且与 `P` 时间相交的 cue，判 `MISSING_SIGNAL`；
- cue 指向对象与 `P` 语义不匹配，判 `WRONG_TARGET`；
- 同屏 cue 数或显著性超过由专家标注校准的范围，判 `SIGNAL_OVERLOAD`；
- cue 的视觉语义违反课程级 style map，判 `INCONSISTENT_SIGNAL`。

“需要提示”的命题本身也要标注，不能规定每个视觉都必须高亮。

### 定向修复动作

- 对目标对象增加 cue；
- 改 cue 的 `target`、样式或层级；
- 移动 cue 的触发/消失时间；
- 删除竞争性 cue；
- 统一跨 scene 的颜色/符号含义。

### 评价

- cue–target 关联准确率、违规类型 F1；
- 正确目标率、时间重叠率、过载率；
- repair success、新错误率、布局回归率；
- 专家 Signaling 符合度；真实学习者的保持/迁移/眼动或认知负荷是更强但成本较高的验证。

## 5.3 Temporal Contiguity：命题—视觉对象/事件的语义与时间联合约束

### 理论定义

对应的词语与图像同时呈现，通常优于先后分离呈现，因为学习者不必在工作记忆中长时间保留一方等待另一方。该效应受材料复杂度和分隔长度调节，短小交替片段可能与同时呈现差别很小，因此容差必须实证校准（[Ginns, 2006](https://doi.org/10.1016/j.learninstruc.2006.10.001)；[Mayer, 2005, Temporal Contiguity](https://doi.org/10.1017/CBO9780511816819.013)）。

### 基本对象

令旁白中的一个可验证命题为：

\[
P=(text, [t_1,t_2], kp, source)
\]

令与之对应的视觉对象或视觉事件为：

\[
E=(element\_id, action, [v_1,v_2], semantics)
\]

需要同时区分：

- **event interval**：对象被画出、强调、移动或更新的动作时段；
- **visibility interval**：对象实际保持可见的时段。

只比较 `trigger_at_sec` 会忽略“对象提前出现但一直保持可见”和“动画开始正确但很快消失”的差异。

### 五类结果

1. `CORRECT`：存在语义匹配的 `E`，其有效事件/可见区间与 `P` 在校准容差内重叠；
2. `PREMATURE`：相关视觉的关键事件过早完成，且讲解开始时已失去必要注意线索；
3. `DELAYED`：讲解已开始或结束后，相关视觉才出现/更新；
4. `MISSING_VISUAL`：该命题按教学任务需要视觉解释，但不存在对应 `E`；
5. `SEMANTIC_MISMATCH`：有同时出现的视觉，但它解释的是其他命题，或图中关系与旁白相反。

可计算的候选量包括：

\[
overlap(P,E)=\frac{|[t_1,t_2]\cap[v_1,v_2]|}{|[t_1,t_2]|}
\]

以及事件 onset lag `v_1-t_1`、offset gap、`semantic_match(P,E)`。判定不能只看 overlap：一个错误视觉可能完美同屏，所以必须先满足语义匹配阈值 `\theta_m`。

### 机器判定条件（示意，不预设固定阈值）

- `SEMANTIC_MISMATCH`：存在候选视觉但 `semantic_match(P,E) < θ_m`；
- `MISSING_VISUAL`：`requires_visual(P)=true` 且不存在语义合格的 `E`；
- `DELAYED`：语义合格，但 `v_1-t_1 > δ_late(type(P),type(E))`；
- `PREMATURE`：关键事件结束早于讲解且讲解窗口内缺少持续可见/提示，超过 `δ_early`；
- `CORRECT`：语义合格，且 overlap/onset/visibility 满足经专家标注校准的组合条件。

`δ_early`、`δ_late`、`θ_m` 必须按视觉类型、命题复杂度、语速和动画动作通过开发集/专家标注校准，并在独立测试集上固定；不能先验规定“差 1 秒即违规”。

### 定向修复动作

- 仅移动 `trigger_at_sec` 或 action window；
- 延长对象可见区间/增加同步高亮；
- 把一个复合命题或 scene 拆开；
- 对 `SEMANTIC_MISMATCH` 替换视觉内容或重新绑定对象；
- 对 `MISSING_VISUAL` 增加解释性视觉；
- 必要时调整旁白断句，而不重写事实内容。

### 评价

- 人工金标准上的五分类 macro-F1、每类 precision/recall；
- onset error、overlap、semantic match 与专家判断的相关；
- 修复后违规消除率、时间误差下降、教材忠实度保持、技术渲染成功率、新错误率；
- 消融：只做时间规则、只做语义匹配、二者联合、只检查 IR、检查最终成片；
- 学习效果：至少把原则合规与 retention/transfer/cognitive load 分开报告；若不能做学习者实验，就明确止于“对齐质量”，不把对齐提升写成学习提升。

# 6. 三种论文定位的重叠、风险与成本

## 6.1 方案 A：Mayer/CTML-guided educational video generation

| 维度 | 判断 |
|---|---|
| 与现有工作重叠 | **很高**：PedaCo-Gen 已直接以 CTML-guided authoring 为核心；PIVOT 已占据 pedagogy-guided generation |
| 可能贡献 | 在教材输入、HTML 动画或中文场景中复现原则指导生成 |
| 新颖性风险 | **高**；若只是 prompt 加原则和专家评分，难以区别 PedaCo |
| 实现成本 | 中；现有 pipeline 容易加 prompt/rubric |
| 实验成本 | 中高；需要多原则专家评价，构念容易漂移 |
| 项目适配 | 高，但“能做”不等于“值得写” |
| 与导师逻辑吻合 | 表面吻合，但“原则如何转成问题定义”这一关键步不够深 |

**结论：不建议作为主定位。** 可在引言中作为上位背景，不应作为贡献句。

## 6.2 方案 B：From pedagogical principles to machine-executable constraints

| 维度 | 判断 |
|---|---|
| 与现有工作重叠 | PedaCo 有自然语言 constraints；LASEV 有 executable IR；但二者未给原则专属可判定条件 |
| 可能贡献 | 原则对象化、违规 taxonomy、人工金标准和 checker validity |
| 新颖性风险 | 中；若选太多原则会变成主观 rubric 工程 |
| 实现成本 | 中；重点在 schema、标注和检测，不必重做生成器 |
| 实验成本 | 中；需要双人/多人标注、一致性和 checker 对比 |
| 项目适配 | **很高**：已有知识点、元素 ID、动画动作和时间轴 |
| 与导师逻辑吻合 | **最强**：直接回答“原则如何转化为自动生成问题定义” |

**结论：适合作为核心科学贡献。** 最好只选 1–2 条原则做完整链条。

## 6.3 方案 C：Principle-aware generation, detection and repair for textbook instructional videos

| 维度 | 判断 |
|---|---|
| 与现有工作重叠 | PIVOT 有通用 verification/repair；LASEV 有通用 quality gates；PedaCo 有 CTML review |
| 可能贡献 | textbook evidence + principle-specific typed checker + local repair + rendered verification |
| 新颖性风险 | 中；必须证明 checker/repair 是原则专属而非换名的 LLM critique |
| 实现成本 | 中高；涉及运行时/成片复检和局部 edit |
| 实验成本 | 中高；需报告检测、修复、副作用，并最好补小规模学习者实验 |
| 项目适配 | **最高**：现有 pipeline 和中间产物允许局部重跑 |
| 与导师逻辑吻合 | **完整**：原则 → 问题 → 解决 → 评价 |

**结论：建议作为论文外包装。** 其中 B 是方法学贡献，C 是完整系统问题。最稳妥写法不是“三原则全自动修复”，而是“围绕一条主原则 + 一条耦合原则完成闭环”。

# 7. 收缩后的两个候选研究框架

## 候选 1（优先）：教材教学视频的命题—视觉语义时序对齐检测与修复

### Research Motivation

现有系统能按旁白时长排列页面，LASEV 也能生成 narration segment → visual event window，但尚无工作证明：最终渲染视频中，每个需要视觉支持的旁白命题，都由**语义正确的对象在合适时间出现/强调**；更没有报告针对 premature、delayed、missing、semantic mismatch 的修复效果。Temporal Contiguity 与 Signaling 提供理论依据，但研究对象是可测的跨模态事件关系，而不是笼统“遵循 Mayer”。

### Research Question / Problem Formulation

> 对教材 grounded 的教学视频，显式建模 `narration proposition P → visual element E → action → rendered interval`，能否比 scene-level duration matching 或通用 LLM critique 更准确地检测语义—时序违规，并通过类型化局部修复提高最终成片对齐，同时不损害教材忠实度与技术质量？

形式上，以第五节的五类结果为主要任务；Temporal Contiguity 是主原则，Signaling 用于“关键对象何时被引导注意”的耦合条件。

### 本项目为什么有条件完成

- 教材解析和 lesson plan 已给 objectives、knowledge point IDs、`source_refs`；
- storyboard 已有 narration、element IDs、animation targets；
- timed storyboard 已有 trigger、timeline 和真实 TTS duration；
- HTML 确定性渲染使对象实际出现时间可观察；
- pipeline 支持从 storyboard/HTML 局部重跑，适合修复实验。

这些事实可由本地 [lesson-plan prompt](../../src/textbook2video/llm/prompts/lesson_plan.md)、[storyboard prompt](../../src/textbook2video/llm/prompts/storyboard.md) 和 [quality module](../../src/textbook2video/pipeline/quality.py) 核对。

### Method（概念流程，不是代码方案）

1. **Generation**：保留现有教材→lesson plan→storyboard→TTS→render 流程；为研究样本记录命题、元素和动作关系。
2. **Checking**：从 IR 与最终渲染轨迹抽取 `P/E` 区间，联合语义匹配和时间规则输出类型化违规、位置、证据和置信度。
3. **Repair**：按违规类型选择最小编辑：移动 trigger、延长可见、重绑/替换视觉、补视觉、拆分命题；不默认整页重生成。
4. **Verification**：重新渲染并用相同 checker + 技术检查复检，同时计算教材忠实度和新错误。

### Evaluation

| 层面 | 必要指标 |
|---|---|
| Principle Compliance | 五分类 macro-F1；per-class P/R/F1；专家一致性；onset/overlap error |
| Textbook Fidelity | 命题—证据支持率；知识点覆盖；专家事实错误率；修复前后差值 |
| Technical Video Quality | 渲染成功、溢出/重叠、音频完整、时长、修复引入的技术回归 |
| Learning Effect | 最佳：学习者 retention、transfer、cognitive load；资源不足时只做专家 perceived alignment，并明确不是学习效果 |

还必须报告 `repair success rate`、`new-error rate`、平均修改范围和重渲染成本。

### Ablation

- scene-level audio duration matching（当前基线） vs proposition-level mapping；
- 只用时间规则 vs 只用语义模型 vs 联合；
- 通用自然语言 critique vs 类型化 checker；
- 整页/整段再生成 vs 类型化局部 repair；
- 只检查 IR vs 加入最终渲染复检；
- Temporal only vs Temporal + Signaling。

### Closest Work 差异

- **PedaCo-Gen**：其 Contiguity 是 prompt/rubric，scene 脚本无时间字段，也不检查最终视频；本候选做对象/命题区间、类型化检测和自动复检。
- **LASEV**：其 `A` 生成 narration segment→event window，但未报告 Temporal Contiguity checker、违规 taxonomy 或成片检测准确率；本候选的贡献必须落在这些实证层。
- **PIVOT**：其 verifier 修布局/事实/清晰度，TTS 在验证后；本候选检查真实音频参与后的最终时序，并做原则专属 repair。

### Research Risk

最大风险是与 LASEV 的“temporal mapping”在标题层面看似相同。规避方式不是换名，而是提供 LASEV 没有报告的四项证据：人工金标准、类型化检测、最终成片复检、修复成功/副作用。第二风险是时间阈值主观；必须用标注校准和敏感性分析，而不能拍脑袋定秒数。

### 小论文适配判断

**高。** 问题边界窄、数据单位清楚、能做自动指标和消融，主要改造集中在 IR 关系与质量闭环。学习者实验可作为增强项，不应阻塞核心检测/修复论文。

## 候选 2：教材证据约束下的 Coherence 违规检测与局部修复

### Research Motivation

PedaCo-Gen 会让 LLM 检查内容与 learning content 是否相关，PresentAgent 从长文档生成展示，PIVOT 检查事实一致性；但没有一项工作公开记录“生成元素由哪段教材支持、服务哪个学习目标、为什么应保留”，也没有把 unsupported、goal-irrelevant、decorative 分开。教材场景允许把 Coherence 从审美上的“简洁”变成证据与目标共同约束的可验证问题。

### Research Question / Problem Formulation

> 将每个旁白命题和视觉元素关联到教材证据与知识点目标，能否比无证据的 LLM reviewer 更可靠地区分“来源不支持”“虽有来源但与当前目标无关”和“有教学功能的必要支架”，并通过局部删除/替换/迁移提高 Coherence，而不降低内容覆盖和学习支持？

### 本项目为什么有条件完成

现有 lesson plan 已有 knowledge point、objective、source_refs、required images；storyboard 记录 knowledge point IDs、narration 和结构化 elements；这使“来源—目标—成片元素”关系可以在现有产物上研究，而无需更换视频生成范式。

### Method（概念流程，不是代码方案）

1. **Generation**：产生带目标与来源关联的 storyboard/成片；
2. **Checking**：分别检测 source support、goal relevance 和 visual pedagogical function，输出五节所列 typed violations；
3. **Repair**：最小化删除无关单元、改写无支持命题、替换装饰图或把内容移到正确知识点；
4. **Verification**：重新生成受影响页面/片段，复查 Coherence、教材忠实度、知识覆盖、布局和音频。

### Evaluation

| 层面 | 必要指标 |
|---|---|
| Principle Compliance | 三类核心违规的 P/R/F1；教师 Coherence 判断；标注一致性 |
| Textbook Fidelity | source entailment/support、事实错误、知识点覆盖、引用定位准确率 |
| Technical Video Quality | 渲染与音频通过率、删除/替换后的布局回归 |
| Learning Effect | 保持/迁移/认知负荷；若无学习者实验，只能报告原则与专家质量 |

repair 评价必须同时看违规消除、coverage loss 和 new hallucination，防止“删得越多分越高”。

### Ablation

- 只看教材来源 vs 只看学习目标 vs 两者联合；
- 通用 LLM reviewer vs typed evidence-aware checker；
- 删除策略 vs 替换/迁移策略；
- storyboard-only 检查 vs storyboard + final-frame 检查；
- 无 repair verification vs repair 后复检。

### Closest Work 差异

- **PedaCo-Gen**：有 learning content relevance prompt，但无 source span、目标字段、违规类型和自动复检；
- **LASEV**：semantic critique 强调解题正确与课程 rubric，输入不是教材，也不区分来源支持与目标必要性；
- **PIVOT**：factual consistency/cognitive clarity 较宽，没有教材证据链或 Coherence 专属 repair。

### Research Risk

最大风险是 Coherence 的“必要性”标注主观，且一个生动例子可能没有逐字来源却有教学价值。必须允许 `pedagogical_support` 类别，并报告专家一致性；若把所有非教材内容都判违规，会把 source fidelity 错当 Coherence。第二风险是范围膨胀：本候选不应同时承诺所有视觉质量和所有 Mayer 原则。

### 小论文适配判断

**中高。** 与 textbook-grounded 项目身份最匹配，改造成本中等；但标注协议和专家仲裁比候选 1 更难，学习效果也更容易受内容删减量混淆。

# 8. 两个候选的最终取舍建议

| 判断项 | 候选 1：语义时序对齐 | 候选 2：教材 Coherence |
|---|---:|---:|
| 研究问题清晰度 | 很高 | 高 |
| 自动指标可定义性 | 很高 | 中高 |
| 与现有项目 IR 匹配 | 很高 | 很高 |
| 最近邻竞争压力 | 高（LASEV） | 中高（PedaCo/PIVOT） |
| 人工标注歧义 | 中 | 高 |
| 局部修复可控性 | 很高 | 中高 |
| 小论文实验闭环 | **最强** | 强 |
| 理论忠实度风险 | 时间阈值需校准 | “来源外”不能自动等于“无关” |

**优先顺序：候选 1 > 候选 2。** 候选 1 更容易形成一个可复现的任务定义和完整检测—修复实验；候选 2 更凸显“教材”特色，可作为备选，或只作为候选 1 的 fidelity guard，而不同时扩成第二条主线。

不建议把二者直接合并成“三原则全覆盖系统”。对一篇小论文，最可信的贡献是把一条主原则完整做深，而不是把七条原则都写进 prompt。

# 9. 是否可以停止调研

**可以停止大范围文献调研。**

现有证据已经足以进入方法定义：理论定义和边界已有 Mayer 原始文献/元分析支持；PedaCo-Gen、LASEV、PIVOT、PresentAgent 分别界定了 CTML prompt/review、结构化时序编排、通用验证修复、文档到成片及 VLM 评价的最近邻边界；项目本身也已有目标、知识点、视觉元素和时间触发的研究接口。

后续只在以下四种触发条件下做**定点补查**，不再继续铺开关键词：

1. 导师或审稿人提出一个具体先例/反例，需要核对；
2. 为某项评价量表、学习测验或统计方法寻找原始依据；
3. 出现新的、与“原则类型化检查 + 修复 + 成片复检”直接同构的竞争工作；
4. 标注试验暴露某个操作定义存在争议，需要回到该原则的原始实验或边界研究。

下一阶段应优先完成研究定义而非继续搜集论文：选择候选 1 或 2，冻结原则范围，写出标注手册、违规 taxonomy、基线与最小评价矩阵。
